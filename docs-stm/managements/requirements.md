## 1. 运行环境与源代码要求

- R-ENV1. 基础源代码基于 Python 编写
- R-ENV2. Windows 11 使用 PowerShell 脚本启动，支持直接调用 Python 源代码或启动 TUI 界面
- R-ENV3. Linux 使用 Bash 脚本启动，支持直接调用 Python 源代码或启动 TUI 界面

## 2. TUI 界面

- R-TUI1. 启动后显示标题"投资分析报告生成系统"
- R-TUI2. 显示以下 11 个选项供用户选择：

| 选项 | 功能 | 说明 |
|---|---|---|
| E | 生成 EXCEL 分析报告 | 读取持仓信息生成 Excel 报告（必选模块 1-5） |
| N | 生成包含新闻的 EXCEL 分析报告 | 生成 Excel 报告 + 财经新闻关联增补页签（模块 6） |
| H | 生成 基础的 HTML 分析报告 | 读取持仓信息生成 HTML 报告，不含 LLM 增补内容（模块 1-6） |
| B | 生成全系列包含新闻的报告 (Excel + HTML) | 同时生成 HTML + 含新闻的 Excel 报告，不含 LLM 增补内容（模块 1-6） |
| L | 生成包含所有内容的全系列报告 | 同时生成 HTML + Excel，含新闻、模块 7-8 LLM 增补内容（模块 1-8） |
| C | 配置持仓信息目录 | 配置持仓文件的存放目录 |
| F | 配置持仓信息文件名 | 配置持仓文件的文件名 |
| R | 配置报告输出目录 | 配置报告文件的输出目录（默认 reports） |
| 1 | 更新基础缓存信息 | 主动更新基金业绩/持仓/基准缓存 |
| 2 | 更新持仓相关缓存信息 | 主动更新价格/指数/穿透/持仓缓存 |
| X | 退出 | 退出程序 |

- R-TUI3. E/N/H/B/L 操作流程：
  - 持仓目录下有多个 xlsx 文件时，弹出选择器要求用户选择其中一个
  - 持仓目录不存在或目录下没有 xlsx 文件时，弹出选择器要求配置持仓目录

## 3. 持仓文件格式

持仓 xlsx 文件格式固定：

- 每个页签 = 一个账户，页签名即账户名（如"证券账户""支付宝-余利宝账户"）
- 每个页签固定 4 列：名称（str）、代码（str）、持仓份额（float）、每份成本（float）
- 列名固定，不需要用户配置映射

## 6. 缓存策略

缓存统一存放在 `data/cache/` 目录，采用 JSON 格式，由 `src/cache.py` 提供泛用键值对存储接口。

### 6.1 缓存文件清单

缓存分为两层：**单条缓存**（`fetcher.py` 日常运行自动读写）和 **合并缓存**（菜单 [1]/[2] 手动刷新时生成的全量快照）。价格数据、基金业绩数据**不**写入合并文件，直接以 `price_{code}.json` / `fund_perf_{code}.json` 单条形式存储。

#### 合并缓存文件（菜单手动生成）

| 文件名 | 用途 | 更新频率 | 来源 |
|---|---|---|---|
| `fund_benchmarks.json` | 业绩比较基准对照表 | 每月 | 自动 + [1] 刷新 |
| `portfolio_latest.json` | 持仓主数据（含最新价格/净值） | 持仓更新时 | [2] 更新持仓缓存 |
| `penetration_cache.json` | 资产穿透 TOP10 计算结果 | 每日 | [2] 更新持仓缓存 |

#### 单条缓存文件（引擎自动管理）

这些文件由 `src/fetcher.py` 在首次取数时自动创建，按 `{类型}_{代码}.json` 命名，后续命中的无需再调 API。

| 文件名模式 | 用途 | TTL | 合并目标 |
|---|---|---|---|
| `price_{code}.json`（如 `price_600900.json`） | 单只股票/基金的最新价、昨收、净值日期 | 24h |（主存储，无合并目标） |
| `index_{code}.json`（如 `index_sh000001.json`） | A股/美股市场指数行情 | 24h | — |
| `fund_perf_{code}.json`（如 `fund_perf_000961.json`） | 单只基金的同类排名和区间收益率 | 24h |（主存储，无合并目标） |
| `fund_hold_{code}.json`（如 `fund_hold_012325.json`） | 单只基金的前 10 持仓明细 | 7天 |（主存储，无合并目标） |
| `news_*.json` | 财经新闻数据（按日期/关键词） | 24h | — |

### 6.2 缓存引擎说明

- **接口**：`cache.get(key, max_age_seconds)` / `cache.set(key, data)` / `cache.clear(key)` / `cache.clear_by_prefix(prefix)`
- **过期机制**：每个缓存项写入时记录时间戳，读取时校验 age > max_age 则失效
- **降级规则**：缓存过期但 API 请求失败时，返回缓存数据而非报错（当前未实现，将在后续迭代完善）
- **手动刷新**：通过 TUI 菜单 [1] 更新基础缓存、[2] 更新持仓相关缓存可清除并重新获取数据

### 6.3 TTL 常量

| 类别 | TTL | 生效范围（单条缓存文件） | 合并缓存文件 |
|---|---|---|---|
| `price` | 86400 秒（24 小时） | `price_{code}.json` |（无合并目标） |
| `index` | 86400 秒（24 小时） | `index_{code}.json` | — |
| `rank` | 86400 秒（24 小时） | `fund_perf_{code}.json` |（无合并目标） |
| `hold` | 604800 秒（7 天） | `fund_hold_{code}.json` |（无合并目标） |
| `news` | 86400 秒（24 小时） | `news_*.json` | — |
| `benchmark` | 2592000 秒（30 天） | — | `fund_benchmarks.json` |

## 7. 输出文件要求

### 7.1 文件命名

| 类型 | 最新文件 | 存档文件 |
|---|---|---|
| Excel | `个人投资分析报告.xlsx` | `个人投资分析报告-<YYYYMMDD>-<HHmmss>.xlsx` |
| HTML | `个人投资分析报告.html` | `个人投资分析报告-<YYYYMMDD>-<HHmmss>.html` |

最新文件存放到 `output_dir` 根目录（默认为 `reports/`，可通过菜单 R 或 `data/config/config.json` 中的 `output_dir` 字段配置），存档文件存放到 `{output_dir}/<YYYYMMDD>/` 子目录。

### 7.2 输出内容

#### 模块 1：汇总（Excel + HTML）

显示当前日期和时间、所属交易日、当日 A 股指数、美股指数、总市值、总成本、总盈亏、本日盈亏。

#### 模块 2：核算市值（Excel + HTML）

15 列明细表：

| # | 列名 | 说明 |
|---|---|---|
| 1 | 账户 | 证券/支付宝/微信/谱蓝 |
| 2 | 名称 | 资产全称 |
| 3 | 代码 | 6 位代码 |
| 4 | 最新价 | 当前价格/净值 |
| 5 | 净值日期 | 具体日期如 2026-06-23 |
| 6 | 昨日价 | 前一日收盘价/净值 |
| 7 | 取价方式 | 场内实时价/场内收市价/官方净值(T)/官方净值(T-1) |
| 8 | 溢价率 | 对 QDII 基金显示 |
| 9 | 份额 | 持仓数量 |
| 10 | 市值 | 价格 × 份额 |
| 11 | 成本 | 成本价 × 份额 |
| 12 | 盈亏 | 累计盈亏（市值 - 成本） |
| 13 | 收益率 | 累计收益率 |
| 14 | 本日盈亏 | 仅场内品种计算，场外非当日更新标 0 |
| 15 | 取价渠道 | 腾讯财经/天天基金网 |

分账户小计在该账户所属资产下立即显示，总计在最后。盈亏正数红色，负数绿色。

**本日盈亏计算逻辑：**
- 场内（交易时段）：(实时价 - 昨收盘) × 份额
- 场内（非交易时段）：(收盘价 - 昨收盘) × 份额
- 国内场外：净值日期 == 当天 → (当日净值 - 前日净值) × 份额；否则 0
- QDII：净值日期 == T-1 → (当日净值 - 前日净值) × 份额；否则 0

#### 模块 3：分类汇总（Excel + HTML）

按资产属性 + 按投资分类进行分组汇总。

#### 模块 4：资产穿透 TOP10（Excel + HTML）

所有基金拆分为前 10 大持仓成分股：
- 债券基金 → 具体债券品种
- QDII → 具体美股（季报数据）
- 主动权益基金 → 前 10 大持仓
- ETF → 前 10 大成分股/黄金现货
- 场外指数联接 → 前 10 大成分股

合并直接持有股票，相同资产合并市值，排序取 TOP10。

#### 模块 5：基金业绩分析（Excel + HTML）

11 列表格：基金 | 代码 | 类型 | 近3月 | 近6月 | 近12月 | 持仓累计盈亏(¥) | 持仓收益率 | 业绩基准 | 业绩评价 | 同类排名

- **类型**：使用穿透分类逻辑自动标注（场内ETF / 场外主动型基金 / 场外指数基金 / 场外QDII基金 / 场外债券基金）
- **累计盈亏(¥)**：持仓累计盈亏 = 市值 − 成本（来自估值明细）
- **收益率**：累计收益率 = 盈亏 / 成本（来自估值明细）

- **业绩评价**：格式为"标签 + 描述"。标签：优秀（持续跑赢基准）、良好（稳定跑赢基准）、稳定（波动控制良好）、偏差（近期表现欠佳）。标签文本禁止出现资产类别词（主动权益基金、QDII、指数型基金等）。
- **同类排名**：格式为"排名/总数"，如"23/156"。信息包含在 API 返回数据中，评级基于排名百分位自动计算。

#### 模块 6：财经新闻热点与持仓关联分析（Excel + HTML）

分析财经新闻热点，仅分析与持仓关联，输出 TOP N 新闻（N 通过 `data/config/config.json` 中的 `news_top_count` 配置，默认 100）。
- **Excel**：通过菜单 N/B/L 生成增补页签（财经新闻热点表）
- **HTML**：自动渲染在报告第 6 节

##### 模块 7：全球政经局势（Excel + HTML，分阶段实现 — LLM 增补项目）

在有 LLM 支持下的增补内容。
- **Phase 1（Iter 3.3）**：模板占位文本输出，预留接口
- **Phase 2（Iter 3.4）**：LLM 基于市场数据和持仓结构生成宏观分析
- **Excel**：通过菜单 L 生成增补页签（待实现）
- **HTML**：通过菜单 L 渲染在报告第 7 节（待实现）

#### 模块 8：智囊团深度复盘（Excel + HTML，分阶段实现 — LLM 增补项目）

在有 LLM 支持下的增补内容。
- **Phase 1（Iter 3.3）**：模板占位文本输出，预留接口
- **Phase 2（Iter 3.4）**：LLM 基于持仓明细和盈亏数据生成优化建议和风险预警
- **Excel**：通过菜单 L 生成增补页签（待实现）

## 8. LLM 智能分析策略（Iter 3.4）

### 8.1 API 配置

- 支持接入 Claude API / OpenAI API，API Key 通过环境变量或 `data/config/config.json` 配置
- API Key 不存在时优雅降级，模块 7/8 继续输出占位文本

### 8.2 Prompt 设计原则

- 模块 7（全球政经）：输入当前市场指数 + 持仓行业分布 + 近期新闻摘要，LLM 输出宏观局势分析
- 模块 8（智囊团复盘）：输入持仓明细 + 盈亏数据 + 分类汇总，LLM 输出优化建议和风险预警
- Prompt 中需明确要求 JSON 结构化输出，便于解析和渲染

### 8.3 费用控制

- LLM 调用结果缓存（默认每日刷新），避免重复扣费
- 限制输入上下文大小：仅传必要数据摘要，不传完整持仓明细
- 每次报告生成最多 2 次 LLM 调用（模块 7 + 模块 8）
