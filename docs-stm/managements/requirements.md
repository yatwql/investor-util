## 1. 系统概述

### 1.1 目标

本系统读取用户持仓 Excel 文件，自动从多个公开金融数据源获取市场行情、基金业绩、财经新闻等数据，生成结构化的投资分析报告（Excel + HTML 双格式），并通过 LLM 提供智能分析增强。

### 1.2 核心业务流程

```
用户持仓 xlsx
     │ 读取
     ▼
多源数据并行获取（行情 / 基金 / 行业 / 新闻 / 历史走势）
     │ 汇总
     ▼
报告生成（Excel + HTML 双管线）
     │
     ├── 基础报告（E 菜单）：汇总、市值、分类、穿透、基金业绩、历史走势/回撤分析
     ├── 完整报告（B 菜单）：基础 + 新闻 + 基金深度分析 + 历史走势
     └── LLM 增强报告（L 菜单）：完整报告 + 全球政经/智囊团/体检/穿透分析
```

## 4. 持仓输入格式

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-HLD-01 | 输入文件为 xlsx 格式，每个页签 = 一个账户，页签名即账户名 |
| R-HLD-02 | 每个页签固定 4 列：名称（str）、代码（str）、持仓份额（float）、每份成本（float） |
| R-HLD-03 | 列名固定，无需用户配置映射关系 |
| R-HLD-04 | 列顺序固定：名称 → 代码 → 持仓份额 → 每份成本 |
| R-HLD-05 | 代码自动去除 .SH / .SZ / .OF 等后缀，统一为纯净代码 |

## 5. 数据获取需求

### 5.1 数据源总览

系统需从以下公开数据源获取数据。每个用途需指定主链路与备用链路，主链路失败时自动切换备用。

| 用途 | 主链路 | 备用链路 |
|:-----|:-------|:---------|
| 场内 A 股/ETF 实时价 | 腾讯财经 | 新浪财经 |
| 场外基金净值 | 东方财富 | 天天基金 |
| 基金业绩排名 | 天天基金 | — |
| 基金持仓数据 | 天天基金 | — |
| A 股指数行情 | 腾讯财经 | 新浪财经 |
| 美股指数行情 | 新浪财经 | 腾讯财经 |
| 财经新闻（5 源并行） | 新浪/东方财富/财联社/华尔街见闻/akshare | — |
| 行业分类/概念板块 | 东方财富 push2 | quotedata 回退 |
| 机构盈利预测 | akshare | — |
| 行业资金流向 | akshare | — |
| 股票历史分红 | akshare | — |
| 基金经理数据 | 天天基金 | 档案页回退 |
| 个股/ETF 历史 K 线 | 腾讯财经 | 新浪财经 |
| 场外基金历史净值 | 天天基金 | 东方财富 |
| 指数历史 K 线（A 股指数） | 腾讯财经 | 新浪财经 |
| 指数历史 K 线（美股指数） | 新浪财经 | 腾讯财经 |

### 5.2 数据质量需求

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-DATA-01 | 所有外部数据源必须配置备用链路或降级方案，单源不可用时不得中断报告生成 |
| R-DATA-02 | 数据获取失败时必须静默降级而非抛出异常，失败的资产在汇总日志中列出 |
| R-DATA-03 | 同一会话内同一 API 数据应复用，避免重复请求导致 API 限频 |
| R-DATA-04 | 盘中 A 股行情需使用短 TTL（默认 30s）确保实时性，盘后回落常规 TTL |
| R-DATA-05 | 收盘后需验证缓存中 price_date 是否为当日数据，避免盘中降级残留数据滞留 |
| R-DATA-06 | 00 开头的代码同时可能是 A 股或场外基金，需通过名称关键词辅助判断，股票链路全失败时自动尝试基金净值链路 |

### 5.3 熔断需求

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-BRK-01 | 单股票级 API 连续 3 次传输级失败后应熔断 300 秒，冷却期满后自动试探恢复 |
| R-BRK-02 | 批量 API（如行业分类）连续 6 次传输级失败后应熔断 120 秒 |
| R-BRK-03 | API 正常返回空数据（非传输级异常）不计入熔断计数器 |
| R-BRK-04 | LLM API 端点应有独立的熔断器（连续 3 次失败熔断 60 秒） |
| R-BRK-05 | 同一次会话中跨模块的同一 API 调用结果应共享会话级内存缓存（上限 2000 条/domain） |

### 5.4 新闻获取需求

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-NWS-01 | 每个新闻源独立获取（合并前），各源原始获取量动态计算为 max(500, news_top_count × 2) |
| R-NWS-02 | 最终输出按关联度排序，截取 news_top_count 条（默认 300 条） |
| R-NWS-03 | 新闻关键词来源：持仓名称片段 + 代码 + 穿透资产名称 + 行业分类 + 概念板块 |
| R-NWS-04 | 关键匹配结果需在报告中以颜色区分来源类型（持仓名称=蓝色、穿透资产=紫色、概念=橙色、行业=灰色） |
| R-NWS-05 | 各新闻源可通过配置独立启停 |
| R-NWS-06 | 新闻模块可选的 LLM 二次关联分析 -> 提供关联度评级（高/中/低/无关）+ 情感分析（利好/利空/中性） |

### 5.5 历史走势数据获取需求

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-HST-01 | 场内股票/ETF 历史 K 线使用腾讯财经，备用新浪财经 |
| R-HST-02 | 场外基金历史净值使用天天基金，备用东方财富 |
| R-HST-03 | 数据获取支持增量合并：首次全量获取，后续仅拉取缺失日期（以已有缓存为底座） |
| R-HST-04 | 检测到历史数据修正（新数据与缓存日期重叠）时应自动全量刷新 |
| R-HST-05 | 数据获取模式由用户配置控制：off（关闭）/ prompt（询问后执行）/ auto（自动执行） |
| R-HST-06 | 00 代码的 K 线全空时自动降级为基金净值链路 |
| R-HST-07 | 基准指数历史数据通过 history_index（A 股）/ history_index_us（美股）chain 获取，支持增量缓存合并。美股指数（gb_ 前缀）路由至 history_index_us（新浪→腾讯），因腾讯 K-line API 不支持 gb_* 代码 |

### 5.6 指数数据获取需求

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-IDX-01 | A 股指数主链路腾讯财经，备用新浪财经 |
| R-IDX-02 | 美股指数主链路新浪财经（JS 变量解析），备用腾讯财经 |
| R-IDX-03 | 双链路均失败时降级过期缓存 |

| 8 | 预警级别 | 🔴 紧急 / ⚠️ 关注 / 📋 首检 / ✅ 正常 |

**预警规则**：
- 30 天内发生变更 → 🔴 紧急
- 90 天内发生变更 → ⚠️ 关注
- 180 天内发生变更 → ⚠️ 关注
- 首次运行无历史快照 → 📋 首检
- 以上均不满足 → ✅ 正常

#### 6.4.7 持仓重合度矩阵

**双指标**：Jaccard 系数 = |A∩B| / |A∪B|，重叠率 = |A∩B| / min(|A|,|B|)，最终取二者最大值。

**着色规则**：
| 重合度 | 着色 |
|:-------|:-----|
| ≥ 50% | 红色白字 |
| 30~50% | 橙色白字 |
| 15~30% | 黄色黑字 |
| > 0% | 绿色黑字 |
| 0% | 无着色 |

**触发条件**：持仓中基金数量 ≥ 2 只。

**风格判定标准**：

#### 6.4.11 组合历史走势

**输出指标**：

| 字段 | 说明 |

| `enable_news` | bool | true | ✅ P | 新闻板块启停 |
| `enable_history` | bool | true | ✅ P | 历史走势启停 |
| `market_hour_aware` | list | `["price","index"]` | — | 交易时段短 TTL 的数据类型 |
| `market_hour_ttl` | int | 30 | — | 交易时段缓存有效期（秒） |
| `market_hours` | dict | `{start:"09:30",end:"15:00"}` | — | 交易时段配置 |
| `degradation` | dict | T2/T3/T4 默认 | — | 数据降级阈值配置 |
| `history.analysis` | str | "off" | — | 历史走势获取模式（off/prompt/auto） |
| `history.snapshot_retention_days` | int | 60 | — | 快照保留天数 |
| `history.snapshot_max_count` | int | 365 | — | 快照最大数量 |
| `history.coverage_threshold` | float | 0.8 | — | 有效区间覆盖阈值 |
| `history.benchmark_indices` | dict | {"sh000300":"沪深300","gb_inx":"标普500"} | — | 基准指数配置，组合历史走势对比 |

| `llm_providers_file` | str | `data/config/llm_providers.json` | — | LLM Provider 多链配置文件路径 |
| `llm_settings_file` | str | `data/config/llm_settings.json` | — | LLM 参数文件路径 |

### 11.2 llm_key.json（敏感凭据文件，建议纳入 .gitignore）

多键凭据字典，支持按 `credentials_ref` 名称引用。

| 键 | 类型 | 必填 | 说明 |
|:---|:----:|:----:|:-----|
| `{ref_name}` | dict | ✅ | 凭据块，任意合法键名（如 `deepseek-main`） |
| `{ref_name}.api_key` | str | ✅ | API 密钥 |
| `{ref_name}.model` | str | ✅ | 模型名 |
| `{ref_name}.endpoint` | str | ✅ | API 端点 URL |
| `{ref_name}.provider` | str | — | Provider 类型（`claude` / `openai` / `gemini`），仅在覆盖 `llm_providers.json` 时使用 |

**简化格式**（无需 `credentials_ref` 的传统使用）：若文件顶层仅含 `{"api_key": "...", "model": "..."}` 等单键凭据字段，自动包裹为 `{"_default": {...}}` 兼容处理。

### 11.3 llm_settings.json（非敏感参数）

**全局配置**：

| 键 | 类型 | 默认值 | 说明 |
|:---|:----:|:------:|:-----|
| `max_retries` | int | 2 | 429/503 最大重试次数 |
| `llm_max_concurrency` | int | 3 | LLM 并发生成最大线程数 |
| `enabled_llm` | dict | 全局开启 | 各模块独立启停 |
| `pricing` | dict | — | 模型定价表覆盖 + 货币设置 |

**模块级配置**（`{key}` = global_macro / expert_review / health_check / penetration_deep / news_correlation）：

| 键 | 类型 | 说明 |
|:---|:----:|:-----|
| `system_prompt_{key}` | str/null | 自定义 System Prompt |
| `model_{key}` | str/null | 模块级模型覆盖 |
| `temperature_{key}` | float | 生成温度（0.1~0.8） |
| `max_tokens_{key}` | int | 最大输出 Token |
| `timeout_{key}` | int | API 超时秒数 |
| `cache_enabled_{key}` | bool | 是否缓存 LLM 结果 |
| `output_brief_{key}` | bool | 精简模式（≤200~300 字，news_correlation 不支持） |
| `thinking_enabled_{key}` | bool | Extended Thinking 开关 |
| `thinking_budget_{key}` | int | Claude Thinking 预算 |
| `reasoning_effort_{key}` | str | DeepSeek 推理深度 |

### 11.4 llm_providers.json（Provider 多链配置）

定义 LLM Provider 的切换策略和备选 Provider 列表，不包含敏感凭据（通过 credentials_ref 引用 llm_key.json）。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|:-----|:----:|:----:|:------:|:-----|
| `strategy` | str | — | `"priority"` | 切换策略：priority / weighted / cost_first / fallback_only。每条 Provider 可额外设置 `proxy_preferred: true`，有代理环境时自动前置 |
| `preferred_providers` | dict | — | `{}` | 模块级首选：`{"news": "provider_name"}`，指定模块强制路由到特定 Provider |
| `providers` | list[dict] | ✅ | — | Provider 条目数组（按优先级顺序，至少 1 条） |

**Provider 条目字段**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|:-----|:----:|:----:|:------:|:-----|
| `name` | str | ✅ | — | 唯一标识名称，用于引用和日志 |
| `provider` | str | ✅ | — | Provider 类型：`claude` / `openai` / `gemini` |
| `credentials_ref` | str | ✅* | — | 引用 `llm_key.json` 中的凭据块名（*与内联 api_key/model 二选一） |
| `api_key` | str | △ | — | 内联 API 密钥（仅当 credentials_ref 未指定时必填；与 credentials_ref 互斥） |
| `model` | str | △ | — | 内联模型名（同上） |
| `endpoint` | str | — | 各 Provider 默认值 | 端点 URL 覆盖 |
| `priority` | int | — | 99 | 优先级（数值越小优先级越高），priority 策略使用 |
| `weight` | int | — | 1 | 权重值，weighted 策略使用 |
| `timeout` | float | — | 60.0 | API 超时秒数 |
| `proxy_preferred` | bool | — | false | 是否优先使用 proxy（proxy_preferred 策略使用） |

**示例**：
```json
{
  "strategy": "priority",
  "preferred_providers": {"news": "deepseek-main"},
  "providers": [
    {"name": "deepseek-main", "provider": "claude", "credentials_ref": "deepseek-main", "priority": 10, "timeout": 120},
    {"name": "gemini-fallback", "provider": "gemini", "credentials_ref": "gemini-fb", "priority": 20, "timeout": 60}
  ]
}
```

## 12. 错误处理约束

| 需求标识 | 需求描述 |
|:---------|:---------|
| R-CON-01 | LLM key 未配置时整流程不阻塞，对应页签显示占位，不报错退出 |
| R-CON-02 | config.json 损坏时回退全默认值，不崩溃 |
| R-CON-03 | 持仓文件格式异常时跳过异常行继续解析，不中断 |
| R-CON-04 | 报告输出目录无写入权限时提示错误后退出，不静默失败 |
| R-CON-05 | 空持仓时暂停生成，直接返回 |
| R-CON-06 | 数据源 API 变更/不可用时，各模块独立降级，互不干扰 |
| R-CON-07 | 网络断开时无法使用备用链路的请求降级到过期缓存，无缓存则跳过 |
| R-CON-08 | 所有降级/失败信息必须在报告中可视化展示，不得静默吞没 |
