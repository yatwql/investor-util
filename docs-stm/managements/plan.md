# 个人投资分析报告生成小助手 — 实现计划

创建日期：2026-06-26
最后更新：2026-07-03（v0.2.66 — ✅ 已完成迭代从 plan.md 移除，全部指向 changelog.md）

---

## 问题描述

个人投资者需要基于持仓数据和市场行情，生成包含市值核算、资产穿透、基金分析等内容的投资分析报告。当前无现成工具，需从零构建 Python TUI 应用，对接中国金融数据源，输出 Excel 和 HTML 格式报告。

---

## 需求

完整需求详见 [`docs-stm/managements/requirements.md`](requirements.md)。

---

## 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| TUI 框架 | 原生 `input()` 循环 | 零依赖，开发最快，满足菜单需求 |
| Excel 库 | `openpyxl` | 原生支持 .xlsx 读写、颜色/字体格式设置 |
| HTTP 客户端 | `httpx` | 同步/异步、连接复用，比 requests 现代 |
| 数据解析 | 手动解析，不使用 pandas | 减少依赖，数据量小，自定义校验更可控 |
| 配置持久化 | `data/config/config.json` | JSON 简单可靠，无需额外依赖 |
| AI 全球政经局势 + 智囊团深度复盘 + 持仓体检报告 + 穿透深度分析 + 财经新闻热点与持仓关联分析 | LLM 生成 | 支持 Claude/OpenAI/DeepSeek API，缓存策略分层，System Prompt 外部可配置 |
| 报告模板 | 程序生成（Excel openpyxl / HTML Jinja2） | Excel 和 HTML 报告均程序化生成 |

---

## 当前配置架构

LLM 配置拆分为两个独立文件：

| 文件 | 内容 | 用途 |
|------|------|------|
| `data/config/llm_key.json` | 4 个必填 + 4 个可选回退字段 | API 调用渠道（provider / api_key / model / endpoint / fallback_*） |
| `data/config/llm_settings.json` | 所有非敏感配置 | 参数调优（temperature、timeout、cache、system_prompt、thinking 等） |

---

## 系统影响

- `data/holdings/`、`data/cache/`、`data/config/` 在首次运行时需保证存在
- `data/config/config.json` 在程序生命周期外持久保存，含 `output_dir` 字段控制报告输出位置
- 程序依赖外部中国金融 API，网络不可用时降级运行（使用缓存数据或显示"--"）
- 持仓目录多 xlsx 文件时，用户通过 TUI 选择

---

## 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 腾讯/东方财富 API 变更或封禁 | 行情获取失败 | 备用链路自动切换；缓存支撑当日使用 |
| 持仓 xlsx 格式与预期不一致 | 解析失败或数据错误 | 固定列名解析 + 字段校验 + 友好提示 |
| 基金穿透计算量大 | 报告生成变慢 | 穿透结果缓存每日更新 |
| LLM API Key 未配置 / 超时 | 全球政经局势 / 智囊团深度复盘不可用 | 降级输出占位文本，不阻塞报告生成 |
| LLM Token 费用超预期 | 成本增加 | 缓存 LLM 结果；限制输入上下文；分层缓存 TTL |

### [P0] B. 基金持仓专属分析（中难度 / 高价值）

- **基金经理变更监控**：检测主动基金近 3 月内基金经理是否变更（已有天天基金 API）
- **持仓重合度矩阵**：计算多只基金间的 TOP10 持仓重叠度，避免买同一堆股票
- **基金风格漂移检测**：对比基金当前持仓与招募说明书约定风格（大盘/中小盘、成长/价值）是否一致，识别风格飘移风险
- **持仓集中度监控**：跟踪前十大持仓占比变化趋势，集中度突变时提示风险


### [P1] W. 剩余场景与数据正确性验证增补（中难度 / 中价值）

来自 §1.8 ◐/❌（5 项）和 §2 🟡/❌（9 项），补全缺失的场景覆盖和数值正确性断言：

**场景补全：**
- **T13 交易时段切换缝隙**：11:29:59 / 14:59:59 附近时段切换前夕的缓存/数据行为
- **非交易日+LLM 混合场景**：非交易日生成含 LLM 的报告
- **多账户混合+LLM 多轮**：多账户 + LLM 多轮交互场景
- **净值数据空窗期**：基金净值未发布（15:00 前）时的降级行为
- **多时区 QDII 净值一致性**：不同交易时区 QDII 净值的日期标注正确性

**数据正确性验证：**
- **三维度分类聚合一致**：资产属性/投资分类/账户的三类分类各自小计 = 总计，交叉验证无遗漏
- **穿透行业占比归一化**：各行业占比之和 ≤ 100%
- **指数行情数值合理**：上证≈3000、沪深300≈4000、恒指≈20000、标普≈5000 的数量级断言
- **多币种转换正确**：美元份额 × 汇率中间价 = 人民币市值
- **QDII 估值净值 vs 官方净值关系**：估值净值 ≥ 0，官方净值延迟 T-2
- **基金业绩排名数据合理性**：排名/收益率在 0-100% 范围内
- **溢价率计算**：(市价 - 净值) / 净值的 QDII ETF 验证
- **本日盈亏场外非 T 日更新**：nav_date ≠ T → today_profit = 0
- **穿透市值占比归一化**：TOP10 占比总和 ≤ 100%

### [P2-2] Y. Edge Case 纵深覆盖增补（四期）（低难度 / 中价值）

当前 ~86 项 edge 测试覆盖了零值/空集/时区/缓存等维度（详见 testplan.md §1.6），以下从实际使用中可能遇到但尚未覆盖的维度纵深增补，按风险概率排序：

- **Y1 — API/网络异常纵深（~15 项）**：HTTP 部分响应/编码不匹配/SSL 错误/DNS 解析失败/重定向/429 Retry-After/连接重置/空 JSON 变体/body 错误码/代理环境
- **Y2 — 数据质量纵深（~15 项）**：停牌无交易/新基金空持仓/穿透数据重复/多层嵌套 FOF/ETF 超多持仓/负价格净值/极低流动性/债券违约/同基金多层份额/跨市场停牌时差
- **Y3 — 文件系统纵深（~12 项）**：加密 Excel/xlsm 宏/隐藏工作表/损坏 xlsx/UNC 网络路径/文件占用/权限变更/超长路径/缓存篡改/空字节文件
- **Y4 — 数值计算纵深（~10 项）**：浮点累加误差/极微份额/超高单价/收益率超 ±1000%/NaN 传播链/int32 溢出/负成本/多数量级相加
- **Y5 — 配置/环境纵深（~10 项）**：BOM 头 JSON/0 字节配置文件/CRLF vs LF/api_key 空格/代理冲突/缺失嵌套键/多实例并发/终端无颜色
- **Y6 — 安全纵深（~8 项）**：CSV 公式注入/XSS 缓存注入/符号链接/路径遍历/API Key 日志泄漏/JSON 原型污染/临时文件竞争

详细规格见 testplan.md §9.2~§9.7。

### [P2-3] Z. 业务场景覆盖增补（二期）（中难度 / 中价值）

当前 S1-S20 覆盖了基础业务链路和 LLM 组合场景，但缺少中国个人投资者实际持有的多个常见品种。按业务领域分组，作为 `scenario_basic`（S21-S30 品种扩展 + S0 前置场景）的候选扩展：

**Z1 — 特殊品种场景（~8 项，scenario_basic）**
- **S21: 港股通持仓**：持仓含港股通标的（腾讯 00700、美团 03690），验证港股通费用/汇率转换/节假日差异
- **S22: 可转债持仓**：含可转债（12xxxx）时分类正确、转股溢价率/纯债价值/到期收益率等特殊指标
- **S23: 公募 REITs**：含基础设施 REITs（18xxxx），现金分派率、特许经营权期限等独特字段
- **S24: 货币基金**：含货币基金/短期理财（万份收益/七日年化），净值恒为 1 的特殊处理
- **S25: 科创板 + 北交所混合**：688（20%涨跌停）+ 8xx（30%涨跌停）同时存在时的分类和涨跌计算
- **S26: 商品/黄金 ETF**：黄金 ETF、有色金属 ETF、豆粕 ETF 等商品类 ETF 的分类和估值
- **S27: 跨境 ETF（美股/港股方向）**：纳指 ETF、恒生科技 ETF 等多只跨境 ETF 的净值延迟和溢价率
- **S28: 纯债/国债持仓**：国债/企业债的利息计算、面值 vs 净价 vs 全价区分

**Z2 — 操作行为场景（~5 项，scenario_basic）**
- **S29: 分红送转除权**：持仓股票分红送股（10 送 10）后的份额跳变和成本摊薄计算
- **S30: 定投成本摊薄**：同一品种在多个不同日期以不同价格买入，验证加权平均成本计算
- **S31: 部分调仓卖出**：部分卖出持仓后剩余份额的成本（先进先出/加权平均）和盈亏
- **S32: 跨账户转仓**：同一只股票从 A 账户转到 B 账户后，分类汇总中合并计算而非重复
- **S33: 新股中签待上市**：持仓中含尚未上市的 IPO 中签新股，以发行价估值

**Z3 — 持仓质量场景（~4 项，scenario_basic）**
- **S0a: 含已清仓记录**：xlsx 中存在已清仓品种（份额=0），验证自动跳过不会计入报告
- **S0b: 同名基金多份额**：同一只基金的 A 类/C 类份额同时持有，穿透时合并计算
- **S0c: 超多持仓（200+ 条）**：极限持仓量的报告生成时间和内存使用不超限
- **S0d: 持仓名称含特殊字符**：名称含 `®`/`™`/`♥`/全角括号/繁体中文/英文混排，Excel 输出不乱码

**Z4 — 场景补充场景（~5 项，T17-T21 时间补充分组）**
- **T17: 跨月/跨年报告**：12 月 31 日生成和 1 月 2 日生成的跨年行情数据连续性
- **T18: 季末/年末效应**：基金季末调仓日前后净值跳变
- **T19: 汇率中间价故障**：美元/港币汇率数据暂不可用时的 QDII 降级
- **T20: 节假日调休**：调休工作日（周日上班）vs 调休放假（周六休息）的交易日判断
- **T21: 港股通假期差异**：A 股开市但港股通关闭（如佛诞日）时的取价降级

### [P4] F. LLM 分析增强（低难度 / 中价值）

- **环比分析**：对比历史报告摘要，说明组合变化趋势
- **报告对比**：将本次报告的关键指标（市值/盈亏/仓位）与上次对比，输出变化摘要
- **回撤监控**：从历史缓存中提取持仓的连续回撤曲线
