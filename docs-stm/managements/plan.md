# 个人投资分析报告生成小助手 — 实现计划

创建日期：2026-06-26
最后更新：2026-07-03（v0.2.64 — ✅ 已完成迭代精简为汇总行，Z 标记名同步，changelog 接替详细记录）

---

## 问题描述

个人投资者需要基于持仓数据和市场行情，生成包含市值核算、资产穿透、基金分析等内容的投资分析报告。当前无现成工具，需从零构建 Python TUI 应用，对接中国金融数据源，输出 Excel 和 HTML 格式报告。

---

## 需求

完整需求详见 [`docs-stm/managements/requirements.md`](requirements.md)。

---

## 关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| TUI 框架 | 原生 `input()` 循环 | 零依赖，开发最快，满足菜单需求 |
| Excel 库 | `openpyxl` | 原生支持 .xlsx 读写、颜色/字体格式设置 |
| HTTP 客户端 | `httpx` | 同步/异步、连接复用，比 requests 现代 |
| 数据解析 | 手动解析，不使用 pandas | 减少依赖，数据量小，自定义校验更可控 |
| 配置持久化 | `data/config/config.json` | JSON 简单可靠，无需额外依赖 |
| AI 全球政经局势 + 智囊团深度复盘 + 持仓体检报告 + 穿透深度分析 + 财经新闻热点与持仓关联分析 | LLM 生成 | 支持 Claude/OpenAI/DeepSeek API，缓存策略分层，System Prompt 外部可配置 |
| 报告模板 | 程序生成（Excel openpyxl / HTML Jinja2） | Excel 和 HTML 报告均程序化生成 |

---

## 当前配置架构

LLM 配置拆分为两个独立文件：

| 文件 | 内容 | 用途 |
|------|------|------|
| `data/config/llm_key.json` | 4 个必填 + 4 个可选回退字段 | API 调用渠道（provider / api_key / model / endpoint / fallback_*） |
| `data/config/llm_settings.json` | 所有非敏感配置 | 参数调优（temperature、timeout、cache、system_prompt、thinking 等） |

---

## 系统影响

- `data/holdings/`、`data/cache/`、`data/config/` 在首次运行时需保证存在
- `data/config/config.json` 在程序生命周期外持久保存，含 `output_dir` 字段控制报告输出位置
- 程序依赖外部中国金融 API，网络不可用时降级运行（使用缓存数据或显示"--"）
- 持仓目录多 xlsx 文件时，用户通过 TUI 选择

---

## 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 腾讯/东方财富 API 变更或封禁 | 行情获取失败 | 备用链路自动切换；缓存支撑当日使用 |
| 持仓 xlsx 格式与预期不一致 | 解析失败或数据错误 | 固定列名解析 + 字段校验 + 友好提示 |
| 基金穿透计算量大 | 报告生成变慢 | 穿透结果缓存每日更新 |
| LLM API Key 未配置 / 超时 | 全球政经局势 / 智囊团深度复盘不可用 | 降级输出占位文本，不阻塞报告生成 |
| LLM Token 费用超预期 | 成本增加 | 缓存 LLM 结果；限制输入上下文；分层缓存 TTL |

### [P2] Y. Edge Case 纵深覆盖增补（四期）（低难度 / 中价值）

当前 39 项 edge 测试集中在零值/空集/时区/缓存等表层。以下从实际使用中可能遇到但尚未覆盖的维度纵深增补，按风险概率排序：

**Y1 — API/网络异常纵深（~15 项）**
- **HTTP 部分响应**：API 返回 200 但 body 截断/不完整 JSON
- **编码不匹配**：服务端返回 GBK 编码，应用层期望 UTF-8
- **SSL/TLS 错误**：证书过期/自签/域名不匹配时的降级
- **DNS 解析失败**：与网络断开的区别——getaddrinfo 失败 vs 连接超时
- **HTTP 重定向**：API 端点返回 301/302，httpx 是否自动跟随
- **429 Retry-After**：限流响应带 Retry-After 头的解析和处理
- **连接重置**：`Connection reset by peer` 中途断开的恢复
- **空 JSON 变体**：`{}` vs `[]` vs `null` vs 纯文本而非 JSON
- **body 内错误码**：HTTP 200 但 body 中 `error_code` 非零
- **代理环境**：HTTP_PROXY/HTTPS_PROXY 环境变量已设置时的请求行为

**Y2 — 数据质量纵深（~15 项）**
- **停牌/无交易数据**：股票代码存在但当日/近期无成交
- **新基金空持仓**：刚成立基金 TOP10 持仓为空
- **穿透数据重复**：同一股票在基金 TOP10 中出现多次（去重验证）
- **多层嵌套穿透**：基金 OF 的持仓中又有 FOF 基金（最多支持几层）
- **ETF 超多持仓**：宽基 ETF 持仓 > 200 只（数据截断边界）
- **负价格/净值**：数据源偶发返回负值的降级处理
- **极低流动性**：股票连续 30 日无成交的价格沿用逻辑
- **债券违约**：净值归零/暂停交易时分类和估值表现
- **同日同一基金多层份额**：A/C 类份额共存时的穿透计算
- **跨市场停牌时差**：A+H 股，一方停牌另一方的估值逻辑

**Y3 — 文件系统纵深（~12 项）**
- **加密/保护 Excel**：xlsx 带密码时的友好提示而非崩溃
- **xlsm 宏文件**：宏文件按 xlsx 读取时的行为
- **隐藏工作表**：`veryHidden` 状态的 sheet 是否被读取
- **损坏 xlsx（非 ZIP）**：非 Excel 文件伪装 .xlsx 后缀
- **UNC 网络路径**：持仓目录在 `\\NAS\share\` 网络路径上
- **文件被占用**：Excel 打开中，同时程序尝试读取
- **权限变更**：读取过程中文件权限被撤销
- **超长路径**：Windows MAX_PATH（260 字符）嵌套超限
- **缓存文件篡改**：手动修改 data/cache/ 下 JSON 内容（注入/损坏）
- **空字节文件**：缓存文件大小为 0 bytes

**Y4 — 数值计算纵深（~10 项）**
- **浮点累加误差**：多品种大额浮点数合计时精度损失断言
- **极微份额**：0.001 份（ETF 允许的最小交易单位）
- **超高单价**：单价 > 10 万元（如贵州茅台）
- **收益率超 ±1000%**：成本极低被收购等情况（不崩、不显示荒谬值）
- **NaN 传播链**：某一数值计算产生 NaN → 所有依赖该值的下游字段均为 NaN 的阻断验证
- **int32 溢出边界**：份额 × 价格超过 2^31 - 1 的跨平台表现
- **成本为负**：数据异常导致的负成本（不触发 crash，记录日志）
- **多数量级相加**：1 万亿 + 0.01 元 ≈ 1 万亿（精度取舍合理）

**Y5 — 配置/环境纵深（~10 项）**
- **BOM 头 JSON**：UTF-8 with BOM 的 config.json 读取
- **0 字节配置文件**：config.json / llm_key.json 为空文件
- **CRLF vs LF**：Windows 编辑的换行符不影响解析
- **llm_key 多余空格**：api_key 值前后有 tab/空格时的 trim 处理
- **环境代理冲突**：HTTP_PROXY 指向无效代理时的绕过机制
- **缺失嵌套键**：llm_settings.json 缺少某模块的配置段时按默认值兜底
- **多个实例并发**：同时开两个终端运行 main.py 的缓存竞争
- **终端无颜色**：`NO_COLOR` 环境变量或管道重定向时 TUI 不输出 ANSI 转义序列

**Y6 — 安全纵深（~8 项）**
- **CSV 公式注入**：持仓名称以 `=` 开头（`=CMD|`）在 Excel 输出中被转义
- **XSS 缓存注入**：缓存 JSON 中包含 `<script>` 标签 → HTML 报告渲染时转义验证
- **符号链接攻击**：`data/cache/` 子路径被符号链接指向敏感目录
- **路径遍历**：配置文件中的路径含 `../` 逃逸到预期目录外
- **API Key 日志泄漏**：异常堆栈中不打印 api_key 原文（已有基础，缺断言）
- **JSON 原型污染**：恶意构造的 JSON 键 `__proto__` 或 `constructor`
- **临时文件竞争**：`tempfile.mkstemp` 创建后、`os.replace` 前的权限竞态

### [P2] Z. 业务场景覆盖增补（二期）（中难度 / 中价值）

当前 S1-S20 覆盖了基础业务链路和 LLM 组合场景，但缺少中国个人投资者实际持有的多个常见品种。按业务领域分组，作为 `scenario_resilience`（S21-S30）和 `scenario_basic`（S0 前置场景）的候选扩展：

**Z1 — 特殊品种场景（~8 项，scenario_resilience）**
- **S21: 港股通持仓**：持仓含港股通标的（腾讯 00700、美团 03690），验证港股通费用/汇率转换/节假日差异
- **S22: 可转债持仓**：含可转债（12xxxx）时分类正确、转股溢价率/纯债价值/到期收益率等特殊指标
- **S23: 公募 REITs**：含基础设施 REITs（18xxxx），现金分派率、特许经营权期限等独特字段
- **S24: 货币基金**：含货币基金/短期理财（万份收益/七日年化），净值恒为 1 的特殊处理
- **S25: 科创板 + 北交所混合**：688（20%涨跌停）+ 8xx（30%涨跌停）同时存在时的分类和涨跌计算
- **S26: 商品/黄金 ETF**：黄金 ETF、有色金属 ETF、豆粕 ETF 等商品类 ETF 的分类和估值
- **S27: 跨境 ETF（美股/港股方向）**：纳指 ETF、恒生科技 ETF 等多只跨境 ETF 的净值延迟和溢价率
- **S28: 纯债/国债持仓**：国债/企业债的利息计算、面值 vs 净价 vs 全价区分

**Z2 — 操作行为场景（~5 项，scenario_resilience）**
- **S29: 分红送转除权**：持仓股票分红送股（10 送 10）后的份额跳变和成本摊薄计算
- **S30: 定投成本摊薄**：同一品种在多个不同日期以不同价格买入，验证加权平均成本计算
- **S31: 部分调仓卖出**：部分卖出持仓后剩余份额的成本（先进先出/加权平均）和盈亏
- **S32: 跨账户转仓**：同一只股票从 A 账户转到 B 账户后，分类汇总中合并计算而非重复
- **S33: 新股中签待上市**：持仓中含尚未上市的 IPO 中签新股，以发行价估值

**Z3 — 持仓质量场景（~4 项，scenario_basic）**
- **S0a: 含已清仓记录**：xlsx 中存在已清仓品种（份额=0），验证自动跳过不会计入报告
- **S0b: 同名基金多份额**：同一只基金的 A 类/C 类份额同时持有，穿透时合并计算
- **S0c: 超多持仓（200+ 条）**：极限持仓量的报告生成时间和内存使用不超限
- **S0d: 持仓名称含特殊字符**：名称含 `®`/`™`/`♥`/全角括号/繁体中文/英文混排，Excel 输出不乱码

**Z4 — 场景补充场景（~5 项，T17-T21 时间补充分组）**
- **T17: 跨月/跨年报告**：12 月 31 日生成和 1 月 2 日生成的跨年行情数据连续性
- **T18: 季末/年末效应**：基金季末调仓日前后净值跳变
- **T19: 汇率中间价故障**：美元/港币汇率数据暂不可用时的 QDII 降级
- **T20: 节假日调休**：调休工作日（周日上班）vs 调休放假（周六休息）的交易日判断
- **T21: 港股通假期差异**：A 股开市但港股通关闭（如佛诞日）时的取价降级
