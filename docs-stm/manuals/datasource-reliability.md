## 1. 概述

本程序依赖 **8 类数据源**（约 20 个 API 端点）完成报告生成。每个数据源在主链路不可用时自动降级到备用链路或过期缓存，部分数据源失败不影响其他模块（模块级隔离）。

数据获取失败路径（从轻到重）：

```
请求 → 首次超时/错误 → 重试（最多 3 次）→ 熔断开启 → 降级到备用链路
→ 备用链路也失败 → 使用过期缓存（如有）→ 返回空/占位文本
```

## 3. 数据源详表

### 3.1 腾讯财经（行情/指数）

| 字段 | 说明 |
|------|------|
| **名称** | 腾讯财经行情 API |
| **用途** | A 股/ETF/LOF/可转债实时行情，A 股指数/全球指数行情 |
| **接口类型** | HTTP GET + JSONP 回调（`qt.gtimg.cn`），K 线 `web.ifzq.gtimg.cn` |
| **数据频率** | 盘中实时（更新间隔取决于请求时机，无 Push） |
| **可靠度** | ★★★★☆——核心行情源，长期稳定；存在单点宕机风险（降级链路保护） |
| **降级目标** | → 新浪财经（`hq.sinajs.cn`）→ 过期缓存 |
| **限流规则** | 未公开限制；高频请求（>5次/秒）可能触发 IP 临时封禁 |
| **免费边界** | 无认证，无用量限制 |
| **超时设定** | 行情 15s，K 线 30s |
| **已知问题** | ① 午盘刚开盘（13:00-13:05）偶尔超时 ② 返回 GBK 编码，需要解码 ③ 仅支持场内品种（场外基金代码直接跳过） |
| **最后验证** | 2026-07-26 |

| **降级目标** | → 腾讯财经（反向回退）→ 过期缓存 |

| **已知问题** | ① 返回 GB18030 编码（与腾讯 GBK 不同） ② 美股指数需 `gb_` 前缀转换（`gb_dji`、`gb_ixic`） ③ 部分品种 K 线不支持超过 365 天 |

### 3.3 东方财富（基金净值）

| 字段 | 说明 |
|------|------|
| **名称** | 东方财富基金净值 API |
| **用途** | 场外基金最新净值、历史净值（分页） |
| **接口类型** | HTTP GET + JSONP 回调（`api.fund.eastmoney.com`） |
| **数据频率** | 每日更新（通常 19:00~22:00 基金公司发布后同步） |
| **可靠度** | ★★★★★——最稳定的净值来源，多年无重大故障 |
| **降级目标** | → 天天基金 fundf10 HTML（`fundf10.eastmoney.com/jjjz_{code}.html`）→ 过期缓存 |
| **限流规则** | 历史净值分页：`pageSize` 上限 20 条（单页最多返回 20 条），超 200 返回 null（实测），页间隔 `time.sleep(0.3)`，最多 10 页 |
| **免费边界** | 无认证，无用量限制 |
| **超时设定** | 15s |
| **已知问题** | ① JSONP 回调包裹需剥离（`_strip_jsonp`） ② 备用链路用正则从 HTML `<td>` 提取净值，易受页面结构变化影响 |
| **最后验证** | 2026-07-26 |

### 3.4 天天基金（持仓/排名/历史净值）

| 字段 | 说明 |
|------|------|
| **名称** | 天天基金数据服务 |
| **用途** | 基金前 10 大持仓、同类排名（百分位/区间收益）、历史净值、评级、风险分析 |
| **接口类型** | HTML 页面解析 + JS 变量提取（`fund.eastmoney.com`） + 季度持仓 API（`FundArchivesDatas.aspx`） |
| **数据频率** | 持仓：季报更新（每年 4/8/10 月末）；排名/评级：每日更新 |
| **可靠度** | ★★★★★——核心基金数据源，依赖东方财富基础设施，长期稳定 |
| **降级目标** | 持仓：主 HTML 页 → 季度 API（多 4 季度回溯）；排名/评级：唯一链路，无可降级目标 |
| **限流规则** | 无明显限流；每次请求独立 |
| **免费边界** | 无认证，无用量限制 |
| **超时设定** | 15s |
| **已知问题** | ① 持仓解析用正则表达式，页面结构变动可能导致解析失败 ② 需区分收益率排行表格（排除 `近N月/季度/年`） ③ 季度 API 返回 JS 字符串包裹，需双重 JSON 解析 ④ 持仓 CSS 选择器 `.leftJzLc font` 若未来变更需同步修改 |
| **最后验证** | 2026-07-26 |

| **名称** | 东方财富行业分类 API |
| **用途** | A 股三级行业归属、概念板块归属、扩展字段（PE/PB/市值） |
| **接口类型** | HTTP GET（`push2.eastmoney.com`），主链路 + REST HTML 备用 |

### 3.6 akshare 扩展服务

| 字段 | 说明 |
|------|------|
| **名称** | akshare 数据封装层 |
| **用途** | 机构盈利预测（`stock_profit_forecast_em`）、行业资金流向（`stock_sector_fund_flow_rank`）、历史分红（`stock_history_dividend`）、无风险利率（`bond_zh_us_rate`） |
| **接口类型** | Python 库调用（通过 `ThreadPoolExecutor` 超时保护） |
| **数据频率** | 盈利预测不定期，资金流向交易日实时，分红年度更新，利率每日 |
| **可靠度** | ★★★☆☆——依赖 akshare 第三方库，接口变更频繁 |
| **降级目标** | ① akshare 未安装 → 静默降级为空结果 ② 调用超时 → ThreadPoolExecutor 强杀 + 重试 1 次 ③ 无风险利率 → `config.json` 手动设置兜底 |
| **限流规则** | 无限流；内存 TTL 缓存（盈利预测 5min，资金流向 1min，分红 10min） |
| **免费边界** | 无认证；akshare 库本身开源免费 |
| **超时设定** | 默认 15s，盈利预测 30s，分红 60s（akshare 同步调用可能阻塞，必须 ThreadPoolExecutor 强杀） |
| **已知问题** | ① **akshare 版本频繁变更** → 接口签名/返回值格式可能变更；升级 `pip install --upgrade akshare` 通常可解决 ② 盈利预测用指数数据指纹做缓存失效，当指数数据不更新时缓存可能过旧 ③ 资金流向仅在交易日有数据，非交易日/盘前返回空 |
| **最后验证** | 2026-07-26 |

## 4. 降级与熔断

### 4.1 三级熔断体系

| 熔断层 | 阈值 | 冷却期 | 退避策略 | 持久化 |
|:-------|:----:|:------:|:---------|:-------|
| **数据源熔断器**（DataSourceRegistry） | 连续 3 次失败（行业 6 次） | 300s（行业 120s） | 指数退避 60s→300s→900s→3600s | `data/state/circuit_breaker.json` |
| **指标熔断器**（IndicatorBreaker） | 连续 3 次失败 | 86400s（24h） | — | `data/cache/metrics_breaker.json` |
| **LLM 端点熔断器** | 连续 3 次失败 | 60s | — | 仅内存 |

### 4.2 Provider Chain 降级路径

| 数据类型 | 主链路 | 备用链路 | 回退条件 |
|:---------|:-------|:---------|:---------|
| `price_stock` | 腾讯财经 | 新浪财经 | 腾讯超时/熔断 |
| `price_fund_otc` | 东方财富 JSONP | 天天基金 HTML | JSONP 解析失败 |
| `industry` | 东方财富 push2 | REST 行情页 | push2 超时/熔断 |
| `history_stock` | 腾讯 K 线 | 新浪 K 线 | 腾讯不可用 |
| `history_index_us` | 新浪 K 线 | 腾讯 K 线（反转，因腾讯不支持 `gb_*`） | 新浪不可用 |

### 4.3 缓存兜底

当主备链路均失败时，`DegradationTracker` 通过双重信号（连续失败次数 + 缓存过时程度）判断是否启用过期缓存：

- **缓存在 TTL 内** → 正常返回（无降级）
- **缓存过期但数据源健康** → 标记降级，仍返回缓存
- **缓存过期且数据源连续失败** → 熔断开启，使用缓存占位
- **无缓存** → 显示占位文本（如 `数据暂不可用`）

> 详细降级治理体系见 `../managements/technical.md` §1.4.5。

## 6. 附录：常见问题排查

### 6.1 数据为空排查路径

| 现象 | 排查步骤 |
|:-----|:---------|
| 某只股票行情为 0 | ① 确认交易时间 ② 查看日志 WARNING（Provider Chain 回退） ③ 检查熔断器 `data/state/circuit_breaker.json` |
| 基金净值未更新 | ① 确认非节假日 ② 确认当天 22:00 后 ③ 查看净值日期字段（可能为 T-1） |
| 行业分类为空 | ① 检查 `push2.eastmoney.com` 是否可连通 ② 确认代码前缀正确（上海 `1.` / 深圳 `0.`） |
| akshare 数据为空 | ① `pip list \| grep akshare` 确认已安装且 ≥1.16.0 ② 尝试 `pip install --upgrade akshare` ③ 查看 `logs/app.log` 中超时/异常详情 |
| 新闻为空 | ① 确认 `enable_news` 为 true ② 勾选的新闻源是否可用 ③ 财联社是否因签名鉴权失败 |

### 6.2 加速建议

- 全量菜单 L 前先执行菜单 E/B，热点缓存命中后 LLM 生成阶段速度更快
- 定期执行菜单 `[3]` 清理过期缓存（不影响 TTL 内数据）
- akshare 接口频繁变更时，以 `pyproject.toml` 锁定的版本为准（当前 `akshare==1.18.64`），必要时在 requirements 中固定版本
