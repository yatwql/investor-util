## Excel 报告

| # | 页签 | 内容说明 |
|:--|------|----------|
| 1 | **1.投资分析汇总** | 当前时间、交易日、A 股/美股指数行情、总市值/成本/盈亏/本日盈亏、持仓概况分类计数、更新状态（分账户小计详见市值核算明细表） |
| 2 | **2.市值核算明细表** | 15 列明细：账户、名称、代码、最新价、净值日期、昨日价、取价方式、溢价率、份额、市值、成本、盈亏、收益率、本日盈亏、取价渠道。取价方式蓝色标识（场内收盘价(T)→蓝、官方净值(T)→蓝、QDII 官方净值(T-1)→蓝），分账户小计+总计 |

| 6 | **6.基金经理变更监控**（菜单 B/L） | 基于快照的基金经理变更检测，1 月/3 月/6 月窗口，变更信息+预警着色，8 列输出 |

| 9 | **9.基金风格分析**（菜单 B/L） | 市值/PE 加权风格判定（六宫格）+网格曼哈顿距离漂移评分（0-4 分三档） |

| 13 | **13.持仓体检报告**（菜单 L） | LLM 从风险分散度、流动性、收益合理性、成本结构四维度量化评分并给出改进建议 |

## 页面/章节分组

17 个报告页签/章节按 `type` 划分为 5 组，各组显示条件和用途不同：

### ① 基础核心（type=always）

始终显示，报告的基础骨架。共 5 个模块：

| # | 页签 | type | 说明 |
|:-:|------|:----:|------|
| 1 | **投资分析汇总** | always | 指数行情、总市值/盈亏、持仓分布概览 |
| 2 | **市值核算明细表** | always | 15 列持仓市值盈亏明细 |
| 3 | **持仓分类表** | always | 资产属性 + 投资分类聚合 |
| 4 | **资产穿透TOP10** | always | 基金底层资产合并排序 |
| 5 | **基金业绩分析** | always | 收益率、评级、基准对比 |

### ② B 系列——基金深度分析（type=b_series）

需要基金持仓数据，有数据才显示。共 4 个模块：

| # | 页签 | type | 说明 |
|:-:|------|:----:|------|
| 6 | **基金经理变更监控** | b_series | 快照式变更检测，1/3/6 月窗口 |
| 7 | **持仓重合度矩阵** | b_series | Jaccard + Overlap Ratio 双指标 |
| 8 | **持仓集中度监控** | b_series | TOP3/5/10 占比 + 三级预警 |
| 9 | **基金风格分析** | b_series | 市值/PE 加权六宫格 + 漂移评分 |

> 菜单 B/L 可输出，有基金持仓数据且 B 系列计算完成后才渲染。

### ③ 新闻板块（type=news）

需要启用新闻功能。共 1 个模块：

| # | 页签 | type | 说明 |
|:-:|------|:----:|------|
| 10 | **财经新闻热点与持仓关联分析** | news | 5 源新闻关键词匹配，可选 LLM 二次关联 |

> 菜单 B/L 可输出，依赖 `enable_news = true`。

### ④ LLM 分析（type=llm）

需要启用 LLM 功能。共 5 个模块：

| # | 页签 | type | 说明 |
|:-:|------|:----:|------|
| 11 | **全球政经局势** | llm | 指数行情 + 持仓结构的全球局势分析 |
| 12 | **智囊团深度复盘** | llm | 三阶段圆桌会议式深度复盘 |
| 13 | **持仓体检报告** | llm | 四维度量化评分 |
| 14 | **穿透深度分析** | llm | 行业集中度 + 国别/币种暴露 |
| 17 | **LLM API 用量** | llm | Token 消耗与费用统计（强制末位） |

> 仅菜单 L 输出，依赖 LLM 功能已配置并启用。#17 LLM API 用量为被动统计页签，非 LLM 生成内容，因技术约束强制位于末位。
>
> **事实锚定校验**：每个 LLM 模块（#11~#14）的 HTML 内容底部自动追加事实校验摘要行。
> 校验器在纯算法层（无需额外 LLM 调用）执行三项检查：
> 1. **数值一致性** — 引用百分比与持仓实际数据（个股收益率 → 优先匹配个股，无个股时回退组合总收益率；收益归因段落自动跳过；指数/宏观指标自动跳过）
> 2. **品种存在性** — 引用代码确实在持仓中（穿透分析场景自动包含底层穿透代码）
> 3. **排名正确性** — "最大持仓"/"第一重仓"等断言与实际排名一致（穿透分析模块跳过此项）
>
> 校验结果以绿色 `✓ 通过` 或黄色 `⚠ 提示` 行展示。黄色提示表示 LLM 输出存在潜在不准确，建议交叉验证。

### ⑤ 历史走势（type=history）

始终显示，数据不可用时显示占位文本。共 2 个模块：

| # | 页签 | type | 说明 |
|:-:|------|:----:|------|
| 15 | **组合历史走势** | history | as-if 市值模拟折线图（含基准指数叠加对比） |
| 16 | **历史回撤分析** | history | 最大回撤、波动率等风险指标 |

> 菜单 B/L 可输出，由 `history.analysis` 配置（`"off"` / `"prompt"` / `"auto"`）控制获取行为，数据不可用时不阻断报告生成。

### 可见性规则总览

两层可见性模型：
- **board 层**：用户配置的板块开关（`enable_b_series`/`enable_news`/`enable_history`/`enabled_llm`），关闭则整个类型的章节完全隐藏
- **data 层**：运行时数据可用性，某模块数据不可用时仅隐藏该模块自身
- 两层 AND 关系：board 层关闭 → 隐藏全部；board 层开启但 data 层不可用 → 仅隐藏该模块

| type | board 层控制 | data 层条件 | 菜单来源 |
|:-----|:------------|:------------|:---------|
| `always` | 无条件 | 无 | E / B / L |
| `b_series` | `enable_b_series` | 有基金持仓数据 | B / L |
| `news` | `enable_news` | 新闻获取成功 | B / L |
| `llm` | `enabled_llm`（任一报告模块启用） | LLM 内容生成成功 | L |
| `history` | `enable_history` | 历史走势数据可用（不可用时占位） | B / L |

## F 系列数据机制

报告第 15 节（组合历史走势）和第 16 节（回撤分析）依赖 F2 历史走势数据，而页脚中的快照对比信息来自 F1 快照系统。两者是两套独立机制，互不依赖。

### F1 持仓快照对比

每次生成报告时自动拍下当前持仓状态的"快照"留存，下次生成时与上次快照对比。

| 项目 | 说明 |
|:-----|:------|
| **存储位置** | `data/history/snapshots/snapshot_{时间戳}.json` |
| **输出内容** | 总市值变化、总盈亏变化、持仓变动 TOP5（新增/清仓/增持/减持） |
| **显示位置** | 嵌入第 16 节（回撤分析）页脚的快照摘要卡片 |
| **触发方式** | 菜单 E/B/L 均自动执行，无需配置 |
| **生命周期** | 保留 60 天，最多 365 个，超限自动清理最旧快照 |
| **首次生成** | 无历史快照时跳过对比，下次自动建立基线 |

**适用场景**：想知道"和上次出报告时比，组合整体是赚是亏？哪些品种变动最大？"

### F2 组合历史走势

假设当前持仓份额在过去一段时间不变，获取每只资产的历史价格/净值，模拟出组合每天的"假如市值"。

| 项目 | 说明 |
|:-----|:------|
| **数据来源** | A 股/ETF → 腾讯或新浪 K 线接口；场外基金 → 天天基金（主）+ 东方财富历史净值 API（备用）；基准指数 → 腾讯→新浪 K 线（走 `history_index` chain） |
| **数据获取链路** | 场外基金：tiantian(`pingzhongdata/{code}.js`) → 空数据时自动 fallback 到 eastmoney(`api.fund.eastmoney.com/f10/lsjz` 分页获取，单页 20 条，最多 10 页)；基准指数通过 `fetch_index_history()` → `history_index` chain 并行获取 |
| **存储位置** | `data/cache/history_stock_{code}.json` / `history_fund_otc_{code}.json` / `history_index_{code}.json`（标准缓存系统） |
| **输出内容** | §16 走势折线图（含基准指数叠加对比，累计收益/最大回撤/年化波动率三卡片）+ §17 回撤面积图（含基准指数回撤对比） |
| **触发方式** | 由 `config.json` 的 `history.analysis` 控制： |
| | `"off"` — 关闭，走势图显示占位文本 |
| | `"prompt"` — 报告生成后询问是否获取 |
| | `"auto"` — 报告生成时自动获取 |
| **数据可用性** | `status: "ok"`（全部成功）/ `"degraded"`（部分失败）/ `"unavailable"`（全部失败） |
| **缓存机制** | 不归任何 cache_group，菜单 [1][2] 不会误清，仅按 TTL 过期（股票 7 天/基金 30 天） |
| **00 代码降级** | A 股 K 线全空时自动切换至基金净值链路（适用于 00 开头的场外基金） |
| **累计收益率起算** | 从 ≥覆盖阈值 持仓都有数据的日期起算（正向扫描），同时从 ≥覆盖阈值 持仓有数据的最近日期截止（反向扫描）。避免起算点过早（只有部分基金）导致收益率虚高，也避免截止点过晚（部分基金净值未刷新）导致收益率虚低。覆盖阈值默认 80%，可在 `config.json` 的 `history.coverage_threshold` 中调整 |
| **净值滞后处理** | 采用 LOCF（Last Observation Carried Forward）：QDII/债券基金等净值更新较慢的标的，在无新数据日沿用上次已知净值，而非计入 0。确保组合市值不因数据更新节奏差异而失真 |
| **回撤计算口径** | 回撤 = 当前市值 - 峰值市值（金额）；回撤百分比 = 回撤金额 / 峰值市值 × 100%。最大回撤为整个区间内最深的那次从峰顶到谷底的跌幅，返回值为负数 |
| **基准指数对比** | 通过 `config.json` 的 `history.benchmark_indices` 配置（默认 `{"sh000300": "沪深300", "gb_inx": "标普500"}`），可指定 1 个或多个基准指数。走势图自动叠加指数归一化曲线（以组合起算日为基点归一化至 100），回撤图同样叠加指数回撤序列。数据走 `history_index` chain（腾讯→新浪双链路），`ThreadPoolExecutor` 并行获取，各指数独立处理互不影响。Excel 报告的 `portfolio_history` 页签每基准一列，`drawdown_analysis` 页签展示对比指标矩阵（累计收益率/最大回撤/波动率等） |

**适用场景**：想知道"如果持仓一直没动，过去一段时间的市值波动和最大回撤是多少？"

### 常见收益率误解

组合历史走势采用 **as-if 模拟**：假设当前持仓份额在过去不变。由于 QDII/债券等基金的历史净值数据覆盖面长度不一，若直接从最早日期起算累计收益率，会因早期只有部分基金入列导致 `first_val` 偏小、收益率虚高。累计收益率从 ≥覆盖阈值 持仓覆盖的日期起算（**双向截断**：起算点正向扫描 ≥阈值，截止点反向扫描 ≥阈值），排除此干扰。覆盖阈值默认 80%，可通过 `config.json` 的 `history.coverage_threshold` 调整。

### F1 vs F2 对比

| | F1 快照对比 | F2 历史走势 |
|:---|:-----------|:-----------|
| **视角** | 两次报告之间的实际变化 | 回溯过去 N 天的假设表现 |
| **依赖** | 上一次报告的快照文件 | 第三方行情/净值 API |
| **配置** | 无开关，始终执行 | `history.analysis` 三档控制 |
| **覆盖范围** | 全部持仓（含失败持仓的快照差异） | 仅成功获取到历史数据的持仓 |
| **首次运行** | 跳过对比，下次生效 | 只要 API 有数据即可生成 |
| **失败处理** | 跳过对比，不影响其他模块 | 走势图+回撤降级显示占位文本 |

## LLM API 用量页签/章节说明（页签 17 / HTML 第 17 节）

本页签/章节是对当前会话中所有 LLM 调用量的**统计汇总**，并非独立的 LLM 生成内容。跟踪范围包括全部 5 个 LLM 子模块（1 个可选）（全球政经局势、智囊团深度复盘、持仓体检报告、穿透深度分析 + 已启用 LLM 服务的财经新闻热点与持仓关联分析）。

### 触发条件

| 条件 | 行为 |
|:-----|:-----|
| 菜单 L 执行且 `enabled_llm` 中任一报告模块启用，至少一个模块触发 API 调用或缓存命中 | ✅ 正常生成页签/章节 |
| 菜单 L 执行且 `enabled_llm` 中任一报告模块启用，但全部为缓存命中（无实际 API 调用） | ✅ 生成，汇总区标注"无新增 API 调用" |
| 菜单 L 执行但 `enabled_llm` 中 4 个报告模块全部关闭 | ❌ 整页不渲染（board 层关闭） |
| LLM API Key 未配置但 `enabled_llm` 有模块启用 | ❌ 整页不渲染（无用量数据） |
| 菜单 B / E（不含 LLM） | ❌ 不生成 |

### 与 LLM 分析章节的关系

LLM API 用量页签/章节被动跟踪以下 5 个子模块（1 个可选）的调用数据，**不能单独启用或关闭**，随菜单 L 的 LLM 分析章节一并输出：

| 模块 | 触发条件 | 说明 |
|:-----|:---------|:-----|
| 全球政经局势 | 菜单 L + `enabled_llm.global_macro = true` | 默认启用 |
| 智囊团深度复盘 | 菜单 L + `enabled_llm.expert_review = true` | 默认启用 |
| 持仓体检报告 | 菜单 L + `enabled_llm.health_check = true` | 默认启用 |
| 穿透深度分析 | 菜单 L + `enabled_llm.penetration_deep = true` | 默认启用 |
| 财经新闻热点与持仓关联分析（LLM 二次关联部分） | 菜单 L + `enabled_llm.news_correlation = true` | 可选模块，仅在 LLM 新闻关联开启时计入统计 |

> **注意**：财经新闻热点与持仓关联分析的基础新闻匹配（关键词富化）**不消耗 LLM Token**，仅在其 `enabled_llm.news_correlation = true` 时，LLM 二次关联分析产生的 Token 才计入本页签。

### Excel 格式

页签名：`17.LLM API 用量`，位于 Excel 报告最右侧。

**系统缓存统计：** 页签底部追加"▎数据缓存系统"区域，展示数据缓存命中/未命中/总请求数/命中率（仅在有缓存请求时显示）。

#### ① 汇总数据区（顶部，仅在有实际 API 调用时显示）

以键值对形式列出本会话的 LLM 整体用量：

| 字段 | 说明 | 示例 |
|------|------|------|
| API 调用次数 | 本次生成实际发起的 API 请求次数（缓存命中不计入） | `4 次` |

## 基金业绩评价标准

一句话：天天基金同类排名 → 类型差异化阈值 → 超额收益修正，三级判定。

基金业绩分析采用 **三层计算逻辑**，数据来源于天天基金 API：

### 第 1 层：基础评级

基于同类排名百分位（`Data_rateInSimilarPersent`），**5 级**评级体系：

#### 1.1 默认阈值（主动型/混合型）

| 排名百分位 | 基础标签 |
|:-----------|:---------|
| ≤ 10%（前 1/10） | **优秀** |
| 10% ~ 30% | **良好** |
| 30% ~ 50% | **稳定** |
| 50% ~ 75% | **偏差** |
| > 75%（后 1/4） | **较差** |

#### 1.2 类型差异化阈值

不同基金类型使用差异化排名百分位阈值，更客观反映同类相对表现：

| 基金类型 | 优秀 | 良好 | 稳定 | 偏差 | 较差 |
|:---------|:----|:----|:----|:----|:----|
| 默认（主动/混合） | ≤ 10% | 10~30% | 30~50% | 50~75% | > 75% |
| 债券型 | ≤ 15% | 15~35% | 35~55% | 55~80% | > 80% |
| QDII | ≤ 15% | 15~35% | 35~55% | 55~80% | > 80% |
| 指数型 | ≤ 10% | 10~25% | 25~45% | 45~70% | > 70% |

> 债券型/QDII 使用更宽松阈值（债券型同类分化较小，QDII 样本量少），指数型使用更严格阈值（被动管理差异本应极小）。
> API 无百分位数据时降级使用排名/总数折算百分位。

### 第 2 层：超额收益修正

基于 `Data_performanceEvaluation` 中的超额收益评分调整评级：

| 超额收益评分 | 修正规则 |
|:-------------|:---------|
| ≥ 80 | 基础评级**上调一级**（如 良好 → 优秀） |
| 40 ~ 80 | 维持基础评级不变 |
| < 40 | 基础评级**下调一级**（如 偏差 → 较差） |

### 第 3 层：显示与标色

| 最终标签 | Excel / HTML 标色 | 显示文本 |
|:---------|:------------------|:---------|
| **优秀** | 红色 `#CC0000` | 持续跑赢基准，超额收益显著 |
| **良好** | 默认 | 稳定跑赢基准，组合管理得当 |
| **稳定** | 蓝色 `#0066CC` | 收益率稳健，波动控制良好 |
| **偏差** | 绿色 `#009900` | 近期表现欠佳，需关注持仓变化 |
| **较差** | 深绿 `#006400` | 同类排名靠后，建议评估持续持有理由 |

## 附录：投资产品知识点

本附录解释报告中出现的专业概念，帮助理解各项数据的含义。

### 基础概念

#### 场内 vs 场外

| 概念 | 含义 | 示例 |
|:-----|:-----|:-----|
| **场内** | 在证券交易所（上海/深圳/香港）上市交易的品种，可通过证券账户买卖 | 股票、ETF、LOF |
| **场外** | 不在交易所上市，通过基金公司、银行、第三方平台（支付宝等）申购/赎回 | 开放式基金（非 ETF） |

**程序自动识别**：6 位数字代码标记 A 股/ETF（场内），F 开头的标记场外基金。识别结果在报告中以取价方式列的颜色区分。

#### 实时价 vs 净值

| 取价方式 | 含义 | 适用品种 |
|:---------|:-----|:---------|
| **实时价** | 交易时段内实时变动的最新成交价 | 场内股票/ETF（盘中） |
| **收盘价** | 当日收盘后的最终价格 | 场内股票/ETF（盘后） |
| **净值（NAV）** | 基金每份的实际价值，每日更新一次 | 场外基金 |
| **官方净值(T-1)** | 上一个交易日的净值，适用 QDII | QDII 基金 |

报告中取价方式列以**蓝色**标识净值/收盘价，默认色为实时价。

#### QDII 基金

**QDII**（合格境内机构投资者）基金投资于海外市场（美股、港股、欧股等）。由于跨境结算和时区差异，其净值通常滞后 1 个交易日（T-1），即今天看到的净值实际上是前一个交易日的。报告中取价显示为蓝色"官方净值(T-1)"属正常现象。

#### ETF 与场外基金的区别

| 维度 | ETF | 场外基金 |
|:-----|:----|:---------|
| 交易方式 | 交易所买卖（与股票相同） | 申购/赎回（T+1 确认） |
| 价格 | 实时交易价（盘中变动） | 每日净值（日终更新） |
| 费用 | 佣金（同股票交易） | 申购费/赎回费 |
| 溢价/折价 | 有（市价偏离净值） | 无（按净值申购/赎回） |

#### 溢价率

仅针对场内 ETF/LOF 计算：

`溢价率 = (最新价 − 净值) ÷ 净值 × 100%`

- **正值**（溢价）：市价高于净值，意味着买贵了
- **负值**（折价）：市价低于净值，意味着折价买入
- 场外基金和股票不计算溢价率，对应列显示 `--`

#### 浮动盈亏 vs 已实现盈亏

报告中的盈亏均为**浮动盈亏**（未实现损益）：

`浮动盈亏 = 当前市值 − 持仓成本 = 最新价 × 持仓份额 − 成本价 × 持仓份额`

程序不保留历史交易流水，不计算已实现盈亏。显示结果未扣除交易佣金和税费。

#### 简单收益率 vs 年化收益率

报告使用**简单收益率**：

`收益率 = 浮动盈亏 ÷ 总成本 × 100%`

按持仓天数年化需要知道每笔持仓的买入日期，程序不记录该信息，故不提供年化收益率。

#### `--` 的含义

报告中出现 `--` 表示该字段数据获取失败或不可用，常见于：
- 某数据源暂时不可用但已成功 fallback 到备用链路
- 基金无对应期限收益率数据（如新成立基金不满 3 个月）
- 股票无机构研报覆盖
- QDII/货币基金/理财型基金不公开持仓明细

该标记不影响其他数据列。

### 资产穿透

**穿透** 是指将基金等持仓标的逐层拆解到底层资产（ETF→成分股、联接基金→底层基金），合并计算后在"资产穿透 TOP10"页签展示实际持仓比例最高的前 10 项底层资产。

**为什么需要穿透？**
- 表面上看你持有 5 只不同的基金，但这 5 只基金可能都重仓同一只股票
- 穿透后能揭示真实的行业集中度和个股风险暴露
- 避免"伪分散"（买了多只基金但底层资产高度重叠）

**穿透流程**：
1. 获取每只基金的前 10 大持仓明细（来自天天基金季报数据）
2. 将持仓明细按底层资产代码合并
3. 按持有市值排序，取 TOP10
4. 标注每项资产的板块、概念、盈利预测等信息

无法获取穿透数据的基金在底部单独列出（常见于 QDII/货币基金/新成立基金）。

### 基金业绩评价

#### 5 级评级体系

基于同行排名百分位，按 5 个等级评价：

| 评级 | 含义 |
|:-----|:------|
| **优秀**（红色） | 排名前 10%，持续跑赢基准 |
| **良好**（默认） | 排名 10%~30%，稳定跑赢基准 |
| **稳定**（蓝色） | 排名 30%~50%，收益稳健 |
| **偏差**（绿色） | 排名 50%~75%，近期欠佳 |
| **较差**（深绿） | 排名后 25%，建议评估 |

不同类型基金使用差异化阈值（债券型/QDII 更宽松，指数型更严格），再经过超额收益评分修正得到最终评级。详见本文件「基金业绩评价标准」章节。

#### 同行排名百分位

百分位数值表示该基金在同类基金中的相对位置。例如百分位 10% 意味着该基金表现优于 90% 的同类基金。

#### 超额收益

基金实际收益率减去业绩比较基准收益率后的差额。正超额收益表示基金经理创造了额外价值。超额收益评分 ≥80 时评级上调一级，<40 时下调一级。

### 组合分析指标

#### 最大回撤（Max Drawdown）

衡量组合从峰值跌落到谷底的最大跌幅，是评估风险的重要指标。

`最大回撤 = (谷底市值 − 峰值市值) ÷ 峰值市值 × 100%`

- 返回值**为负数**（如 -15% 表示从高点下跌了 15%）
- 越接近 0% 说明组合波动控制越好
- 最大回撤越大，恢复所需时间越长

#### 年化波动率

衡量组合收益率的标准差年化值，反映组合的波动程度：
- **低波动率**（<10%）：组合较稳定，适合保守型投资者
- **中等波动率**（10%~20%）：正常市场波动
- **高波动率**（>20%）：波动剧烈，可能导致较大亏损或盈利

#### as-if 模拟

组合历史走势采用 **as-if 模拟** 方法：假设当前持仓份额在过去一段时间内保持不变，回溯每只资产的历史价格/净值，模拟出组合每天的"假如市值"。

**重要说明**：
- 这不是真实的历史收益——因为你在过去可能没有持有这些份额
- 目的是展示"当前配置在历史行情下的表现"
- 帮助评估当前组合在类似市场环境下的潜在风险

#### LOCF（Last Observation Carried Forward）

当 QDII/债券基金等净值更新较慢时（如遇海外节假日），程序采用 LOCF 方式处理：在无新数据日沿用上次已知净值，而非计入 0。确保组合市值不因数据更新节奏差异而失真。

#### 累计收益率起算

组合历史走势中，累计收益率**从 ≥80% 持仓覆盖的日期起算**。这是因为 QDII/债券基金等历史数据长度不一，如果从最早日期起算，早期只有少数基金有数据，会导致市值偏低、收益率虚高。

早期数据仍保留在走势图上供查看，但不纳入收益率计算。

### 持仓分析指标

#### Jaccard 系数与 Overlap Ratio

用于衡量两只基金持仓的**重合度**：

| 指标 | 含义 |
|:-----|:------|
| **Jaccard 系数** | 交集股票数 ÷ 并集股票数（衡量选股相似度）|
| **Overlap Ratio** | 共同持仓市值 ÷ 总持仓市值（衡量实际重叠程度）|

报告中取两者的最大值作为重合度得分，0=完全不同，1=完全一致。

#### 行业资金流向

统计各行业板块的**主力资金净流入/流出**情况，用于判断当前市场资金的板块偏好：

- **正数**（净流入）：资金在买入该板块
- **负数**（净流出）：资金在卖出该板块

#### 持仓集中度

衡量组合中 TOP N 持仓占总市值的比例：
- **TOP3**：前 3 大持仓占比
- **TOP5**：前 5 大持仓占比
- **TOP10**：前 10 大持仓占比

集中度过高（如 TOP3 > 60%）意味着组合风险未充分分散，需警惕单品种风险。
