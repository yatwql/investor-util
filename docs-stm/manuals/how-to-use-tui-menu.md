# TUI 菜单操作手册

> **CLI 命令行模式**：CLI 模式（`.venv/bin/python -m src.python.cli`）使用 `--help` 参数查看等价操作，无需 TUI 界面。
> 详见[CLI 命令行模式使用指南](how-to-use-cli-mode.md) §13「定时任务」。

## 主菜单总览

启动程序后进入 TUI 文本界面主菜单：

```
  > [E] 生成基础版Excel分析报告
    [B] 生成标准报告(Excel+HTML) [按章节配置]
    [L] 生成完整报告(Excel+HTML) [含LLM，按章节配置]
    [W] 调仓 What-if 模拟（对比两份持仓，独立报告）
    [C] 配置持仓信息目录
    [F] 配置持仓信息文件名
    [O] 配置报告输出目录
    [1] 更新基础类缓存
    [2] 更新行情类缓存（含价格/指数等）
    [3] 清理过期缓存文件
    [4] 查看缓存/状态统计
    [P] 配置报告可选章节（基金深度分析/市场新闻/组合历史走势+回撤/组合演进/行动建议/报告增强子模块）
    [I] 管理对比指数池
    [A] 配置持仓匿名化（代码/名称脱敏）
    [S] 配置LLM分析章节
    [R] 刷新配置
    [V] 查看最近运行日志（可按级别筛选）
    [H] 查看数据源健康历史（近期检查记录）
    [D] 系统自检（环境/配置/目录/数据源一键体检）
    [X] 退出
```

> **[D] 系统自检为实验功能**（开关 `doctor_check`，默认关闭）——开关关闭时该菜单项**整体不出现在主菜单中**（就地裁剪，非置灰）。在菜单 **[S]** 配置界面的「实验功能」区块勾选「系统自检」即可开启（或直接编辑 `features.json`；亦可用 CLI `--experiment doctor_check` 单次生效）。关闭与否只影响菜单可见性，**不影响 `doctor` 子命令**——CLI 侧始终可用。

### 键盘操作

| 操作 | 说明 |
|------|------|
| **↑ ↓** | 方向键上下移动选择项 |
| **Enter** | 确认执行当前选中项 |
| **字母/数字键** | 快捷键直达功能 |
| **Ctrl+C** | 退出程序 |

> 方向键在 SSH / tmux 下可能无效，可使用字母/数字快捷键替代。

## 各菜单项详解

### 报告生成类

#### [E] 生成基础版 Excel 分析报告

读取持仓 → 获取行情 → 生成 Excel 报告，默认包含 7 个核心页签：
- 投资分析汇总、市值核算明细表、持仓分类表、资产穿透 TOP10、基金业绩分析、组合演进、数据源可用性矩阵

其中组合演进章节由配置项 `enable_portfolio_evolution` 控制（默认开启，可在菜单 `P` 切换）。行动建议章节由 `enable_action` 控制（默认开启，可在菜单 `P` 关闭，开启后 E/B/L 均输出）。无新闻、无 LLM、无基金深度分析。生成速度最快，适合快速查看持仓概况。

#### [B] 生成标准报告（Excel+HTML）[按章节配置]

在 E 的基础上增加：
- **财经新闻** — 5 源并行获取，与持仓关键词关联匹配
- **组合历史走势与回撤** — 视 `history.fetch_mode` 配置而定
- **基金深度分析** — 基金经理变更监控、持仓关系矩阵、持仓集中度监控、风格与因子分析
- **环比摘要/快照对比** — 与上次报告自动对比

不含 LLM 分析。

#### [L] 生成完整报告（Excel+HTML）

全功能报告，在 B 的基础上增加：
- **LLM 多模块分析** — 全球政经局势、智囊团深度复盘、持仓体检报告、穿透深度分析、新闻关联分析（可选）
- **行业资金流向** — 注入实时行业资金流数据
- **LLM API 用量页签** — Token 消耗统计、费用估算

> **建议使用顺序**：按菜单 L 生成全量报告（含 LLM），如需单独生成不含 LLM 的版本可随后执行 B 或 E，程序会复用已缓存的行情和新闻数据。

#### [W] 调仓 What-if 模拟（对比两份持仓，独立报告）

对比**基准持仓（调仓前）**与**目标持仓（调仓后/假设）**两份持仓文件，生成独立调仓 diff 报告（不并入主报告管线）：
1. **选择基准持仓**（调仓前）— 默认使用当前配置的持仓文件，或从目录中挑选
2. **选择目标持仓**（调仓后/假设）— 从持仓目录中挑选基准之外的另一份 xlsx 文件；若目录只有基准一份，引导选择：`[1]` 自动复制基准为可编辑模板（生成 `<基准名>-调仓后模板.xlsx`，改份额后再运行）/ `[2]` 手动输入目标文件完整路径
3. **输入调仓生效日（可选）**— 直接回车跳过则仅做成本口径截面比较；输入 `YYYY-MM-DD`（如 `2026-07-01`）则 opt-in 联网取生效日后行情，追加**时序回测**（区间/年化收益、波动率、夏普、最大回撤）
4. 程序输出 **Excel**（调仓摘要 / 分类配置对比 / 持仓变动明细 3 页签 + 指定生效日时第 4 页签「时序回测」）+ **HTML**（双栏对比 + 资产配置双环图 + 回测折线图）

产物输出到报告输出目录：最新版固定名 `调仓模拟.xlsx/.html`（每次覆盖为最新对比），历史归档至 `YYYYMMDD/` 日期子目录（超 180 天自动清理），独立输出不影响主报告。默认全程**本地计算、零网络请求**；仅指定生效日时联网取历史。

> **设计边界**：What-if 模拟为**成本口径**截面比较（份额 × 每份成本）；指定生效日启用时序回测为**假设推演、不构成收益承诺**，数据不足时回测降级不阻塞主报告。详见[报告说明](reports-instruction.md#调仓-what-if-模拟独立报告)。

### 配置管理类

#### [C] 配置持仓信息目录

修改持仓 `.xlsx` 文件所在目录路径。程序会列出该目录下所有 `.xlsx` 文件供选择。

#### [F] 配置持仓信息文件名

修改要读取的持仓文件名。配合 [C] 使用。

#### [O] 配置报告输出目录

修改报告输出目录（默认 `reports/`）。每次生成同时保留两份：
- **最新版** — `个人投资分析报告.xlsx` / `个人投资分析报告.html`（覆盖写入）
- **归档版** — `个人投资分析报告-YYYYMMDD-HHMMSS.xlsx` / `.html`（按日期命名）

> 程序自动清理 180 天前的归档目录，如需长期保留请移出 `reports/`。

#### [P] 配置报告可选章节

交互式配置报告可选章节的显示/隐藏：
- **基金深度分析** — 基金经理变更监控/持仓关系矩阵/持仓集中度监控/风格与因子分析
- **市场新闻** — 财经新闻热点与持仓关联分析
- **历史走势** — 组合历史走势与回撤（走势表 + 回撤矩阵 + 危机区间标注）
- **组合演进** — 组合演进/多快照趋势
- **行动建议** — 再平衡信号/交易纪律/调仓建议/收益归因
- **报告增强子模块** — 进入子菜单配置 6 项区块级开关（数据质量仪表盘 / 行业Beta子表 / 候选基金比较子表 / 成本流水 / 估值分位 / 市场温度），数据质量仪表盘默认开启，其余默认关闭，实时保存到 `config.json` 的 `report_submodules`。开启后对应章节按需增强区块，不改变既有章节输出

关闭的章节在报告中完全隐藏，剩余章节自动连续重新编号。LLM 分析章节可见性通过菜单 [S] 或 `llm_settings.json` 控制。

#### [S] 配置 LLM 分析章节

交互式子菜单，分两组控制：

**标准 LLM 模块（1-5）**：5 个 LLM 分析模块独立启停，实时保存到 `llm_settings.json` 的 `enabled_llm`。禁用模块在报告中完全跳过，不调用 LLM API。

**⚗ 实验性功能（6-14）**：实验性增强通路，面板中以 ⚗ 标识区分，默认全部关闭。开关清单由 `features.EXPERIMENTAL_FEATURES` 注册表驱动（新增实验开关会自动上屏）：
| 编号 | 名称 | 效果 |
|:----:|:-----|:------|
| 6 | ⚗ 辩论-正反辩论 | 智囊团复盘→三段式(白脸→黑脸→综合)，pro(绿)/con(红)/synthesis(金)三色块 |
| 7 | ⚗ 辩论-条件推理 | 注入预设市场情景(上涨/下跌/震荡)，使分析结果情景化 |
| 8 | ⚗ 辩论-集中度问答 | 单品种占比≥20%时自动生成集中度量化评估块（标准模式嵌入专家复盘，辩论模式嵌入综合权衡，位于调仓建议之前） |
| 9 | ⚗ 决策跨期反思闭环 | 登记投资决策 → 用真实行情结算命中率 → 将教训回灌专家复盘提示词 |
| 10 | ⚗ 信号预消化 | 市场温度/估值分位/尾部风险预消化为 `信号：…` 方向行注入复盘与体检提示词，减少模型读裸数值的误判 |
| 11 | ⚗ 模块级质量分级 | 对 4 个 LLM 模块输出按完整性/篇幅评 A~F，低评级者随内容头部注入 `【内容质量提示】` 横幅（只标注、不阻断、不重试） |
| 12 | ⚗ 决策头结构化 | 专家复盘提示词追加受控 JSON 决策头，抽取优先读结构化、失败回落确定性表格解析（决策词归一，防写反方向） |
| 13 | ⚗ 确定性信号沉淀 | 温度/估值分位/尾部风险/风格因子/再平衡超限五类确定性评级沉淀为账本，附实时/非实时标签（统计默认只算实时） |
| 14 | ⚗ 系统自检 | 开启后主菜单出现 `[D]` 系统自检项、Web 出现自检卡片（CLI `doctor` 子命令不受本开关约束） |

> **⚗ 实验性功能说明**：6~14 是**相互独立的开关**，默认全部关闭，可任意组合开启。**正反辩论（6）**开启后，智囊团复盘改为"看多 → 看空 → 收敛结论"三段式输出；**条件推理（7）**为分析注入上涨/下跌/震荡情景，使结果情景化；**集中度问答（8）**在单品种占比≥20% 时自动附加集中度量化评估——标准模式嵌入专家复盘，辩论模式嵌入综合权衡（位于调仓建议之前），均要求输出量化评估/基准对比/调仓建议；**决策跨期反思闭环（9）**在行动建议章内嵌「历史决策复盘」块（HTML + Excel），需先有已结算的历史决策记录才有内容；**信号预消化（10）**把算法层已算出的确定性结论（市场温度档位/持仓估值分位分布/尾部风险幅度）预先消化为带方向标注的信号行，置于提示词结论位置（先给结论、再看明细），让模型读结论而非从裸数值自行推断方向（改动提示词内容与缓存键，属实验级观察项）；**模块级质量分级（11）**给 4 个 LLM 模块输出评 A~F，只有「内容在但存在缺陷」（缺必需章节/篇幅明显偏短）的低评级才在内容头部加一条 `【内容质量提示】` 横幅——A/B 级健康输出零噪音，内容缺失型（空内容/降级占位）已有各自醒目提示故不叠加，全程**不改生成流程、不重试、不写回缓存**；**决策头结构化（12）**让抽取侧优先读机器可读的结构化决策头、失败才回落表格解析，两路共用同一套决策词归一判据（长词优先+否定守卫+复合词左边界+二义不猜），防「不建议加仓」被判成加仓；**确定性信号沉淀（13）**把五类确定性算法评级沉淀为账本并注入智囊团复盘提示词，统计默认只算实时记录；**系统自检（14）**控制 TUI 主菜单 `[D]` 项与 Web 自检卡片的**可见性**（关闭时该菜单项/卡片整体不出现），自检本身为只读诊断、自身永不抛异常。

辩论模式开启后，智囊团复盘页签标题尾部附加 `🧪 辩论模式` / `🧪 实验模式` 标签。同一次报告周期内辩论模式与标准模式互斥（辩论优先）。

多个辩论模式可同时开启（如正反辩论+条件推理）。启用后，**HTML 报告页脚**和 **LLM 用量页**会显示当前启用的模式组合标识（如"🧪 辩论模式 · 正反辩论+条件推理"），方便确认生效的组合。**Excel 报告**的 LLM 用量行也会展示相同的组合标识。

> **⚠ 实验阶段说明**：实验性功能当前处于实验阶段，输出质量可能不稳定。TUI 面板中实验开关区域以 ⚗ 标识和独立分隔线区分，底部附实验阶段提示。辩论模式开启后如生成失败会自动回退标准模式，不影响报告生成。

> **关于 Feature Flag**：实验性功能开关存储在 `data/config/features.json`（不必须存在，首次切换自动创建）。该文件为纯 JSON 格式（不支持 `//` 注释），仅记录与代码默认值不同的开关。手动编辑示例：
>
> ```json
> {
>   "llm_debate_procon": true,
>   "decision_reflection": true
> }
> ```
>
> 可用的实验开关对照：
>
> | features.json 键名 | 菜单编号 | 功能 |
> |:-------------------|:--------:|:------|
> | `llm_debate_procon` | 6 | 辩论-正反辩论 |
> | `llm_debate_conditional` | 7 | 辩论-条件推理 |
> | `llm_debate_qa_concentration` | 8 | 辩论-集中度问答 |
> | `decision_reflection` | 9 | 决策跨期反思闭环 |
> | `signal_pre_digest` | 10 | 信号预消化 |
> | `module_quality_gate` | 11 | 模块级质量分级 |
> | `decision_header_parse` | 12 | 决策头结构化 |
> | `signal_ledger` | 13 | 确定性信号沉淀 |
> | `doctor_check` | 14 | 系统自检（TUI 菜单 `[D]` / Web 自检卡片可见性） |
>
> 除实验开关外，`features.json` 还统一管理匿名化总开关（`anonymizer`）、新闻分类（`news_cls`）、历史走势（`history_portfolio`/`history_benchmark`）、量化指标（`metrics_*`）、缓存清理（`cache_daily_cleanup`）、交互图表（`enable_interactive_charts`）等共 33 项开关。完整清单见[配置指引-功能开关 §M](how-to-config.md#m-功能开关featuresjson)。

#### [A] 配置持仓匿名化（代码/名称脱敏）

交互式设置持仓匿名化模式。支持 4 种模式：
- **关闭** — 显示真实名称和代码（默认）
- **代码显示** — 名称替换为"品种A/B/C…"，保留证券代码和盈亏数据
- **完全匿名** — 名称→"品种X"，代码→"000XXX"，盈亏→±XX%
- **汇总模式** — 仅显示大类汇总，不展示单品种明细

选择后立即保存到 `config.json` 的 `anonymization.mode`。匿名化仅在报告生成阶段生效，不修改原始持仓文件。

#### [R] 刷新配置

重新加载 `config.json`、`llm_settings.json`、`llm_key.json`，立即生效无需重启程序。

#### [I] 管理对比指数池

交互式维护竞争语境对比指数池。可添加/删除指数代码，用于报告中组合与基准的多维度对比（收益、夏普、波动率、最大回撤）。默认预设池为沪深300 + 中证500 + 中证全债，无需手动维护即可获得有意义的对比。

### 缓存管理类

#### [1] 更新基础类缓存

清除并重新获取：基金业绩、持仓明细、基准、行业分类、新闻、盈利预测、行业资金流向、分红/基金经理/持仓重合度/基金风格扩展数据。

**附带清除**：财经新闻热点与持仓关联分析（LLM 缓存）。

纯股票组合时自动跳过基金相关刷新（基金业绩/持仓/基准/基金经理），但仍主动重拉行业分类、分红、盈利预测、资金流向，并刷新财经新闻与基金风格扩展缓存。

#### [2] 更新行情类缓存（含价格/指数等）

清除并重新获取：价格行情、指数行情。

**附带清除** LLM 缓存：智囊团深度复盘、全球政经局势、持仓体检报告、穿透深度分析。

适合：切换到另一份持仓文件时，一键清理依赖旧持仓的缓存。

#### [3] 清理过期缓存文件

按 TTL 扫描删除已过期的缓存文件。不影响未过期的缓存。

#### [4] 查看缓存/状态统计

仅浏览，不执行删除操作。分三块展示：

**data/cache/**（API 响应缓存）：
- 文件总数 / 总大小
- 命中率统计
- 按前缀分类统计
- 最大文件 TOP3
- 过期文件数预览（可通过菜单 [3] 清理）

**data/history/snapshots/**（持仓快照）：
- 快照文件数 / 总大小
- 最新快照时间
- 超期自动删除，不随缓存清理

**data/state/**（运行时状态文件）：
- 状态文件数 / 总大小
- 跨会话持久化，不随缓存清理

### 诊断类

#### [V] 查看最近运行日志（可按级别筛选）

读取 `logs/app.log`，按时间戳切分记录并以 `time [LEVEL] message` 展示；多行正文（如 traceback）归并缩进展示。仅浏览，不修改任何数据。

- 按级别筛选：ERROR 红 / WARNING 黄着色（NO_COLOR 或非终端环境自动降级为无着色）
- traceback 折叠为「⤷ 堆栈详情 +N 行」，按需展开
- 默认读取末尾 200 行；不适合交互式手工翻看超大日志（大文件反向分块读取不卡顿）

#### [H] 查看数据源健康历史（近期检查记录）

聚合 `data/state/datasource_health.jsonl` 最近若干次运行的健康检查结果，展示 ok/total 与失败源清单。配合菜单 `V` 在数据源异常时快速定位。

#### [D] 系统自检（环境/配置/目录/数据源一键体检）· 实验功能

> **需先开启实验开关 `doctor_check`**（菜单 **[S]** → 实验功能区块勾选「系统自检」，或编辑 `features.json`）。开关关闭时本项不出现在主菜单中。

一键盘点运行环境，按 **环境 / 配置 / 目录 / 功能开关 / 数据源适配 / 数据源凭据 / 数据源** 七组输出检查结果：通过项标 `[OK]`、失败项标 `[!]` 并**附可执行修复建议**（如「改用 `.venv/bin/python`」「建目录或改 `config.json`」）。适合新机部署、报告跑不起来、怀疑配置损坏时先跑一遍。

- **纯只读诊断**：写探测用于判断目录可写性，哨兵文件**即刻删除**；不改任何配置或缓存
- **自身永不抛异常**：任一项出错都转成该组的一条失败结果行——配置损坏正是它要诊断的场景，此处崩掉等于在最需要它的时刻失效
- **零重依赖**：不依赖 pandas（其缺失正是它要报告的一类失败），故即使环境残缺也能跑起来
- 同一条链路在 CLI 侧为 `doctor` 子命令（**不受开关约束**，始终可用）、Web 侧为运行状态区「系统自检」卡片

## 持仓快照自动清理

B/L 菜单生成报告时自动保存持仓快照（环比对比用），并清理超过 60 天的旧快照（保留天数可通过 `config.json` 的 `history.snapshot_retention_days` 配置），避免 `data/history/snapshots/` 目录无限堆积。

## 生成报告建议顺序

1. **首次使用** — 确保持仓文件就绪后，直接按菜单 **L**（全量报告，含 LLM）
2. **日常更新** — 菜单 **`[1]`** 更新基础缓存 → 菜单 **B** 生成含新闻的报告
3. **需最新行情** — 菜单 **`[2]`** 更新持仓缓存 → 菜单 **L** 生成完整报告
4. **仅看概览** — 菜单 **E** 快速生成基础 Excel 报告
