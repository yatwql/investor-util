# Jev 接入设计草案 — 新闻关联判定通道

> 文档版本：0.11.2-dev
>
> 定位：在办设计草案（`docs-stm/plan/` 中间设计文件）。**先决条件是配套评测通过**（见 `jev-news-correlation-evaluation.md`）；未通过则本草案随完成态归档并标注未采纳。
>
> 落地顺序：评测 → 通道骨架 → 报告层接线 → 配置与文档 → 归档。

---

## 1. 范围与非目标

**范围**：把「财经新闻热点与持仓关联分析」模块的 `sentiment` 判定（及保真度用的 `relevance` 判定）从现网生成式二次分析迁到 Jev 的类型化判定接口。

**非目标**（明确排除，避免范围蔓延）：

- **不作为用户可切换的「模型」**。Jev 不生成文本；四条对外路由（厂商直连、两家聚合网关、一家边缘平台）均无对话补全兼容面，且 `models.json` 只接受对话语义的四种 API 类型。
- **不替换其他生成模块**（宏观、复盘、体检、穿透深析四个长文模块）。
- **不做「生成 + 判定」双供应商级联**。评测预检已证伪其动机：判定侧「无关」占比 0%，无可预筛项；且生成侧仍需吞下全量输入以产出理由文本，级联只增加一半管道而零信息增量。详见 §6。
- **不改动报告版式**（列数不变；理由列内容由模板生成，见 §5）。

## 2. 语义命名（先定名再设计）

| 语义名 | 类型 | 职责 |
|:-------|:-----|:-----|
| `jev_client` | 模块 | Jev 判定接口客户端（端点/认证/信封校验/重试预算） |
| `evaluate_typed` | 函数 | 单次判定：`state` + `questions` → `answers`（含用量） |
| `JEV_MODEL` | 常量 | 模型标识，默认 `jev-latest` |
| `JEV_BASE_URL` | 常量 | 端点基址（直连或网关） |
| `JEV_QUESTION_RELEVANCE` | 常量 | 「与持仓相关性」Choice 问项定义 |
| `JEV_QUESTION_SENTIMENT` | 常量 | 「对持仓方向影响」Choice 问项定义 |
| `JEV_QUESTION_SET_VERSION` | 常量 | 问项文案版本号，参与缓存指纹 |
| `render_news_rationale` | 函数 | 由判定 + 命中关键词 + 实体生成理由文本（确定性模板，不调模型） |
| `provider_news_correlation` | 配置键 | 通道选择键，取值域 `chat` / `typed`，默认 `chat` |
| `news_sentiment_threshold` | 配置键 | 置信度低于此值时判定回落为「中性」（默认不启用） |

命名纪律：不得用任务编号或系列代号命名任何标识符。实现落地时，上述语义名须同步登记进技术设计文档的「功能语义命名表」——该表与代码双向校验，**未实现前不得提前登记**。

## 3. 接口设计：独立类型化通道，不并入对话调用链

现网调用链是对话式形状（`llm/api.py` 与 `llm/api_base.py` 的调用入口接受 `system_prompt` + `user_prompt`，返回文本与用量），并挂载了扩展思考注入、截断检测、内容过滤安抚重试、对话式熔断与重试。

Jev 的形状不同：`state` + `questions` → `answers`，无消息数组、无采样温度、无思考档位、无流式。**把 Jev 塞进对话链会污染既有抽象**——每个环节都要加「是否类型化通道」分支。因此设计为**平行独立通道**：

```
llm/jev_client.py
  ├─ evaluate_typed(state, questions, *, timeout, retry_budget) -> TypedResult
  ├─ 认证解析顺序：显式凭据命令（仅显式配置时）→ 凭据文件/环境变量
  ├─ 信封校验：答案类型须与问项类型一致；Choice 概率和须≈1；confidence 须落在 [0,1]
  └─ 失败一律返回结构化错误对象，绝不向报告层抛裸异常
```

**复用面（不重造轮子）**：

- 缓存：复用统一缓存管理（按前缀匹配 TTL 的既有机制）
- 定价与费用：在核心常量模块的定价表新增 Jev 条目（见 §9）
- 会话用量：接入既有会话用量与成本跟踪
- 熔断：接入端点级熔断，但使用**与对话链分离的实例**——避免判定通道故障拖垮生成链

## 4. 判定映射

### 4.1 问项定义

```
sentiment（主判定，Choice）
  instructions: "这条新闻对下列持仓标的的整体影响方向是什么？"
  criteria:
    利好 — 指向利好（订单/提价/政策支持/基本面改善等）
    利空 — 指向利空（处罚/降价/需求下滑/基本面恶化等）
    中性 — 无明确方向，或不构成可判断的影响

relevance（保真度判定，Choice）
  instructions: "这条新闻与下列持仓标的的关联程度如何？"
  criteria:
    高 — 直接点名标的或其核心业务
    中 — 涉及所属行业或产业链，间接相关
    低 — 仅弱相关或泛行业提及
    无关 — 与标的及其行业均无实质关联
```

### 4.2 state 构造

`state` 复用现网已构造的两段文本（持仓摘要 + 新闻摘要），保持判定依据同源。这样「判定依据」在切换通道前后一致，避免把**输入差异**误记为**模型差异**。

### 4.3 批量策略

单请求承载多条新闻：每条新闻一组问项（形如 `news_<i>_sentiment` / `news_<i>_relevance`）。问项上限 128，默认取 30 条新闻 → 60 问项，留有余量。

**不做两段式**（先判定筛除、再送生成模型）：预检显示「无关」占比 0%，无筛除空间，两段式只会增加一次无谓往返。

### 4.4 结果映射

| 判定输出 | 现网字段 | 说明 |
|:---------|:---------|:-----|
| `answers.<id>_sentiment.choice` | `sentiment` | 直接映射（利好/利空/中性） |
| `answers.<id>_sentiment.confidence` | 新增（不上屏） | 仅用于降级判定与阈值 |
| `answers.<id>_relevance.choice` | `relevance` | 直接映射；「无关」仍按现网规则不写入该行 |
| — | `analysis` | 由模板生成，见 §5 |

## 5. 理由文本：确定性模板

预检显示现网理由中位 23 字、最大 33 字，内容形如「命中实体 + 影响方向」（例：「黄仁勋点出台湾半导体问题，涉及英伟达持仓」）。因此不必为它保留生成模型调用：

```
render_news_rationale(item, verdict) -> "{主体/命中方向} + {方向短语}"
  例：命中「半导体 / 国产替代」→「涉及半导体与国产替代方向，利好」
```

- 素材全部来自已存在字段：`matched_keywords`、标题中的主体词、`sentiment` 判定、行业标签
- **不引入新的模型调用**，与项目「确定性优先」的既有取向一致
- 可用性由评测阈值把关（抽检 ≥ 80% 认为「与现网原文信息量相当」）；不达标则退化为「只保留标签、隐藏理由列」

## 6. 两种候选形态对比与推荐

| | 级联（判定 + 生成并存） | **判定单独 + 模板理由（推荐）** |
|:--|:--|:--|
| 信息增量 | 零（三字段本可由单一通道给全） | 标签信息等价，理由由模板给 |
| 生成侧输入 | 仍需全量（为产出理由） | 不调用 |
| 失败面 | 3 条降级路径（含 2 种半成品态） | 2 条 |
| 缓存 | 两套或共用 + 半新鲜语义 | 一套替换 |
| 配置面 | 保留全部 8 键 | 5 键在类型化通道下不读取（见 §7） |
| 成本 | 现网成本 + 判定成本 | 仅判定成本 |

**推荐判定单独接入**，理由：级联唯一能提供而单通道给不了的是「信另一方的标签、但信本方的文笔」——这是个极窄的理由，且无数据支撑；同时它为零信息增量付出双倍管道与中间失败态。

## 7. 配置面

现网该模块有 8 个配置键，其中 **5 个在类型化通道下无意义**：

| 配置键 | 类型化通道下 |
|:-------|:-------------|
| `model_news_correlation` | 语义变为「判定模型标识」，保留但取值域改变 |
| `temperature_news_correlation` | 不读取（判定无采样温度概念） |
| `max_tokens_news_correlation` | 不读取（输出非生成文本） |
| `thinking_enabled_news_correlation` | 不读取 |
| `thinking_budget_news_correlation` | 不读取 |
| `reasoning_effort_news_correlation` | 不读取 |
| `timeout_news_correlation` | 保留（请求超时） |
| `cache_enabled_news_correlation` | 保留 |

处理原则——避免死键堆积，同时不破坏既有用户配置的向后兼容：

1. 新增 `provider_news_correlation` 作为通道选择键，取值域 `chat` / `typed`，**默认 `chat`**——缺省行为逐字节不变。
2. 5 个无意义键在 `typed` 通道下**不读取**，并在配置模板注释中标明「仅 chat 通道生效」；**不删除**（删除会破坏已有配置文件）。
3. 新增键须按开关注册表的统一纪律登记（单条声明字段齐备、分组属性、默认值由注册表派生），并同步 Web 配置编辑白名单与三渠道入口。

## 8. 缓存与指纹

- 缓存前缀：`llm_news_sentiment_`——与现网 `llm_news_item_` 区分，避免两通道在同一前缀下互相污染
- 指纹构成：`fingerprint({"title": title[:80], "holdings_fp": context_fp, "question_set": JEV_QUESTION_SET_VERSION})`
  - 新增 `question_set` 维度是**必需**的：问项文案（criteria 措辞）变化会改变判定口径，若不换键就会命中旧口径的缓存
- 缓存体只存 `{"sentiment", "relevance", "confidence"}`，**不含理由文本**——理由由模板随时重算，入缓存只会固化过时措辞

## 9. 定价与用量

- 在核心常量模块的定价表新增 Jev 条目：输入按公开单价折算为人民币，**输出单价记 0**（避免用「输出单价 × 0 token」制造伪精度）
- 该条目**不参与峰谷定价**（无高峰价子段）
- 用量上报接入既有会话用量与成本跟踪；理由由模板生成，不产生 token

## 10. 失败与降级

现网行为：该模块任一步失败 → 整体降级为关键词匹配（报告层异常分支）。类型化通道下**保持同一条降级路径**，不新增中间态：

| 情形 | 行为 |
|:-----|:-----|
| 认证失败 / 限流 / 过载 | 按预算指数退避重试；耗尽后降级为关键词匹配 |
| 信封校验失败（该项缺失或概率非法） | 该项视为未判定；全部失败则整体降级 |
| 部分问项缺失 | 缺失项按现网口径回落为「低 / 中性 / 空理由」，其余正常 |
| 置信度低于阈值（启用时） | 该项判定回落为「中性」，并计数日志 |

**红线**：不得让判定结果升级为「阻止报告生成」的硬闸门——该模块出厂默认关闭，现网定位是增强而非门禁。

## 11. 测试策略

| 层 | 用例 |
|:---|:-----|
| 单元 | `evaluate_typed` 信封校验：类型不符 / 概率和不为 1 / 置信度越界 / 问项缺失 |
| 单元 | `render_news_rationale`：空关键词 / 超长主体 / 多主体叠加 |
| 单元 | 问项版本常量：criteria 文案变更须导致指纹换键 |
| 单元 | 降级矩阵：认证失败 / 信封失败 / 部分缺失 / 低置信度四条路径 |
| 单元 | 配置面：`typed` 通道下 5 个无意义键不读取；默认 `chat` 时输出逐字节不变 |
| 场景 | `typed` 通道下页签结构与现网一致（列数、着色规则、占位文案） |

约束：所有涉及网络与模型的用例必须 mock，禁止真实调用；判定相关测试不得与普通测试混搭在同一文件，需按项目对边缘场景文件的隔离要求放置。

## 12. 分阶段落地

1. **评测**（先决）——按配套评测方案跑三方对照，产出采纳/不采纳结论
2. **通道骨架**——`jev_client` + 信封校验 + 定价条目 + 缓存（不接报告层）
3. **接线**——通道选择键 + 模板渲染 + 降级矩阵
4. **配置与文档**——开关注册表登记、Web 白名单、配置模板与用户手册说明
5. **归档**——完成后随完成态移入对应版本归档目录；未采纳则标注为已评估未采纳
