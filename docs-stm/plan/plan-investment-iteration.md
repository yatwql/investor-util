## 1. 迭代总览

**总目标**：21 章总数减至 19（合并「持仓重合度矩阵」+「持仓相关性矩阵」为「持仓关系矩阵」、合并「组合历史走势」+「历史回撤分析」为「组合历史走势与回撤」、合并「基金风格分析」+「因子暴露分析」为「风格与因子分析」-3、新增「行动建议」独立章 +1），功能从「事后体检」扩展至「买入比较 + 决策行动 + 数据可信」，用户感知章节更精简、单章更充实、决策更直接。

**阶段地图（21 轮 / 8 阶段）**：

| 阶段 | 轮次 | 主题 | 承载章节 | 状态 |
|:--|:--:|:--|:--|:--:|
| **A 数据质量地基** | 1~3 | 数据质量仪表盘 | 改造 18 章 | ✅ 已完成 |
| **B 决策中枢** | 4~7 | 调仓建议/交易纪律/收益归因 行动板块 | 新增 20 行动建议（always）+ 14 章摘要引用 | ✅ 已完成 |

**迭代原则**：
1. **每轮独立可交付**：每轮结束产物可运行、可测试、可回滚；
2. **每轮有量化验收标准**：测试数 / 覆盖率 / 计算精度 / 行为断言 / 向后兼容，达标才进下一轮；
3. **默认关**：所有新子模块 config 开关（`report_submodules.*`）默认关闭；「行动建议」顶层章节开关 `enable_action` 默认关——不开时报告为合并后 18 章基线，开启才出现第 19 章；
4. **不破坏既有**：旧持仓文件格式、旧 config、既有章节输出**向后兼容**（回归测试保证）。

## 2. 通用验收标准（每轮强制，不逐轮重复列出）

以下标准**每轮必过**，轮 1~21 的"量化验收"是对此的**叠加**：

- **[门禁-P0]** `python scripts/test_runner.py --mode dev-verify` 全部通过（核心单元 + 基础场景）；`python scripts/check-code-traces.py --ci`、`python scripts/check-doc-traces.py --ci`、`python scripts/check-task-numbering.py --ci` 三脚本通过。
- **[测试规范]** 新增/修改测试用例**必须标注对应 pytest marker**（`unit_*` 子标记，新 marker 注册到 `conftest.py` 并同步维护文档）；LLM 相关测试一律 mock（禁真实调用）。
- **[隔离]** 遵守 `_isolate_sensitive_paths` / 单例重置 / output_dir 重定向 / 持久化文件路径隔离；新持久化文件须加入 fixture。
- **[覆盖率]** 涉及模块整体覆盖率 ≥80%；**新增/改造模块 ≥85%**。
- **[向后兼容]** 旧持仓文件（无流水页签）、旧 config 解析与改造前**完全一致**（回归断言）；既有章节输出不因新子模块开关默认关而改变；`enable_action` 默认关时报告为合并后 18 章基线（无行动建议章）。
- **[回填]** 每轮完成：`docs-stm/managements/changelog.md` 记一轮；自审问题入 `review-findings.md`（修复后即归档）。
- **[架构]** 每轮对照 features.md §4.4 架构合规自查表逐条自检 C1~C20（尤其 C3 原子写、C8 日志统一、C11/C12/C13/C14 测试规范、C16 路径绝对化、C18 凭据隔离）；物理合并轮必须同步 C19 契约增删（附录 H）；新增图表必须 C20 图下说明；管线共享层 `report/orchestrator.py` 不因 Web 无关改动而破坏。
