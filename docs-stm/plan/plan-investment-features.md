# 投资分析功能优化 — 设计（需求 × 数据源可行性 × 章节归并）

> 关联：`plan.md` P3 待办 · 实施计划 [`plan-investment-iteration.md`](./plan-investment-iteration.md)（20 轮，每轮量化验收）
>
> **定位**：本文档是 plan 的功能优化设计——从投资决策闭环与数据源约束出发，定义全部优化功能。**章节结构**：合并「持仓重合度矩阵」+「持仓相关性矩阵」为「持仓关系矩阵」、合并「组合历史走势」+「历史回撤分析」为「组合历史走势与回撤」、合并「基金风格分析」+「因子暴露分析」为「风格与因子分析」（共 -3），新增「行动建议」独立章（+1），**总数 21 章减至 19 章**；其余功能作为现有章节的子模块/子块/子列融入。数据源是硬约束：本工具免费使用，凡依赖付费源（Wind/Choice/iFinD/理杏仁/乌龟量化等）或极不稳定源的功能，要么给免费替代方案，要么明确不做。
>
> **命名规范**：本文档只用**语义名**（英文 slug = 代码/配置名，中文名 = 文档/UI 描述），不用任务代号。功能语义命名表见 §2。

## 1. 设计框架：从投资决策闭环出发

个人投资的完整决策链：

```
买入（买什么/买多少/何时买）→ 持有监控（结构/风险/纪律）
→ 卖出与调仓（止盈/止损/再平衡）→ 复盘（收益归因/教训）
```

**现状审视**：报告对「持有监控」与「复盘」覆盖扎实——穿透 TOP10、相关性矩阵、集中度、因子暴露、回撤分析、组合演进、LLM 智囊团复盘、what-if 模拟，共 21 个页签/章节。对照决策链，薄弱环节：

1. **「事前/事中决策支持」弱**：报告偏"事后体检"——告诉"超限了/集中了/回撤了"，很少告诉"**具体该卖哪只、卖多少、先卖哪个、调仓后组合变成什么样**"。
2. **「买入/选择」环节零覆盖**：换仓/补仓/新建仓时需比较候选标的，报告帮不上忙。
3. **「交易摩擦」缺位**：收益/回测计算不含交易成本与税费，高估调仓价值。

优化功能围绕这些缺口设计，同时逐一受数据源免费/稳定双约束检验。

### 2.1 买入与选基

**候选基金比较**（→ 5 章「候选比较」子模式，开关默认关）
- **痛点**：选基金时需横向比较——同类里谁规模合适、费率低、排名稳、回撤小、风格不重复。
- **边界**：仅比较**池内显式候选**（持仓基金 + 用户补充代码 ≤10 只），不做全市场筛选。
- **数据源**：天天基金单代码接口（排名/持仓，免费稳定）。
- **输出**：规模 / 综合费率 / 同类排名百分位 / 近 1·3·6 月·1 年收益 / 最大回撤 / 风格标签 / 与现有持仓重合度。

**估值分位**（→ 4 章「估值分位」列）
- **痛点**：散户高频问题"现在买贵不贵"。历史估值分位依赖付费源，用免费数据近似。
- **方案**：当前 PE/PB（东财 push2 扩展字段，免费稳定）+ 3~5 年**价格分位代理**（历史 K 线本地计算）。价格分位 ≠ 估值分位（盈利增长未纳入），作为"贵不贵"近似信号，**显式标注"价格分位代理，非真实历史估值分位"**。
- **输出**：低估/合理/高估三档刻度。

**市场温度**（→ 1 章「市场温度」刻度行）
- **痛点**：主观问题"现在是机会还是风险"。市场温度 = 价格分位 + 均线偏离 + 波动率合成。
- **数据源**：指数历史 K 线（腾讯/新浪，免费稳定）；估值分位受限同估值分位功能。
- **形态**：以「温度计」呈现（低估/合理/高估三档），**不做仓位硬建议**（"建议几成仓"合规与误导风险高，且 LLM 内容已有类似解读）。

### 2.2 决策与调仓

**调仓建议（含可行化层）**（→ 20 章「行动建议」）
- **痛点**：报告给出"单品种超限"后，用户仍要自己回答：卖哪只？卖多少？先卖哪个？卖完结构如何？——调仓执行的核心三问。
- **可行化层**：每条建议输出代码/名称/操作/**份额（A 股取整一手 100 股）**/金额/**预估费用**/**调仓后现金余额**（防现金负值）。把"建议"变成"能照做的方案"。
- **数据源**：持仓（本地）+ 实时价（腾讯/新浪）+ 静态费率表。**零新增外部依赖，免费稳定**。

**交易纪律**（并入调仓建议，20 章）
- **痛点**：散户两大心理弱点——套牢死扛、上涨拿不住。把纪律程序化：按成本价止盈/止损线、组合回撤纪律、估值安全边际。
- **与既有再平衡互补**：再平衡是"结构超限"（仓位百分比），纪律是"价格触发"（涨跌）。同构扩展既有「再平衡信号」子块（同"触发/未触发 + 距触发幅度"）。
- **数据源**：成本价（本地）+ 实时价（腾讯/新浪）+ 组合高点（历史 K 线）。**纯本地规则引擎，零新增外部依赖**。

**收益归因（品种收益贡献占比）**（→ 20 章「行动建议」）
- **痛点**："组合收益从哪来、亏在哪只？"——哪几只品种贡献了主要盈利/亏损。
- **数据源**：各品种盈亏（本地市值核算，现有）。**纯本地，零新增外部依赖**。
- **形态**：TOP 5 品种按贡献占比（pp，非收益率）排序，正负分列（盈利来源/亏损来源）+ 正负合计摘要——**复用既有实现**（`prompts_core._build_profit_attribution_block`，注入 LLM 提示词），呈现为行动建议章内的可读清单。

### 2.3 成本与现金流

**资金流水 + 资金加权收益 + 成本分档**（→ 1/2/3 章，含分红现金流）
- **痛点**：持仓 Excel 只有聚合成本，丢失分笔成交信息，导致——算不出资金加权收益（XIRR，定投收益被系统性扭曲）；无法判断"是否在追高加仓"；无法做成本分档止盈。
- **输入扩展**：持仓 Excel 新增**可选**「交易流水」「分红流水」页签（**不破坏既有 4 列**，无流水回退聚合成本，向后兼容）。
- **输出**：资金加权收益率（XIRR，纳入分红现金流时点效应）+ 成本分档（低成本/高成本档，支持分档止盈）+ 分红累计。

**分红现金流**（并入资金流水）
- **痛点**：组合一年给我多少现金流（分红/利息）。
- **方案**：**本地分红流水记录**（同资金流水思路），计算累计分红/股息率/再投资效果，纳入 XIRR 时点。**全部本地输入，零外部依赖**。

### 2.4 风险与暴露

**行业 Beta 暴露矩阵**（→ 9 章「行业 Beta」子表）
- **痛点**：现有穿透给 TOP10 与行业分类，但未量化"组合实际受哪些行业指数驱动"。
- **数据源**：穿透行业分类（push2）+ 行业指数历史 K 线（腾讯/新浪）；OLS 复用 9 章风格与因子的回归机制。
- **输出**：行业暴露占比（穿透后加权）+ 各行业指数 Beta/相关性，回答"组合下注在哪些宏观主题上"。

**危机区间标注**（→ 15 章增强）
- **痛点**：假设性情景（Beta CI 传播 ±10%~±30%）缺真实历史锚——"我的持仓在 2015 股灾/2018 贸易战/2020 疫情/2022 熊市实际会怎样"。
- **数据源**：危机区间表现 = 既有历史 K 线切片（腾讯/新浪）+ 静态危机日期表；as-if 净值复用 `portfolio_history.py`。**零新数据源**。
- **形态**：净值曲线危机区间分段着色 + 区间统计（区间回撤/恢复天数）；无历史区间显式"无历史数据"，不强拉长 lookback。

**尾部风险**（→ 15 章增强）
- **输出**：VaR(95/99)、最大单日跌幅、连续下跌天数、下跌后恢复时间。
- **数据源**：历史日收益序列（腾讯/新浪，免费稳定），纯本地计算。

### 2.5 监控与质量

**快照差异**（→ 16 章增强）
- **痛点**：报告是"时点快照"，投资是"持续过程"；定时报告只出最终报告，变化点靠肉眼比对。
- **数据源**：本地多快照（`data/history/snapshots/`，全部现有）。
- **输出**：16 章顶部「自上次快照变化摘要」——集中度/相关性/超限项/新增移除品种。

**数据质量仪表盘**（→ 改造 18 章，含品种覆盖诊断）
- **痛点**：报告里哪些数字可信、哪些是降级/过期/估算？现状降级是"静默占位 + 数据源可用性矩阵"，**逐数据项可信度标记不足**。
- **数据源**：缓存/降级元数据（`data_status.py`、`datasource_health.jsonl`）——**基础设施已有，缺"面向用户的可信度表达"**。
- **输出**：全局数据新鲜度摘要（几个缓存/降级/过期）+ 净值/价格单日 ±20% 异常跳变检测（防把脏数据当真）+ 报告头部"N 个品种数据异常"摘要。

**品种覆盖诊断**（并入数据质量仪表盘，18 章）
- **痛点**：已退市/停牌品种、代码格式错误、名称不匹配被 `read_holdings` 静默容错，报告不提示"这个品种为什么没数据"。
- **输出**：逐品种标注"有行情 / 净值缺失 / 可能退市 / 代码格式可疑"，让"数据缺失"从静默变成显式。

## 4. 章节归并方案（核心）

### 4.1 原则

1. **章节总数减至 19**：合并「持仓重合度矩阵」+「持仓相关性矩阵」为「持仓关系矩阵」、合并「组合历史走势」+「历史回撤分析」为「组合历史走势与回撤」、合并「基金风格分析」+「因子暴露分析」为「风格与因子分析」（共 -3），新增「行动建议」独立章（+1），**总数 21 章减至 19 章**——合并多于新增，报告更精简；
2. **能作为既有章节增强的，不新立功能**；能并入既有功能的，不新开（交易纪律并入调仓建议，品种覆盖诊断并入数据质量，分红现金流并入资金流水）；**行动建议因决策语义独立，单独成章**；
3. 子模块可见性由 **config 开关**控制（`report_submodules.*`，**默认关闭**）；「行动建议」为顶层章节开关 `enable_action`（**默认关**），避免 19 章内容突然"变胖"；
4. 信息密度策略：**已有章节标题不变，章节内按需增减子块**；仅合并章（持仓关系矩阵、组合历史走势与回撤、风格与因子分析）与新章（行动建议）是标题级变化——用户感知是"章节更精炼、单章更充实"。

| 15 组合历史走势与回撤 | **合并原「组合历史走势」+「历史回撤分析」**（章节 sheet key 统一为 `portfolio_history_drawdown`）+ 危机区间标注、尾部风险 | 走势表 + 回撤矩阵区块 + 标注层 + 指标列 | `report_submodules.tail_risk` |
| 16 组合演进 | 快照差异 | 顶部加差异摘要 | 随 `enable_portfolio_evolution` |
| 20 行动建议 | **再平衡信号、交易纪律、调仓建议、收益归因（决策行动）** | **新增独立顶层章节**（`always` 类型，`enable_action` 默认关） | `enable_action` |
| 18 数据源可用性矩阵 | 数据质量 + 品种覆盖诊断 | 改造为「源健康 + 品种覆盖 + 可信度」三区块 | `report_submodules.data_quality` |

> 未列章节（6/8/10/11/13/14/19）不改造，保持现状（序号已按合并后重排）。19 章为「LLM API 用量」（`llm_usage`），功能不变，仅序号顺延为末章。
>
> **章节合并（-3）**：①「持仓重合度矩阵」与「持仓相关性矩阵」同属"持仓关系"维度，两矩阵并一章分上下区块，开关沿用 `enable_fund_deep_analysis`；②「组合历史走势」与「历史回撤分析」**数据同源**（共享同一 `history_data`：净值 bars + 基准对比 + 回撤事件），回撤是净值走势的衍生指标，并一章分「走势表 + 回撤矩阵」两个区块，且两章指标区（累计收益/最大回撤/波动率/起止日）重复，合并同时消除冗余；③「基金风格分析」与「因子暴露分析」**语义同源**——因子暴露分析按 value/growth/quality 三风格因子对基准做回归，列头即"风格因子"，与基金风格分析是一体两面，并一章分「基金风格表 + 风格因子回归」两个区块。合并后章节序号整体重排为 19 章。
>
> **行动建议独立成章（+1，关键）**：调仓建议、交易纪律、收益归因是**纯算法功能**，与 LLM 无关，且是**决策闭环的核心产出**（"具体该卖哪只、卖多少、先卖哪个"）。若作为某现有章的子块，会稀释其决策地位；若归入 14 章智囊团复盘（`llm` 类型，仅 `full` 报告），`basic`/`both` 报告将完全看不到这些纯算法能力。**因此新增 `always` 类型的独立顶层章节「行动建议」（第 20 章）**，展示再平衡信号 + 交易纪律触发 + 调仓建议清单 + 收益归因，全报告类型可见；14 章（LLM 场景）以「行动摘要」子块引用 20 章结果，避免重复计算（单源计算，两处呈现）。开关 `enable_action`（**默认关**），不开时报告维持无此章。
>
> **14 章重组**：分「复盘」板块（现状 LLM 圆桌 + 情景 + 口径 + 量化指标 + 竞争语境，不变）与「行动摘要」子块（引用 20 章行动建议结果，不重复计算）——14 章仍是决策解读中枢，20 章是行动明细宿主。

### 4.3 章节合并落地

- **物理合并 3 处**：①「持仓重合度矩阵」+「持仓相关性矩阵」→ **「持仓关系矩阵」**——同属"持仓关系"维度，两矩阵分区块合并；②「组合历史走势」+「历史回撤分析」→ **「组合历史走势与回撤」**——数据同源（同一 `history_data`）、回撤为净值衍生指标，合并消除指标区重复；③「基金风格分析」+「因子暴露分析」→ **「风格与因子分析」**——因子暴露列头即"风格因子"，与风格分析语义同源，并章分「基金风格表 + 风格因子回归」两区块。合计 -3，加上行动建议新增 +1，**总数 21 章减至 19 章**。
- **暂不合并**：LLM 文本章（12/13/14 智囊团/体检/穿透）——改造成本高、收益有限，不做物理合并，仅以 HTML 分组导航缓解入口繁杂。
- **轻合并**：HTML 报告按「基础/基金深度/风险/历史/LLM」**分组导航折叠**；Excel 沿用 `report_section_order` 自定义排序 + `enable_*` 开关（用户可自行把不常用章节后置/关闭）。

## 5. 实施次序

按「价值/风险比」与「地基优先」排序（实施细节与每轮量化验收见 [`plan-investment-iteration.md`](./plan-investment-iteration.md)）：

1. **改造 18 章 → 数据质量仪表盘**（数据质量 + 品种覆盖诊断，分两步：源健康+品种覆盖 → 可信度+异常跳变）——地基，先行；
2. **新增 20 章 → 行动建议**（再平衡信号 + 交易纪律 + 调仓建议 + 收益归因，纯算法、`always` 类型、basic/both/full 可见，`enable_action` 默认关）——决策价值最高；
3. **14 章 → 行动摘要**（LLM 场景引用 20 章结果，单源计算两处呈现）；
4. **15 章 → 历史增强**（合并组合历史走势 + 历史回撤为「组合历史走势与回撤」，加危机区间标注 + 尾部风险）；
5. **合并 7 章 → 持仓关系矩阵**（持仓重合度 + 相关性并入一章）+ **合并 9 章 → 风格与因子分析**（基金风格 + 因子暴露并入一章，分「风格表 + 因子回归」两区块）+ **9 章 → 行业 Beta**（行业 Beta 暴露子表）+ **5 章 → 候选比较**（候选基金比较，默认关）；
6. **3/1/2 章 → 成本流水**（资金流水 + 分红现金流，随持仓文件格式扩展排期，向后兼容）；
7. **4 章 → 估值分位**（估值分位）+ **1 章 → 市场温度**（市场温度，简化版 + 免责，放最后）。

**效果**：21 章总数减至 19 章（合并持仓关系矩阵 + 组合历史走势与回撤 + 风格与因子分析 -3、新增行动建议章 +1），功能从「事后体检」扩展至「买入比较 + 决策行动 + 数据可信」全覆盖，用户感知章节更精简、单章更充实、决策更直接。
