# 投资分析功能优化 — 设计（需求 × 数据源可行性 × 章节归并）

> 关联：`plan.md` P3 待办 · 实施计划 [`plan-investment-iteration.md`](./plan-investment-iteration.md)（20 轮，每轮量化验收）
>
> **定位**：本文档是 plan 的功能优化设计——从投资决策闭环与数据源约束出发，定义 F1~F15 功能，并全部归并为**现有 21 个章节的子模块**（章节总数锁死）。数据源是硬约束：本工具免费使用，凡依赖付费源（Wind/Choice/iFinD/理杏仁/乌龟量化等）或极不稳定源的功能，要么给免费替代方案，要么明确不做。

---

## 1. 设计框架：从投资决策闭环出发

个人投资的完整决策链：

```
买入（买什么/买多少/何时买）→ 持有监控（结构/风险/纪律）
→ 卖出与调仓（止盈/止损/再平衡）→ 复盘（收益归因/教训）
```

**现状审视**：报告对「持有监控」与「复盘」覆盖扎实——穿透 TOP10、相关性矩阵、集中度、因子暴露、回撤分析、组合演进、LLM 智囊团复盘、what-if 模拟，共 21 个页签/章节。对照决策链，薄弱环节：

1. **「事前/事中决策支持」弱**：报告偏"事后体检"——告诉"超限了/集中了/回撤了"，很少告诉"**具体该卖哪只、卖多少、先卖哪个、调仓后组合变成什么样**"。
2. **「买入/选择」环节零覆盖**：换仓/补仓/新建仓时需比较候选标的，报告帮不上忙。
3. **「交易摩擦」缺位**：收益/回测计算不含交易成本与税费，高估调仓价值。

F1~F15 功能围绕这些缺口设计，同时逐一受数据源免费/稳定双约束检验。

## 2. 功能设计（F1~F15）

### 2.1 买入与选基

**F10 候选基金比较器**（→ 5 章「候选比较」子模式，开关默认关）
- **痛点**：选基金时需横向比较——同类里谁规模合适、费率低、排名稳、回撤小、风格不重复。
- **边界**：仅比较**池内显式候选**（持仓基金 + 用户补充代码 ≤10 只），不做全市场筛选（天天基金全市场列表接口脆弱且属唯一链路，风险高）。
- **数据源**：天天基金单代码接口（排名/持仓，免费稳定）。
- **输出**：规模 / 综合费率 / 同类排名百分位 / 近 1·3·6 月·1 年收益 / 最大回撤 / 风格标签 / 与现有持仓重合度。

**F3 简化估值分位**（→ 4 章「估值分位」列）
- **痛点**：散户高频问题"现在买贵不贵"。真实历史估值分位依赖付费源（理杏仁/乌龟量化）。
- **免费替代**：当前 PE/PB（东财 push2 扩展字段，免费稳定）+ 3~5 年**价格分位代理**（历史 K 线本地计算）。价格分位 ≠ 估值分位（盈利增长未纳入），作为"贵不贵"近似信号，**显式标注"价格分位代理，非真实历史估值分位"**。
- **输出**：低估/合理/高估三档刻度。

**F7 市场温度刻度**（→ 1 章「市场温度」刻度行）
- **痛点**：主观问题"现在是机会还是风险"。市场温度 = 价格分位 + 均线偏离 + 波动率合成。
- **数据源**：指数历史 K 线（腾讯/新浪，免费稳定）；估值分位受限同 F3。
- **形态**：以「温度计」呈现（低估/合理/高估三档），**不做仓位硬建议**（"建议几成仓"合规与误导风险高，且 LLM 内容已有类似解读）。

### 2.2 决策与调仓

**F1 调仓建议书（含可行化层）**（→ 14 章「行动板块」）
- **痛点**：报告给出"单品种超限"后，用户仍要自己回答：卖哪只？卖多少？先卖哪个？卖完结构如何？——调仓执行的核心三问。
- **可行化层**：每条建议输出代码/名称/操作/**份额（A 股取整一手 100 股）**/金额/**预估费用**/**调仓后现金余额**（防现金负值）。把"建议"变成"能照做的方案"。
- **数据源**：持仓（本地）+ 实时价（腾讯/新浪）+ 静态费率表。**零新增外部依赖，免费稳定**。

**F4 纪律引擎**（并入 F1 行动引擎，14 章）
- **痛点**：散户两大心理弱点——套牢死扛、上涨拿不住。把纪律程序化：按成本价止盈/止损线、组合回撤纪律、估值安全边际。
- **与既有再平衡互补**：再平衡是"结构超限"（仓位百分比），纪律是"价格触发"（涨跌）。同构扩展既有「再平衡信号」子块（同"触发/未触发 + 距触发幅度"）。
- **数据源**：成本价（本地）+ 实时价（腾讯/新浪）+ 组合高点（历史 K 线）。**纯本地规则引擎，零新增外部依赖**。

**F6 收益归因（Brinson 简化版）**（→ 14 章「行动板块」）
- **痛点**："组合为什么跑赢/跑输基准？"——大类配置贡献 vs 品种选择贡献。没有归因就无从改进配置/选基。
- **数据源**：基准指数（既有 `comparison_indices`）+ 品种分类（`category.py`）+ 组合 as-if 净值（`portfolio_history.py`）。**全部现有，免费稳定**。
- **实现**：Brinson 二因子（配置贡献 + 选择贡献），不做交叉项防过度复杂。

**F5 what-if 交易成本模拟**（→ what-if 独立报告）
- **痛点**：what-if 回测不含交易成本，高估调仓收益；小资金高频调仓可能被摩擦成本完全吞噬。
- **数据源**：佣金/印花税/赎回费为**本地静态费率表**（税率政策低频变化，手动维护 + 文档注明）。
- **输出**：净调仓收益（调仓收益 − 摩擦成本）+ 摩擦成本吞噬比例 + "手续费过高不建议调仓"提示阈值。

### 2.3 成本与现金流

**F2 资金流水 + XIRR + 成本分档**（→ 1/2/3 章，含 F13）
- **痛点**：持仓 Excel 只有聚合成本，丢失分笔成交信息，导致——算不出资金加权收益（XIRR，定投收益被系统性扭曲）；无法判断"是否在追高加仓"；无法做成本分档止盈。
- **输入扩展**：持仓 Excel 新增**可选**「交易流水」「分红流水」页签（**不破坏既有 4 列**，无流水回退聚合成本，向后兼容）。
- **输出**：资金加权收益率（XIRR，纳入分红现金流时点效应）+ 成本分档（低成本/高成本档，支持分档止盈）+ 分红累计。

**F13 分红现金流跟踪**（并入 F2）
- **痛点**：组合一年给我多少现金流（分红/利息）。外部红利接口不稳定（akshare `stock_history_dividend` ❌）。
- **方案**：改为**本地分红流水记录**（同 F2 流水思路），计算累计分红/股息率/再投资效果，纳入 XIRR 时点。**全部本地输入，零外部依赖**。

### 2.4 风险与暴露

**F15 行业 Beta 暴露矩阵**（→ 10 章「行业 Beta」子表）
- **痛点**：现有穿透给 TOP10 与行业分类，但未量化"组合实际受哪些行业指数驱动"。
- **数据源**：穿透行业分类（push2）+ 行业指数历史 K 线（腾讯/新浪）；OLS 复用 10 章因子暴露回归机制。
- **输出**：行业暴露占比（穿透后加权）+ 各行业指数 Beta/相关性，回答"组合下注在哪些宏观主题上"。

**F11 历史危机区间标注**（→ 18 章增强）
- **痛点**：假设性情景（Beta CI 传播 ±10%~±30%）缺真实历史锚——"我的持仓在 2015 股灾/2018 贸易战/2020 疫情/2022 熊市实际会怎样"。
- **数据源**：危机区间表现 = 既有历史 K 线切片（腾讯/新浪）+ 静态危机日期表；as-if 净值复用 `portfolio_history.py`。**零新数据源**。
- **形态**：净值曲线危机区间分段着色 + 区间统计（区间回撤/恢复天数）；无历史区间显式"无历史数据"，不强拉长 lookback。

**F14 尾部风险统计**（→ 18 章增强）
- **输出**：VaR(95/99)、最大单日跌幅、连续下跌天数、下跌后恢复时间。
- **数据源**：历史日收益序列（腾讯/新浪，免费稳定），纯本地计算。

### 2.5 监控与质量

**F8 快照差异告警**（→ 19 章增强）
- **痛点**：报告是"时点快照"，投资是"持续过程"；定时报告只出最终报告，变化点靠肉眼比对。
- **数据源**：本地多快照（`data/history/snapshots/`，全部现有）。
- **输出**：19 章顶部「自上次快照变化摘要」——集中度/相关性/超限项/新增移除品种。

**F9 数据质量仪表盘**（→ 改造 20 章，含 F12）
- **痛点**：报告里哪些数字可信、哪些是降级/过期/估算？现状降级是"静默占位 + 数据源可用性矩阵"，**逐数据项可信度标记不足**。
- **数据源**：缓存/降级元数据（`data_status.py`、`datasource_health.jsonl`）——**基础设施已有，缺"面向用户的可信度表达"**。
- **输出**：全局数据新鲜度摘要（几个缓存/降级/过期）+ 净值/价格单日 ±20% 异常跳变检测（防把脏数据当真）+ 报告头部"N 个品种数据异常"摘要。

**F12 品种级覆盖诊断**（并入 F9，20 章）
- **痛点**：已退市/停牌品种、代码格式错误、名称不匹配被 `read_holdings` 静默容错，报告不提示"这个品种为什么没数据"。
- **输出**：逐品种标注"有行情 / 净值缺失 / 可能退市 / 代码格式可疑"，让"数据缺失"从静默变成显式。

## 3. 数据源可行性总评

| 数据 | 免费 | 稳定 | 评价 |
|:--|:--:|:--:|:--|
| 腾讯/新浪 行情 + 历史 K 线 | ✅ | ✅ | 核心行情源，主备齐全；K 线有 365 天/美股指数小限制 |
| 东财/天天 基金净值/排名/持仓 | ✅ | ✅ | 最稳净值源；排名/持仓为唯一链路（HTML 解析易受改版影响） |
| 东财 push2 行业 + PE/PB/市值扩展字段 | ✅ | ✅ | 估值当前值可用；概念板块字段可能为空 |
| 5 源新闻聚合 | ✅ | ⚠️ | 财联社需签名鉴权默认关；源级降级已兜底 |
| akshare（盈利预测/资金流向/分红/利率） | ✅ | ❌ | 接口签名/格式变更频繁，静默降级为空；**不可作为核心功能依赖** |
| 中证官网指数估值 | ✅ | ⚠️ | 网页结构易变，解析脆弱；仅作可选项 |
| 理杏仁/乌龟量化/韭圈儿 | ❌ 付费 | — | **不可用**，真实估值分位放弃 |
| Wind/Choice/iFinD | ❌ 付费 | — | **不可用**，财务基本面深度放弃 |

**核心结论**：本工具能免费稳定拿到的数据是——行情/K 线、基金数据、行业分类、新闻。**F1/F2/F4/F5/F6/F8/F9/F10/F12/F13/F14/F15 全部落在免费稳定集合内可放心做；F3/F7 用价格分位代理估值分位（显式标注局限）；凡要"历史估值分位、财务基本面"的功能必须用免费代理或放弃。**

**明确不做（数据源硬约束）**：
- **真实历史估值分位**（PE/PB 全历史百分位）——依赖理杏仁/乌龟量化等付费源；
- **全市场基金筛选**——天天基金全市场列表接口脆弱 + 属唯一链路，收益与风险不匹配；
- **个股财务基本面深度**（ROE/营收增速/现金流/负债）——免费源（akshare 财务接口）不稳定，东财 F10 网页解析重且易碎；
- **板块轮动/资金流向高频信号**——akshare `sector_fund_flow` 不稳定，此类信号本身可靠性存疑（作为 LLM 素材已够，不作为量化功能）。

## 4. 章节归并方案（核心）

### 4.1 原则

1. **21 章总数锁死**，F1~F15 全部作为**现有章节的子模块/子块/子列**融入，不新增顶层章节；
2. **能作为既有章节增强的，不新立功能**；能并入既有功能的，不新开（F4 并入 F1，F12/F13 并入 F9/F2）；
3. 子模块可见性由 **config 开关**控制（`report_submodules.*`，**默认关闭**），避免 21 章内容突然"变胖"；
4. 信息密度策略：**章节标题不变，章节内按需增减子块**——用户感知是"章节更丰富"而非"又多了章"。

### 4.2 章节归并对照表

| 章节 | 归入功能 | 改造方式 | config 开关 |
|:--|:--|:--|:--|
| 1 投资分析汇总 | F7 市场温度、F2 XIRR 汇总 | 加温度刻度行 + XIRR 行 | `report_submodules.market_temperature` |
| 2 市值核算明细表 | F2 成本分档子列 | 加可选列 | 随 F2 |
| 3 持仓分类表 | F2 成本分档、F13 分红累计 | 加子列 | `report_submodules.cost_lots`（默认关） |
| 4 资产穿透TOP10 | F3 估值分位 | 加估值分位列 | `report_submodules.valuation_percentile` |
| 5 基金业绩分析 | F10 候选比较模式 | 增强模式（候选来自 config/CLI，≤10） | `report_submodules.candidate_compare`（默认关） |
| 10 因子暴露分析 | F15 行业 Beta 子表 | 加子表 | `report_submodules.industry_beta` |
| 14 智囊团深度复盘 | F1 调仓建议、F4 纪律、F6 归因 | 重组「复盘 + 行动」两板块 | `report_submodules.action` |
| 18 历史回撤分析 | F11 危机标注、F14 尾部风险 | 加标注层 + 指标列 | `report_submodules.tail_risk` |
| 19 组合演进 | F8 快照差异摘要 | 顶部加差异摘要 | `report_submodules.snapshot_diff` |
| 20 数据源可用性矩阵 | F9+F12 数据质量仪表盘 | 改造为「源健康 + 品种覆盖 + 可信度」三区块 | `report_submodules.data_quality` |

> 未列章节（6/7/8/9/11/12/13/15/16/17/21）不改造，保持现状。F5 what-if 成本归入独立 what-if 报告（非 21 章）。
>
> **14 章重组**：分「复盘」板块（现状 LLM 圆桌 + 情景 + 口径 + 量化指标 + 竞争语境）与「行动」板块（再平衡信号 + 纪律触发 + 调仓建议清单 + 收益归因）——决策中枢清晰、不增章。

### 4.3 旧章节处理（防繁杂的另一面）

- **不强制物理合并**：6/7/8/11（基金关系）与 9/10（风格）虽有重叠，但物理合并牵动渲染模块/config 开关/测试/文档四处，收益仅"入口变少"，成本高。
- **轻合并**：HTML 报告按「基础/基金深度/风险/历史/LLM」**分组导航折叠**；Excel 沿用 `report_section_order` 自定义排序 + `enable_*` 开关（用户可自行把不常用章节后置/关闭）。
- **物理合并在用户明确表达"章节太多要减"时再评估**，不做主动预建。

## 5. 实施次序

按「价值/风险比」与「地基优先」排序（实施细节与每轮量化验收见 [`plan-investment-iteration.md`](./plan-investment-iteration.md)）：

1. **改造 20 章 → 数据质量仪表盘**（F9+F12，分两步：源健康+品种覆盖 → 可信度+异常跳变）——地基，先行；
2. **14 章 → 行动板块**（F1+F4+F6，重组为复盘+行动）——决策价值最高；
3. **18 章 → 历史增强**（F11 危机标注 + F14 尾部风险）；
4. **10 章 → 行业 Beta**（F15）+ **5 章 → 候选比较**（F10，默认关）；
5. **3/1/2 章 → 成本流水**（F2+F13，随持仓文件格式扩展排期，向后兼容）；
6. **4 章 → 估值分位**（F3）+ **1 章 → 市场温度**（F7，简化版 + 免责，放最后）。

**效果**：21 章总数不变，功能从「事后体检」扩展至「买入比较 + 决策行动 + 数据可信」全覆盖，用户感知章节不膨胀、单章更充实。
