# Jev 新闻关联判定 — 对照评测方案

> 文档版本：0.11.2-dev
>
> 定位：在办评测方案（`docs-stm/plan/` 中间设计文件）。评测完成后随完成态归档，或转为「已评估未采纳」存档。
>
> 配套文档：`jev-news-correlation-design.md`（接入设计草案）

---

## 1. 评测目标

在「财经新闻热点与持仓关联分析」模块上，用三个可证伪命题判断是否值得把判定逻辑迁到 Jev：

| 命题 | 内容 |
|:-----|:-----|
| **替换价值** | Jev 的判定与人工金标准的一致度**不低于**现网 DeepSeek 二次分析 |
| **稳健性** | Jev 的 schema 化答案相对现网「自由文本 JSON + 围栏剥离」路径，**显著降低解析失败率** |
| **成本与披露面** | 同等判定质量下，单次报告该模块的货币成本与墙钟延迟不高于现网，且向外披露的数据面可接受 |

## 2. 预检结论（已完成，用于收窄评测范围）

从 `data/cache/` 回收 48 条既有判定（`llm_news_item_*_v3.json`，文件体仅存判定三元组）：

| 指标 | 实测 | 含义 |
|:-----|:-----|:-----|
| `relevance` = 「高」 | 37/48 = **77%** | 严重饱和，区分度低 |
| `relevance` = 「无关」 | **0/48 = 0%** | 关键词预筛已承担相关性闸门，判定侧从不否决 |
| `sentiment` 分布 | 利好 23 / 中性 19 / 利空 6 | **有真实区分度**（48% / 40% / 12%） |
| `analysis` 字数 | 最小 17 / 中位 **23** / 最大 33 | 短、实体中心、可模板化 |
| `analysis` 空值 | 0/48 | 现网路径未出现空理由 |

**由此产生的四条设计约束：**

1. **主指标取 `sentiment`**。`relevance` 有 77% 集中在单一档位，无法区分三个方案。
2. **`relevance` 降级为保真度指标**——各方案是否至少都判为相关（即不出现「无关」误杀），而非准确率主指标。
3. **「先用判定预筛、再减少送生成模型的输入」这一动机已被证伪**（「无关」占比 0% → 无可筛除项），从候选方案中剔除，评测不再考察两段式。
4. `analysis` 的短小实体中心特征，使「判定 + 确定性模板生成理由」方案在可行性上站得住（细节见设计草案）。

> **预检的边界**：这 48 条来自单一持仓快照、由同一模型产出，样本小且有模型偏置，只用于**收窄范围**，不能替代三方对照。

## 3. 语料构造

### 3.1 为什么不能从缓存回收语料

`llm_news_item_{fp}_v3.json` 的文件名与文件体都不含新闻原文与持仓上下文：

- 文件名 `fp = fingerprint({"title": title[:80], "holdings_fp": context_fp})` 是**单向哈希**；
- 文件体仅 `{"_ts": <float>, "_data": [relevance, sentiment, analysis]}`。

因此已产出的判定**无法与新闻原文、持仓上下文重新对齐**（持仓快照已变，`holdings_fp` 不可复原）。语料必须现场构造。

### 3.2 取法：现场快照 + 冻结

```
snapshot 阶段（一次性，可重复执行）
  1. aggregate_news(keywords, top_n=...)            # providers/news_aggregator.py
  2. correlate_news_with_holdings(news, keywords)   # providers/news_correlator.py
  3. 落盘冻结语料 jev-eval-corpus-<YYYYMMDD>.jsonl
     每行含：title / intro / ctime / media_name / matched_keywords
  4. 同时冻结当次持仓名单摘要（name / code），随语料一并落盘
```

冻结语料一旦落盘即**只读**，三个方案与人工标注共用同一份，保证可比性。

**落盘位置纪律**：语料含真实新闻标题与持仓信息，必须落在 `docs-stm/tmp/`（运行时临时产物，git 忽略），**不得**进入受版本管理的目录。若需入库，只允许提交**脱敏样例**（不超过 10 条，名称替换为「品种X」）。

### 3.3 样本量与分层

- 目标 **40~60 条**新闻（单快照），覆盖至少 3 个行业与 2 个基金重仓方向。
- 按 `matched_keywords` 命中数分**高/中/低**三层，每层不少于 10 条——否则会复现 `relevance` 饱和，使对照失去意义。
- 单快照不足时可叠加 2~3 个交易日快照，但同一轮对照必须使用同一份冻结语料。

## 4. 三个对照方案

| 方案 | 实现入口 | 需要网络/凭据 | 说明 |
|:-----|:---------|:--------------|:-----|
| **关键词臂** | `providers/news_correlator.correlate_news_with_holdings` | 否 | 确定性、零成本。无 `sentiment` 输出 → 主指标不计分，仅作相关性保真度与成本下限参照 |
| **现网臂** | `llm/generators_news.enhance_news_correlation` | 是（现有凭据） | 现网行为，作为「替换价值」的对照基准 |
| **Jev 臂** | `POST /v1/systemone`（或网关等价路径） | 是（需 Jev 凭据） | 待评对象 |

两个需要网络的方案必须使用**同一冻结语料**、**同一持仓摘要文本**、**同一问项文案**。

## 5. 人工金标准

- **盲标**：标注者不被告知某条判定来自哪个方案；各方案输出随机交错为单一待标清单。
- **标注对象**：`sentiment`（利好/利空/中性）为主，`relevance`（高/中/低/无关）为辅。
- **标注依据**：仅依据「冻结语料中的新闻文本 + 冻结的持仓名单」，**不引入标注者的外部行情判断**——否则会把「事后涨跌」当成金标准，评测即失效。
- **标注粒度**：以新闻为单位给出 `sentiment`，与现网实现口径一致（不要求与持仓逐一绑定）。
- **一致性**：抽 20% 双标并报告 Cohen's κ。κ < 0.6 时该字段金标准不可用，改用「双标注者多数票」并在结论中显式标注不确定性。

## 6. 指标

### 6.1 主指标 — `sentiment`

- 三分类准确率（对金标准）
- 宏平均 F1（利好/中性/利空三类等权）
- 混淆矩阵——重点观察「中性 ↔ 利好」混淆，预检显示这两类占 88%

### 6.2 保真度指标 — `relevance`

- **「无关」误杀率**：某方案判「无关」而金标准为相关 → 该新闻会被丢弃，属**用户可见的功能回归**
- 「高」判定占比（饱和度对照，检验是否复现 77% 集中）

### 6.3 稳健性指标

- **解析失败率**：现网臂 = JSON 解析失败 / 缺项 / 索引越界占比；Jev 臂 = schema 校验失败占比
- **答案完整率**：请求 N 条，成功返回 N 条答案的比例
- **重试与降级触发次数**

### 6.4 校准指标 — 仅 Jev 臂

以 Choice 问项产出概率分布与 `confidence`：

- **Brier 分数** 与 **期望校准误差（ECE）**，按置信度分 5 箱
- 若 ECE 高于 §7 预注册阈值，则「校准概率」这一卖点在本场景**不成立**，选型理由必须回落到「是否更准」，而非「是否更校准」

### 6.5 成本与延迟

- 货币成本：现网臂按现网定价表估算；Jev 臂按公开单价（输入 $0.042/M、输出免费）估算
- 墙钟延迟：单批全量请求端到端耗时，各测 3 次取中位
- 必须区分**单次报告增量**与**边际成本**——该模块出厂默认关闭，需说明启用后的真实增量

### 6.6 披露面

记录 Jev 臂向外发送的字段清单与字节数，与现网臂对比**披露面增量**（新增一家厂商接收持仓与新闻文本）。

## 7. 判定阈值（预注册）

阈值先写死再跑，避免事后挑选结论：

| 决策 | 条件 |
|:-----|:-----|
| **推荐接入（判定 + 模板理由）** | `sentiment` 宏平均 F1 ≥ 现网臂，且「无关」误杀率 = 0，且 ECE ≤ 0.15，且解析失败率 < 现网臂，且模板理由抽检 ≥ 80% 认为「信息量相当」 |
| **推荐接入（仅标签）** | 同上但模板理由抽检不达标 → 仅保留标签，隐藏理由列 |
| **维持现状** | `sentiment` F1 < 现网臂，或 ECE > 0.25（校准无价值），或披露面增量不可接受 |
| **放弃该方向** | 现网臂与关键词臂在 `sentiment` 上无显著差异（说明该字段本身不承载信息） |

显著性：40~60 条样本下用配对检验（McNemar）或 bootstrap 置信区间。样本量不足以判显著时，结论必须写成「未观察到差异」，**不得**写成「等价」。

## 8. 脚本落点

- 目录：`scripts/`（沿用扁平语义命名）
- 拟名：`jev-news-correlation-eval.py`——与既有 `calibrate-dedup-threshold.py`、`llm-hallucination-sampler.py` 同类，属离线评测/校准脚本
- 子命令：`snapshot`（取数冻结）/ `run`（三方案跑分）/ `report`（指标汇总与判定）
- 必须复用 `scripts/_checklib.py` 的 CLI 契约（`-v/--verbose` + `--ci`；通过退出 0，发现 finding 退出 2）
- 该脚本是**离线工具**，不得被 pytest 收集：不放在 `src/test/` 下，也不得在其中真实调用 LLM 而进入测试套件

## 9. 前置条件

1. **Jev 凭据**——TypeSafe 直连为 waitlist；可经 Vercel AI Gateway / OpenRouter / Cloudflare Workers AI 之一，前两者可复用本机既有凭据
2. **冻结语料**——由 `snapshot` 子命令产出
3. **人工标注**——40~60 条 `sentiment` + `relevance`
4. 该模块处于启用状态（`enabled_llm.news_correlation`）——否则评测无实际落点

## 10. 复现步骤

```bash
# 1. 冻结语料（一次性，产物落在 git 忽略的 tmp 目录）
.venv/bin/python scripts/jev-news-correlation-eval.py snapshot --out docs-stm/tmp/jev-eval-corpus.jsonl

# 2. 三方案跑分
.venv/bin/python scripts/jev-news-correlation-eval.py run --corpus docs-stm/tmp/jev-eval-corpus.jsonl

# 3. 汇总并做判定（含阈值比对，未达标返回退出码 2）
.venv/bin/python scripts/jev-news-correlation-eval.py report --ci
```

## 11. 结论记录方式

评测结束后在本文件追加「结论」小节，固定记录：样本量与分层构成、标注一致性 κ、三方案主指标表、ECE、解析失败率、成本与延迟、披露面增量、最终判定（推荐/维持/放弃）与依据。若判定为「维持现状」或「放弃」，设计草案随完成态一并归档并标注未采纳。
