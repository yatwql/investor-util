# LLM 模块缓存指纹的提示词覆盖设计（竞争语境块与量化指标）

> 来源：自审发现（LLM 模块指纹**覆盖不足**——`competitive_context` / `metrics` 参与提示词构造却不进任何模块指纹）。
> 级别：**缺陷修复（无开关，默认路径生效）**——不引入 `features.json` 开关，不做实验登记。
> 前置：模块指纹的「唯一事实来源 + 读写同源」已由 `llm/module_fingerprint.py` 结构性保证（前一轮缺陷修复落地）；本设计解决的是同一设施上的**第二类缺陷**。

## Context

模块缓存键 = `CACHE_PREFIX_LLM + f"{模块}_{指纹}"`。指纹决定「同一份持仓在行情/配置变动后能否复用旧内容」。

现状是**两侧一致缺失**：竞争语境文本块与量化指标都进了提示词，但两侧的指纹构造里都没有它们。因此不产生「恒不命中」（那是读写不同源的症状），而是**恒命中过期内容**——持仓未变、基准指数或指标已变时，键不变 → 预检直接复用旧 LLM 输出，而旧输出里写着按旧数据算出的对比结论（如「相对沪深300 跑赢 1.26 个百分点」）。报告其它章节展示的是新算出的数字，两处口径不一致，且**不报错**。

两类缺失内容（提示词实际包含、键未包含）：

| 内容 | 进入哪几段提示词 | 生成自 | 键中是否已有 |
|:--|:--|:--|:--|
| 竞争语境文本块 | 全球政经局势、智囊团复盘（含辩论三阶段） | `prompts_core._build_competitive_context_block(a_indices, total_mv, total_today_profit, history_data, comparison_indices, metrics)` | ✗ |
| 　└ 今日对比 / 跑赢跑输 | 同上 | 指数当日涨跌幅 + 组合当日涨跌幅 | 组合侧已入键；**指数侧未入** |
| 　└ 区间对比 | 同上 | `history_data.benchmark_returns` / `portfolio_returns` | 仅风险信号摘要入键，**区间序列未入** |
| 　└ 指标对比 | 同上 | `metrics` 的 sharpe / annualized_volatility / max_drawdown / calmar | ✗ |
| 　└ 对比指数池 | 同上 | `config.json` 的 `comparison_indices` | ✗（配置改动 → 提示词变、键不变） |
| 量化指标（`metrics`） | 智囊团复盘（指标表 + 情景分析 + 风格一致性） | `analysis.metrics.compute_all_metrics()` + `report/_full_risk_metrics.py` 补充字段 | ✗（仅风险信号摘要部分重合） |

## 量化与取舍（先量化再决定）

rf 登记的顾虑是「纳入会提高未命中率、增加 LLM 费用」。量化结论：**边际失效成本接近零，且新增失效维度恰是缺陷要消除的那些**。

1. **常态下不产生新的失效**。三类模块的指纹**已经**包含 `total_mv` / `total_profit` / `total_today_profit`——A 股持仓的当日盈亏随行情变动，键本就随市场漂移。竞争语境块与指标表都是由这些**已在键中的量**派生的（组合当日涨跌幅 = 当日盈亏 / 总市值；区间收益、指标表随历史数据刷新而变，而历史数据刷新同样改变风险信号摘要）。同一份数据重跑 → 块与指标逐字节相同 → 该命中仍命中。
2. **新增失效维度只有两类，且都是「提示词真的变了」**：
   - **指数/基准变动而组合未动**（QDII 净值滞后一日、组合当日盈亏恰好不变）：此即缺陷所述「基准指数变动使对比块内容变化」，不换键就是陈旧内容；
   - **同参数重算 `metrics`**（基准 β 变化带动情景分析）：由历史数据刷新驱动，本就不频繁。
3. **失效上界受 TTL 约束**：`expert_review` 2h、`global_macro` 24h。极端情形下每个 TTL 窗口至多多一次重算，费用可控。
4. **与既有原则一致**：模块指纹的既有口径是「多算只带来无害的过度失效，漏算则导致内容与键脱钩的陈旧缓存」（`history_data` 风险信号对三模块统一入哈希即按此执行）。本设计沿用同一条原则，只是把「多算」的范围补到提示词实际包含的段落上。

**结论：纳入。** 覆盖范围以「该模块提示词是否真的包含这一段」为准，不做全局无差别并入——并入不进入提示词的内容是纯成本、零收益。

## 设计

### 核心不变量：一次渲染，同一实例既入指纹又入提示词

竞争语境块由 `_build_competitive_context_block` 渲染。若「进提示词的块」与「进指纹的块」由两次独立渲染产生，就退化成同源靠纪律维护（正是前一轮缺陷的成因）。故：

- **渲染点收敛到 `generate_all_llm`**（该函数的唯一调用方）：进入预检前渲染一次，得到的**同一字符串实例**分别传给预检侧（参与指纹）与 worker 分发侧（注入提示词）；
- `_dispatch_llm_workers` **不再自行渲染**，改由参数接收该实例；
- 预检侧因此无需知道 `comparison_indices` / `metrics` 如何渲染成文本——它只对收到的字符串取哈希。渲染器未来改动（换单位、加行、改口径说明）自动反映到键上，不会出现「改了提示词忘了改键」。

### 指纹输入扩展

`ModuleFingerprintInputs` 增两个字段（两侧共同持有）：

| 字段 | 含义 |
|:--|:--|
| `competitive_context: str` | 已渲染的竞争语境文本块（与注入提示词的**同一实例**） |
| `metrics: dict \| None` | 量化指标字典（指标表 / 情景分析 / 风格一致性的共同来源） |

覆盖精确到模块（构造器逐个判断，而非注册表统一加）：

| 模块 | 提示词含竞争语境块 | 提示词含量化指标 | 本次改动 |
|:--|:--:|:--:|:--|
| `global_macro` | ✓ | ✗ | 并入 `competitive_context` |
| `expert_review` | ✓ | ✓ | 并入 `competitive_context` + `metrics` |
| `health_check` | ✗ | ✗ | 不变 |
| `penetration_deep` | ✗ | ✗ | 不变 |
| 辩论三键（白脸/黑脸/综合） | ✓ | ✓ | 另立构造器，仅并入其提示词实际包含的输入 |

### 辩论三键：消除第二处指纹自拼

辩论模式的缓存键（`llm_debate_pro_` / `llm_debate_con_` / `llm_debate_synthesis_`）由 `generate_debate_procon` **自行调用 `build_llm_fingerprint` 拼接**——这是唯一绕开模块指纹注册表的拼接点，属既有技术债。其提示词实为 expert_review 提示词（含竞争语境块与量化指标），但键里两者皆无。本次一并收敛为 `module_fingerprint.debate_procon_fingerprint()`。

**刻意不复用 `expert_review_fingerprint`**：辩论提示词**不含**历史风险信号段与信号预消化段（其 user prompt 不传 `history_data` / `enable_signal_digest`），若复用会把每次运行都变化的 `pipeline_data` 摘要并入键 → 辩论三键每份报告必 miss，白跑三次 LLM。故辩论构造器只并入其提示词真正包含的输入（基础持仓 + 辩论增强后缀 + 竞争语境块 + 量化指标）。

### 为何不对整个 user prompt 取哈希

「键 = 提示词哈希」是这条不变量的最强形式，但不可行：预检要在**提示词构造之前**得出结论（构造提示词本身即编排行为，且需 `pipeline_data` 等运行期数据），且既有指纹口径以**输入**为单位（含稳定字段提取，剔除行情波动字段）。故取「块级渲染文本 + 指标字典」这一粒度：粒度覆盖了实际缺口，且不改变既有的稳定字段提取纪律。

## 测试（先补断言，后改实现）

在 `src/test/unit/llm/test_module_fingerprint.py` 现有「读写同源」测试基础上补三类断言，**改动前先跑出红**：

1. **同源**：既有 `test_precheck_key_equals_write_key` 的参数化场景补上「竞争语境块变化」「量化指标变化」两维 → 预检键与写侧键逐字符相同（预检侧若未收到同一字符串即红）。
2. **敏感性**：竞争语境块内容变化 / `metrics` 变化 ⇒ 对应模块指纹随之变化（本缺陷的正面断言）。
3. **精确性**：`health_check` / `penetration_deep` 的指纹**不随**两者变化（防止误加导致的纯成本失效）。
4. **渲染一次的结构性保证**：`generate_all_llm` 运行期只渲染一次竞争语境块，且进入指纹的实例与注入提示词的实例**同一**（哨兵字符串 + 两侧捕获参数断言 `is` 同一对象）。
