## 1. 数据源可靠性文档

> **状态：✅ 已完成**（2026-07-27）
> - 文档：`docs-stm/manuals/datasource-reliability.md`
> - 健康检查命令：`python -m src.python.cli check-sources`

### 概述

当前 `datasource.md` 记录了缓存键和数据路径，但缺少运维视角的信息：每个数据源的可靠性如何、挂了之后降级到哪里、更新频率、是否有 API 访问限制。

### 收益

- **故障排查有依据**：当"贵州茅台行情为 0"时，快速查到这个源是否处于已知故障期
- **新数据源接入指南**：新人（或 6 个月后的你）接入新数据源时有模板可循
- **用户知情权**：报告中可引用文档说明数据可靠性等级，用户理解为什么某些数据可能缺失
- **低投入高回报**：信息已经在团队（你）的脑子里，只是没有写下来

### 风险

- 文档需要持续维护（数据源接口变化时），容易过时
- 第三方数据源的 SLA 不可控，文档说"稳定"但对方挂了就尴尬

### 工作估算：**1-1.5 天**

### 文档结构

每个数据源记录以下字段：

| 字段 | 示例 |
|------|------|
| 名称 | 腾讯财经行情 API |
| 用途 | A 股/ETF 实时行情 |
| 接口类型 | HTTP GET + JSONP 回调 |
| 数据频率 | 盘中实时（3s 更新） |
| 可靠度 | ★★★★☆（偶尔熔断限制） |
| 降级目标 | 新浪财经 → 缓存 |
| 限流规则 | 单 IP 10 次/秒 |
| 免费边界 | 无认证，无用量限制 |
| 已知问题 | 13:00-13:05 午盘刚开时偶尔超时 |
| 历史故障 | 2026-05-12 宕机 4 小时 |
| 最后验证 | 2026-07-20 |

当前覆盖的数据源：
- 腾讯财经（行情）
- 新浪财经（行情/新闻/美股指数）
- 东方财富（基金净值/新闻）
- 天天基金（业绩排名/持仓/经理）
- akshare（资金流向/分红/盈利预测）
- 财联社 / 华尔街见闻（新闻）
- 接口直连（A 股指数、美股指数）

## 2. 架构决策记录（ADR）

### 概述

`technical.md` 描述了"当前架构是 X"，但没有记录"为什么选择 X，为什么没有选择 Y"。几个月后回头看，"为什么 Provider Chain 有 5 种策略？"、"为什么不用 asyncio？"——需要 ADR 来回答这些问题。

### 收益

- **保留上下文**：未来的你修改代码时理解原始决策的约束条件
- **避免重复讨论**：回头再遇到"要不要异步化"的讨论，ADR 记录了上次为什么否决
- **新手 onboarding**：读 ADR 是理解项目架构最快的方式
- **低维护成本**：一个决策写一次，架构大变更时才更新

### 风险

- 写 ADR 需要时间和纪律，容易被低优先级挤掉
- 过时的 ADR 比不写更危险（误导读者）
- ADR 数量膨胀后管理成本上升

### 工作量估算

| 阶段 | 内容 | 天数 |
|------|------|------|
| 框架搭建 | ADR 目录结构 + 模板 + 索引 | 0.5 |
| 回顾性 ADR | 补写过去 5-8 个关键决策（见列表） | 1.5 |
| 流程固化 | 要求所有架构变更配套写入 ADR | 0.5 |
| **合计** | | **2.5 天** |

### 建议首批 ADR 列表

| # | 标题 | 关键决策 |
|---|------|----------|
| 001 | 选择 Provider Chain 而非单数据源 | 多源可靠性竞争 vs 额外复杂度 |
| 002 | 缓存设计：TTL + 指纹失效 + 分组隔离 | 缓存一致性 vs 实时性 |
| 003 | 为什么选 akshare 而非自建数据采集 | 维护成本 vs 自由度 |
| 004 | 同步 HTTP 而非 asyncio | 简单性 vs 性能（此文记录需 revisit） |
| 005 | Feature Flag 而非条件编译 | 运行时开关 vs 编译时判断 |
| 006 | 五层架构分层原则 | 模块解耦 vs 性能开销 |
| 007 | Excel + HTML 双格式而非单格式 | 打印/存档 vs 分享/交互 |

### ADR 模板

```markdown
# ADR-{编号}: {标题}

## 状态
[已接受 | 已否决 | 已废弃]

## 上下文
...

## 决策
...

## 后果
正面：
负面：

## 替代方案
- 方案 A：...（否决原因）
- 方案 B：...（否决原因）

## 关联决策
- ADR-{编号}
```
