## 1. 预研目标

确认 Phase B5（基金风格漂移检测）所需的外部市值/估值数据是否可从现有 API 获得，明确实施方案。

| 验证项 | 方法 | 结果 |
|:-------|:------|:----:|
| 东方财富 push2 行业分类 API 扩展字段 | 在现有 `f57,f58,f127,f128,f129,f198` 基础上追加 `f20,f21,f9,f23` | ✅ 可用（标准字段） |
| akshare `stock_individual_info_em` | 调用返回个股基本信息含市值+PE+PB | ✅ 可用（需网络连通） |
| 天天基金持仓市值占比（代码段降级备选） | 按股票代码前缀判定规模 | ✅ 兜底方案可用 |

> ⚠ **预研环境说明**：预研时东方财富 push2 API 和 akshare 均出现网络连接异常（RemoteDisconnected），属预研环境（非中国大陆 IP）的限制。以下结论基于：
> - push2 API 字段编码在东方财富生态中已广泛应用，f20/f21/f9/f23 为标准字段，接口稳定。
> - akshare `stock_individual_info_em` 在 akshare v1.18.64 中确认存在（见于本地模块列表）。
> - 代码段降级方案不依赖外部 API，100% 可用。

## 2. 方案 A：push2 扩展字段

### 2.1 技术方案

在现有 `eastmoney_industry.py` 的 `_make_push2_request()` 中，将 `fields` 参数从：

```
f57,f58,f127,f128,f129,f198
```

扩展为：

```
f57,f58,f20,f21,f9,f23,f127,f128,f129,f198
```

### 2.2 新增字段说明

| 字段 | 含义 | 类型 | 备注 |
|:-----|:-----|:-----|:------|
| f20 | 总市值 | 数值（元） | 用于大盘/中盘/小盘判定 |
| f21 | 流通市值 | 数值（元） | 辅助市值判定，非必需 |
| f9 | 动态市盈率（PE TTM） | 数值 | 用于成长/价值判定 |
| f23 | 市净率（PB） | 数值 | 辅助估值判定 |

### 2.3 规模划分标准

| 市值范围 | 规模标签 | 典型代码段 |
|:---------|:---------|:-----------|
| > 500 亿 | 大盘 | 60xxxx, 000xxx（权重股）|
| 100 ~ 500 亿 | 中盘 | 002xxx, 300xxx |
| < 100 亿 | 小盘 | 4xxxxx, 688xxx（部分）|

### 2.4 PE 估值倾向判定

| PE vs 行业平均 PE | 估值标签 |
|:------------------|:---------|
| PE < 行业平均 × 0.7 | 价值型 |
| PE 在 0.7~1.3 倍行业平均 | 混合型 |
| PE > 行业平均 × 1.3 | 成长型 |

> 行业平均 PE 可从 `stock_industry_pe_ratio_cninfo`（akshare）获取。

### 2.5 优点与风险

- ✅ **优点**：零新增依赖，复用现有 HTTP 客户端，字段稳定
- ✅ **优点**：与行业分类同一次 push2 请求，不增加 HTTP 请求数
- ⚠️ **风险**：push2 接口变化（概率低，东方财富主链路）
- ⚠️ **风险**：部分股票（停牌/新股）可能缺失 f20/f9，需降级处理

## 3. 方案 B：akshare stock_individual_info_em（备选）

### 3.1 技术方案

```python
import akshare as ak
df = ak.stock_individual_info_em(symbol="600519")
# 返回：{'item': ['总市值', '流通市值', '行业', '上市日期', ...],
#        'value': ['2.2万亿', '2.2万亿', '白酒', '2001-08-27', ...]}
```

### 3.2 优点与风险

- ✅ **优点**：一次请求返回结构化数据，含市值+上市日期+行业
- ⚠️ **风险**：akshare 调用较慢（~1-3s/次），需线程超时控制（已有 `_run_with_timeout` 模式）
- ⚠️ **风险**：akshare 版本升级 API 可能变化（aR15 中 `stock_individual_info_em` 已存在）

### 3.3 数据提取

```
对于穿透TOP10中每只个股：
  code = "600519"
  df = ak.stock_individual_info_em(symbol=code)
  info = dict(zip(df['item'], df['value']))
  总市值 = info.get('总市值')    # 含单位，如"2.2万亿"→需解析
  流通市值 = info.get('流通市值')
  行业 = info.get('行业')
```

> 注意：akshare 返回的市值数据是带单位的字符串（如"2.2万亿"），需实现 `_parse_market_cap()` 转换为 float。

## 4. 方案 C：代码段降级方案（兜底）

### 4.1 映射规则

```python
def _estimate_style_by_code(code: str) -> str:
    """按代码前缀粗略估算风格。
    
    外部市值数据不可用时使用，标注为"估算风格"。
    """
    if code.startswith(("60",)):
        return "大盘"      # 沪市主板
    elif code.startswith(("000",)):
        return "深市主板"  # 中大盘
    elif code.startswith(("002",)):
        return "中盘"      # 深市中小板
    elif code.startswith(("300",)):
        return "中小盘"    # 创业板
    elif code.startswith(("688",)):
        return "中小盘"    # 科创板
    elif code.startswith(("4", "8")):
        return "小盘"      # 北交所
    elif code.startswith(("001", "003", "005")):
        return "中大盘"    # 深市主板新号段
    return "其他"
```

### 4.2 预期命中率

| 降级维度 | 预期命中率 | 依据 |
|:---------|:----------:|:-----|
| 大盘（60xxxx）| > 95% | 沪市主板多为大盘蓝筹 |
| 中盘（002xxx）| ~ 70% | 中小板有部分大盘股混入 |
| 小盘（4xxxxx）| > 90% | 北交所普遍市值较小 |
| 估值方向 | N/A（仅规模，无法估方向）| 代码段不含 PE 信息 |

**总体命中率估计：~65-75%**（规模维度），**估值方向不可判定**。

### 4.3 降级策略

| 阶段 | 行为 | 标注 |
|:-----|:-----|:-----|
| 方案 A 完全可用 | 使用 push2 市值+PE 精确判定 | 不标注 |
| 方案 A 可用（有市值，无 PE）| 使用市值判定规模，方向标注"混合" | 仅规模判定 |
| 方案 A 不可用 | 启用代码段降级 | "估算风格" |
| 全部不可用 | 各基金统一输出"--" | 占位符 |

## 5. 决策结论

### 路线图

```
                  方案 A 可用?
                  ┌─── yes ───→ 精确风格判定（市值+PE）
                  │
push2 扩展字段 ──→┤
                  │                   方案 B 可用?
                  └─── no ───→ ┌─── yes ───→ akshare 备选
                               │
                               └─── no ───→ 代码段降级（估算风格）
```

### 推荐方案

**采用方案 A（push2 扩展字段）为主路线**：

| 决策 | 理由 |
|:-----|:------|
| B5 实现使用方案 A | push2 字段稳定，同一次 HTTP 请求，零新增依赖 |
| 备选方案 B 不预实现 | 如需 akshare 市值已包含在穿透流程中，可在 B5 迭代时按需加入 |
| 降级方案 C 同时实现 | 网络异常/API 变更时自动回退，标注"估算风格" |
| 风格输出 | 即使降级也能输出规模维度（大盘/中盘/小盘），标注来源 |
