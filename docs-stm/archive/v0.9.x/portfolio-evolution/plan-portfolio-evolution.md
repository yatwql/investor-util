## 1. 多快照趋势追踪

### 概述

`history_snapshot` 已经存了多期 JSON 快照，但报告只展示当期。新增"组合演进"页签，展示多期快照合并后的趋势。

### 收益

- **看到变化**：行业配置在 3 个月内的变动趋势、穿透 TOP10 的集中度变化
- **回答"我怎么到这里的"**：回看历史配置可以复盘自己的决策轨迹
- **自动增量**：每次跑报告自动产生一份快照，趋势数据随时间自然积累
- **低增量成本**：快照数据已有，只需聚合 + 展示

### 风险

- 快照格式在版本升级中可能变更，需做向后兼容
- 首次使用时快照不足（< 3 期），图表数据点太少

### 工作量估算：**3 天**

### 主要输出

- **总市值趋势线**（时间序列 + 分账户堆叠）
- **行业配置流**（百分百堆叠面积图，行业占比随时间变化）
- **穿透 TOP10 变迁**（类似 Bar Chart Race）
- **集中度指数 HHI 趋势**
- **量化指标趋势**（夏普、波动率的历史变化）

### 数据源可行性分析

| 维度 | 结论 |
|:-----|:-----|
| 新数据源需求 | **无** — 聚合既有 `history_snapshot` JSON 快照文件（纯本地持久化数据） |
| 依赖的既有数据 | 每次跑报告自动产生的快照（包含持仓权重、品种详情、穿透 TOP10、量化指标），零 API 调用 |
| 数据源风险 | **无** — 快照数据在本地缓存中，不受网络/API 影响 |
| 其他风险 | 快照格式跨版本兼容性（需做向后兼容）；初期快照不足 3 期时图表数据点偏少 |

**结论**：plan-6 不依赖任何外部数据源，可行性无数据源阻力。
