# 调仓纪律回放（schedule_replay）设计 —— plan-80

> **状态**：设计 + 已实施（plan-80 四迭代落地，先决门槛三段全过；实施与门槛判定见 §14）。
> **参照**：gs-quant `backtests/`（`RebalanceAction` 规则触发、`TransactionModel` 三件套成本分层、`PnlAttribute` 分期分解——只借语义不搬引擎，见 `gs-quant-borrow-candidates-research.md` §2.3）。
> **研究背景**：见 `gs-quant-borrow-candidates-research.md` §2.1。

## 1. 动机与缺口

- `rebalance.py` / `simple_rebalance.py`：**约束检查与建议**（能不能调、怎么调）——不回答「调了会怎样」；
- `whatif_backtest`：**单次调仓**的指定生效日窗口对比——不回答「长期坚持某纪律会怎样」；
- 缺口：**规则化多期回放**——「每月定再平衡 / 偏离阈值触发再平衡」在历史窗口逐期执行（含成本），与「买入持有」对比。这是「纪律 vs 放任」的量化回答，也是行动建议章最有说服力的证据类型。

## 2. 先决门槛（go-no-go，未过则归档未采纳）

1. **指标原语可复用**：收益/回撤/夏普全部复用 `analysis/metrics*` 与 `whatif_backtest` 既有纯计算，**不新造回测引擎**（架构决策：扩展而非引入新框架）；核对存在至少 3 处可直接复用项后成立。
2. **成本联动**：成本计入依赖 plan-77 `trade_cost_model`；未落地时先出「无成本版」且**每行显式标注「未计成本」**（日志回显纪律同款），落地后软切换——不阻塞、不双实现。
3. **价值验证**：用户对 2 个真实持仓规则回放样例（定期 + 阈值各一）确认「有启发、想持续看」；否则归档。

## 3. 语义命名（先定名再设计）

| 语义名 | 层 | 说明 |
|---|---|---|
| `replay_schedule` | 契约 | 回放规则（定期 cadence / 阈值偏离触发 + 目标权重来源） |
| `schedule_replay` | analysis | 纯计算：规则 → 逐期调仓序列 → 逐期净值回放（复用 metrics 指标原语；成本经 plan-77 `trade_cost_model` 软接入） |
| `schedule_replay_panel` | report | Excel/HTML 回放章（纪律回放 vs 买入持有双线 + 逐期换手/成本表） |
| 开关 `rebalance_schedule_replay` | config | 默认关（实验组） |

## 4. 迭代设计

四个迭代串行推进，每个迭代单独可合并（P0 门禁绿）；前置依赖未满足不得开工。

| 迭代 | 范围 | 前置依赖 | 产出物 |
|---|---|---|---|
| 1 规则契约与纯计算 | `replay_schedule` 解析（cadence=月/季、阈值=偏离 x pp；目标权重=当前持仓归一或用户指定）+ `schedule_replay` 逐期回放（调仓日对齐交易日、LOCF 行情、逐期净值归一 100 基点，同源 `whatif_backtest` 约定）；fixture 手算：2 期回放 + 阈值触发 1 例 | 先决门槛 1（指标原语核对 ≥3 处可复用） | 规则契约 + 回放纯函数 + 手算用例 |
| 2 成本软接入 | plan-77 `trade_cost_model` 可用则逐期计入（FIFO 档位口径同源）；不可用则置 `cost_note="未计成本"` 并在面板/日志回显；零双实现 | 迭代 1；先决门槛 2（软依赖声明） | 成本注入点 + 两态输出 |
| 3 报告双端 | `schedule_replay_panel`（双线图数据 + 逐期换手/成本表 + 与 `action_advisor` 纪律建议互链只读）；LLM 行动建议块可引用回放结论（单源数据，指纹携带） | 迭代 1（迭代 2 可并行） | 双端面板 + LLM 引用接线 |
| 4 验收与文档 | 先决门槛三项判定 + 五份文档同步 + P0 门禁 | 迭代 1~3 全绿；先决门槛 3（2 个真实样例用户确认） | 门槛判定记录 + 文档同步 |

## 5. 红线与约束

- **分层不重叠**：与 plan-77 分工明确——plan-77 = 单次调仓窗口 + 成本口径；本模块 = 多期规则回放（消费其成本模型，不复制口径）；与 `rebalance.py` 只读互链，不互写。
- **不新造引擎**：不引入 gs-quant / Vibe 引擎代码；回放逻辑全在 `analysis/schedule_replay` 纯函数内（<800 行硬上限受 `check-file-length` 守护）。
- **降级**：历史窗口不足 12 个月或行情缺口 >30% → `available=false` 章隐藏；阈值触发无一发生 → 明示「窗口内未触发」而非空表。
- **开关纪律**：默认关；关态逐字节回退回归用例。
- **测试纪律**：fixture 最小持仓（2-5 品种）+ mock 行情；输出目录隔离；edge 场景入 `*_edge.py`。

## 7. 架构定位与依赖方向

| 构件 | 落点层 | 依赖方向与约束 |
|---|---|---|
| `replay_schedule` | 契约（规则解析/校验） | 纯校验无 I/O；cadence/阈值/目标权重语义唯一 |
| `schedule_replay` | analysis 纯计算 | 零 I/O：历史行情经 fetcher 网关备入（Provider 多源链路必经）；逐期调仓日与窗口一律交易日对齐（交易日计数，`core/trading_calendar.py`）；收益/回撤/夏普复用 `metrics*`/`whatif_backtest` 原语（不新造引擎）；单文件受 `check-file-length` 800 行红线守护 |
| 成本注入 | plan-77 `trade_cost_model`（软依赖） | **单源消费不复制口径**：可用则注入，不可用置 `cost_note`；绝不并行实现第二套成本计算 |
| 回放缓存（若启用） | `cache/` 既有接口 | 键含规则指纹，载荷带语义版本（规则语义变更时旧条目按未命中丢弃），禁直写 `data/cache/`（缓存统一管理） |
| `schedule_replay_panel` | report 双端 | 序号/显示名经注册表（报告序号注册表）；pipeline_data 键先入附录 H（pipeline_data 契约）；双线图带 `.chart-caption`（图下说明）；实验组功能经 `_experimental_seams` 挂载点接入（实验挂载点集中） |
| LLM 行动建议引用回放结论 | llm 注入 | 指纹经 `module_fingerprint.py` 单源构造（LLM 指纹单源），降级时只出表不出段落 |
| 开关 `rebalance_schedule_replay` | `config/features.py` | 唯一登记点（开关注册表唯一），默认关 + experiment_stats 观测 |

依赖方向：`report` → `analysis.schedule_replay`（纯函数）← 数据由 `fetcher` 备入；
成本模型是**可选注入的同层协作**（analysis→analysis 接口），未落地时不阻塞、不双实现；
与 `rebalance.py` 只读互链不互写。

## 10. 技术债防线

1. **规则契约版本化**：`replay_schedule` 结构带版本字段，规则语义变更时旧序列按未命中丢弃，不静默沿用旧回放。
2. **成本软接口先行**：对 plan-77 只依赖 `trade_cost_model` 的输入输出契约（买卖明细+费率表→成本金额），不依赖其内部实现；未落地时只出标注版，**绝不并行写第二套成本实现**。
3. **回放缓存键含规则指纹**：规则/窗口/成本开关任一变化即缓存失效；载荷带语义版本（缓存统一管理 与载荷语义版本规则）。
4. **无成本标注显式**：`cost_note="未计成本"` 面板/日志双回显，防误读为已计成本（同「日志回显当前值」纪律）。
5. **单文件红线与语义命名**：`schedule_replay` 受 800 行红线守护；语义名入命名表，任务代号不进实现层。
6. **测试卫生与计数同步**：过 `check-test-redundancy` 五类；删并后同步 `test-coverage.md`/`folders.md` 计数。
7. **文档同步即门禁**：每迭代同回合同步五份文档，`check-doc-drift --ci` 绿才算完。
8. **迭代可独立合并**：每迭代 P0 门禁全绿再进下一迭代；门槛复评不过则全量归档，不留半成品分支。

## 12. 外部数据依赖与稳定性考察

**结论先行**：一项核心外部依赖——**长窗口历史行情**（回放期 ≥12 个月，窗口越长对源稳定性越敏感）；成本费率是可选外部项（软依赖 plan-77）；无新增凭据。

| 数据项 | 来源（链路） | 稳定性风险 | 考察/监测指标 | 降级与防护 |
|---|---|---|---|---|
| 历史行情序列（回放窗口） | `fetch_with_fallback` 多源链（既有） | 单源故障、长窗口中间缺口、停牌 | 行情缺口率（>30% → `available=false` 章隐藏）；chain 命中归属登记（既有诊断） | LOCF + 标注；缺口越阈不硬算；缓存复用降低重取风险 |
| 逐期成本（可选） | plan-77 `trade_cost_model`（未落地则无） | 软依赖缺席 | `cost_note` 状态回显 | 显式「未计成本」标注，不并行实现 |
| 规则触发日 | `core/trading_calendar.py`（本地） | 长假/休市 | — | 调仓日对齐交易日，禁自然日 |
| 目标权重来源 | 用户配置或当前持仓归一（本地） | 用户配置变动 | — | 回放输入快照化（同一次回放内不变） |

**判定动作**：先决门槛 1 的「原语复用 ≥3 处核对」在迭代 1 入口执行并记录清单；运行期缺口率越阈只降级不硬算；2 个真实样例的回放结果若因数据缺口失真（缺口 >30%），先补数据再交用户确认（防拿失真样例过价值门槛）。
