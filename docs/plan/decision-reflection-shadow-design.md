# 决策跨期反思闭环（decision_reflection）设计 —— plan-70

> **状态**：设计（plan-70 原仅有「撤销死线」动作，本文件补齐落地路径；死线条款
> 仍然有效并优先）。
> **参照**：Vibe-Trading `agent/src/shadow_account`（extract → codegen → backtest
> → render 影子账户闭环，3.2K 行 + 2.5K 行测试）。
> **研究背景**：见 `vibe-trading-borrow-candidates-research.md` §2.1。

## 1. 问题重述

`decision_reflection` 实验（`core/decision_ledger` + `decision_llm_capture` +
experiment_stats 观测）现状：真实账本积累极少、闭环从未被真实数据跑通。plan-70
原动作是「2 个发布周期内无增长即撤销」。本设计回答：**若要给转正一次机会，闭环
应当长什么样**。

## 2. Vibe-Trading 影子账户的核心思想（可借鉴点）

1. **把行为结构化成可回放的 profile**：`extract_shadow_profile` 从 journal 提取
   ShadowProfile/ShadowRule（规则化、可序列化、可复跑）——对应我们：把每次复盘/
   调仓 LLM 给出的「行动建议」从自由文本提炼成结构化决策条目（品种/方向/理由
   摘要/置信表述），存入 `decision_ledger.jsonl`（已有）但补齐**可结算字段**。
2. **到期自动回放对账**：影子回测按期复跑 profile，对比「如果按规则做 vs 实际」。
   对应我们：**结算器**——新报告生成时，对账本中未到期的条目按当前行情结算
   （建议后 N 交易日的品种收益 vs 同期基准），回写 direction_accuracy。
3. **归因报告而非裸数字**：AttributionBreakdown 把结果拆成可解释块。对应我们：
   doctor 账本概览已有雏形，补「命中率分品种/分理由类型」拆解。

**不照搬**：其 codegen 生成可执行配置文件的形态（把影子编译成回测配置）对我们
过重——我们已有 whatif_backtest 引擎，结算器直接复用其指标原语即可，不新增引擎。

## 3. 落地路径（若观测期数据支持转正）

四个迭代串行推进，每个迭代单独可合并（P0 门禁绿）；前置依赖未满足不得开工。

| 迭代 | 范围 | 前置依赖 | 产出物 |
|---|---|---|---|
| 1 决策条目结构化 | `decision_ledger` 写入侧（decision_llm_capture）补齐可结算字段：品种代码 / 方向（增配/减配/观望）/ 建议生成日 / 建议理由摘要 / 关联信号 id（可读 signal_ledger 对账） | 死线判定「转正」（§4 硬约束） | 契约版本号 +1；旧条目按「不可结算」跳过；写侧与兼容用例 |
| 2 到期结算器 | `decision_settlement`（analysis 纯计算）：扫描到期条目，按品种取建议日后窗口收益（行情经 fetcher 网关备入），回写结算结果与命中率；结算失败（数据不足）保持未结算下轮重试 | 迭代 1（需可结算字段） | 纯函数 + 回写逻辑；结算重试语义用例 |
| 3 doctor 概览增强 | 账本概览补「已结算命中率 / 分品种命中率 / 未结算积压数」三块；转正评估与死线判定直接读该概览 | 迭代 2（需结算数据） | doctor 概览三块指标 + 判定读取路径 |
| 4 报告内反思块 | 行动建议章（HTML/Excel）追加「上期建议兑现情况」小节（上账本期的建议 + 结算结果），让「复盘→建议→下期对账」在报告内可见 | 迭代 2（数据就绪）；迭代 3 可并行 | 经 `_experimental_seams` 挂载点接入的双端小节 |

## 4. 与死线的关系（硬约束）

- 观测期（2 个发布周期）内上述迭代**不实施**；死线判定仍按 plan-70 原文执行。
- 若死线判定「撤销」，本设计随实验一并归档，不遗留半成品。
- 若判定「转正」，按迭代 1→4 执行，转正动作 = 注册表分组与默认值调整 + R-* 需求
  同步（plan-71 已写明同构流程）。

## 5. 数据来源衔接（前瞻）

plan-76 交易日志复盘落地后，decision_ledger（意图侧）与 trade_journal（成交侧）
互为对照：建议了但没做、做了但没建议、建议且做了——三类样本正是反思闭环的质量
指标。两项独立立项、只读对账，不互写（分层不重叠）。

## 6. 架构定位与依赖方向

| 构件 | 落点层 | 依赖方向与约束 |
|---|---|---|
| 决策条目可结算字段 | `core/decision_ledger`（既有写侧，契约版本 +1） | 落盘经 `core/jsonl_store.py` 原子原语（原子写入）；旧条目按「不可结算」跳过（同缓存载荷语义版本思路） |
| `decision_settlement` | analysis 纯计算 | 零 I/O：行情由调用方经 fetcher 网关备入后纯函数结算（Provider 多源链路必经，不 import `providers.*`）；建议后窗口以交易日计数（交易日计数）；收益/回撤指标复用 `whatif_backtest`/`metrics*` 原语，不新造引擎 |
| doctor 账本概览 | `core/doctor.py`（既有消费点） | 只读账本不写；输出走 `logging.getLogger("invest")`（日志统一） |
| 报告内反思块 | 行动建议章（HTML/Excel）双端 | **必须经 `report/_experimental_seams.py` 挂载点接入**（实验挂载点集中：实验功能异常不中断主链路；工序「结算先于 LLM 拉取」）；pipeline_data 键先入附录 H schema（pipeline_data 契约） |
| 开关与注册 | `config/features.py`（`decision_reflection` 既有） | 唯一登记点（开关注册表唯一）；转正 = 分组与默认值调整；转正前不进 `core/registry.py` 报告章节注册，避免注册漂移（LLM 模块注册 同构纪律） |

依赖方向单向：`report`/`core.doctor` → `analysis.decision_settlement`（纯函数）；
`analysis` 不反向 import `report`/`llm`；结算结果只回写账本与 pipeline_data，不碰
行情/新闻等其它状态。

## 7. 架构约束对照（逐条自查）

依据 `technical.md` §8「架构设计约束」逐条判定：✓ = 适用且本设计遵从；— = 不适用（附理由）。

| 约束 | 判定 | 遵从方式 / 不适用理由 |
|---|---|---|
| 原子写入 | ✓ | 账本回写经 `core/jsonl_store.py`（原子原语唯一实现），不自留 mkstemp 拷贝 |
| 会话级 API 复用 | ✓ | 同一建议日窗口行情同会话只取一次（会话缓存），不重复请求 |
| HTTP 客户端统一 | ✓ | 行情在 fetcher 层经工厂客户端（兼 cassette 回放注入点） |
| Provider Chain 必经 | ✓ | 行情经 `fetch_with_fallback`；analysis 结算函数零 I/O 不触网 |
| 报告序号不可硬编码 | ✓ | 反思块随行动建议章注册表，不写死序号 |
| 日志统一 | ✓ | 结算/概览输出走 `logging.getLogger("invest")` |
| 测试纪律（marker / edge 文件隔离 / 数据隔离） | ✓ | 每迭代用例带 marker、edge 入 `*_edge.py`、账本与配置路径测试隔离 |
| 渲染期数据不落全局 | ✓ | 反思块数据经 render context 传递，不进 `_ENV.globals` |
| pipeline_data 契约 | ✓ | 反思块数据键先入附录 H schema 再实现 |
| LLM 指纹单源 | ✓ | 兑现数据若进提示词，指纹由 `module_fingerprint.py` 构造（提示词承载哪段、指纹覆盖哪段） |
| 实验挂载点集中 | ✓ | 报告接入只经 `_experimental_seams.py`，工序「结算先于 LLM 拉取」 |
| 开关注册表唯一 | ✓ | 只用既有 `decision_reflection` 注册项，不另立清单 |
| 交易日计数 | ✓ | 建议日→窗口收益一律交易日计（`core/trading_calendar.py`） |
| **不适用汇总** | — | 代码类型判定（不判定资产代码类型）、缓存统一管理（不直写 `data/cache/`）、LLM 模块注册/路由/凭据分离（不新增 LLM 模块与调用面）、新闻召回不改（不涉新闻召回）、着色不改（不改着色器）、配置路径绝对化（无新增路径型配置键）、图下说明（反思块缺省无新图；若后续加图须带 `.chart-caption`）、凭据源纪律（不经手凭据）、重试统一/节流统一（无新增重试/节流点，由既有原语承担） |

## 8. 共享能力复用清单（防双实现）

| 能力 | 既有实现（符号） | 本设计复用方式 | 若重复实现的技术债 |
|---|---|---|---|
| 窗口收益/归一/回撤 | `analysis/whatif_backtest.py` + `analysis/metrics*` | 结算器直接调指标原语 | 第二套收益算法 → 口径漂移，两处修一漏一 |
| 行情获取 | `fetch_with_fallback()` | 调用方备入窗口序列 | 直连 provider → 熔断/fallback 失效（违反Provider 多源链路必经约束） |
| 交易日历 | `core/trading_calendar.py`（`count_trading_days_elapsed` 等） | 建议后 N 交易日窗口计算 | 自建日历 → 长假前后假告警（违反交易日计数约束） |
| 账本存取 | `core/jsonl_store.py` 原子原语 | 追加与结算回写 | 自留 mkstemp 拷贝 → 半写损坏 |
| 实验接入报告 | `report/_experimental_seams.py` | 迭代 4 反思块挂载 | 内联 try/except → 守护判据复制即源移 |
| doctor 概览 | `core/doctor.py` 账本概览（既有） | 迭代 3 增强三块指标 | 另开输出面 → 双处维护 |
| 启用观测 | `experiment_stats` + 死线判定读同一源 | 转正/撤销判定直接读 | 另立统计 → 两套口径互相矛盾 |

## 9. 技术债防线

1. **单文件红线**：新增/扩展文件受 `check-file-length.py --ci` 约束（主程序 ≤800 行），逼近即按职责拆子模块，不等破线补拆。
2. **语义命名**：`decision_settlement` 等语义名入「功能语义命名表」；任务代号不进代码/注释（`check-code-traces` + `check-semantic-index` 双脚本强制）。
3. **契约版本演进**：账本契约版本 +1，读侧把「版本不符」当未命中——旧条目永久兼容，不重写历史、不留静默误读（同缓存载荷语义版本规则）。
4. **状态单源**：账本唯一写侧为既有 `decision_ledger` 写入路径，不出现第二份 jsonl writer / 第二份统计。
5. **死线联动不留半成品**：观测期零实施；死线判「撤销」则本设计随实验归档，开关、注册、需求条目一并摘除，无残留分支。
6. **测试卫生**：新增用例过 `check-test-redundancy` 五类硬禁止；删并用例后同步 `test-coverage.md`/`folders.md` 计数。
7. **文档同步即门禁**：每迭代落地同回合同步五份文档，`check-doc-drift --ci` 绿才算迭代完；禁止「先代码后补文档」跨迭代欠账。
8. **迭代可独立合并**：每迭代结束 P0 门禁全绿、主干无挂起半成品；不跨迭代堆叠未验证改动。

## 12. 外部数据依赖与稳定性考察

**结论先行**：新增外部依赖仅一项——**建议日→窗口收益所需的品种行情**（经既有 provider 链路），无新增数据源、无新增凭据。

| 数据项 | 来源（链路） | 稳定性风险 | 考察/监测指标 | 降级与防护 |
|---|---|---|---|---|
| 建议日后 N 交易日窗口行情 | `fetch_with_fallback` 多源链（既有） | 单源故障、长假停牌、数据缺口 | 窗口行情 5 日缺口率（>30% 判数据不足）；chain 命中归属登记（既有诊断） | 数据不足 → 保持未结算下轮重试（不硬算）；熔断/fallback 既有治理 |
| 基准/基准序列（若用） | 同上 | 同上 | 同窗口缺口率 | 同上；缺则该条目不结算 |
| 账本数据 | 本地 `decision_ledger.jsonl` | 写侧契约演进 | 契约版本号；不可结算条目占比 | 版本不符按跳过计数，不误读 |

**判定动作**：doctor 概览「未结算积压数」连续 2 个发布周期上升 → 视为行情/账本稳定性退化，先排查再谈转正（转正判据的前置信号）；结算成功率（已结算 ÷ 应结算）作为稳定性量化指标随迭代 3 一并呈现。

## 13. 风险、回滚与文档同步义务

| 风险 | 影响 | 缓解 | 触发后的动作 |
|---|---|---|---|
| 观测期死线判「撤销」 | 本设计整体不实施 | 观测期零实施（§4 硬约束），无半成品可残留 | 设计随实验归档；开关/需求条目一并摘除 |
| 真实账本积累不足 | 结算命中率不可信、转正判据无据 | 死线已设 ≥10 条已结算样本门槛 | 样本不足 → 不转正，维持观测或撤销 |
| 行情缺口导致大面积未结算 | 闭环空转 | 数据不足保持未结算 + 下轮重试 | 积压连续上升 → 先排查数据链路再继续 |
| 结果误读为收益承诺 | 合规/用户误导 | 反思块只呈现「建议 vs 实际」事实，不出操作建议 | 文案审校入迭代 4 验收 |

**回滚策略**：① 迭代级——每迭代独立提交序列、独立验收，未过不合入；已合入迭代出问题 → 单次 revert 即回（无跨迭代耦合）。② 功能级——`decision_reflection` 开关关闭即回到现状（关态逐字节不变已由验收锁定）。③ 数据级——契约版本向后兼容，回滚不删历史账本、新版本写入的旧代码可读（未知字段忽略）。

**文档同步义务（每迭代同回同）**：`requirements.md`（需求条目与验收）、`technical.md`（语义命名表 + 架构约束落点）、`testplan.md`（测试载体）、`changelog.md`（变更记录）、`folders.md`/`test-coverage.md`（目录与用例计数，删并后必刷）；全部以 `check-doc-drift --ci` 0 finding 为完成判据。
