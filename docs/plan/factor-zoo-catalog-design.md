## 1. 动机与边界

`core/signal_ledger`（确定性信号账本）与风格因子分析的**信号源全靠手写注册**，
新增一个信号要新写算子+测试，边际成本高。Vibe-Trading 的 Alpha Zoo 真正可借鉴的
不是 462 个算子实现（其数据口径面向股票池、与本项目基金持仓穿透后的股票池部分
重合但引擎不同），而是**目录形态**：每个因子带元数据（来源族/类别/所需字段/文献
或出处），按需取用、可评测可淘汰。

**明确不搬**：算子代码不移植（数据口径/复权/停牌处理不同，移植即埋雷）；只评测
「目录 + 元数据 + 少量代表性因子的可计算性」。

## 2. 评测设计（go-no-go）

1. **选样**：从五个来源族各抽 5 个代表性因子（共 25 个），优先选字段需求简单的
   （动量/波动/换手率/量价背离类），回避需要分钟线/Level2/财务附注的。
2. **可计算性**：用穿透持仓股票池（既有持仓穿透模块输出）逐一验证：所需字段在
   我们行情/财务链路是否全部可得（走 `fetcher/chain.py`，禁裸调）。
   - 指标 A：字段可得率 ≥80%（25 个中 ≥20 个可完整计算）→ 过。
3. **增益评估**：可计算因子中，抽样计算近 1 年信号，与 `signal_ledger` 既有信号
   的相关性结构评估（新增信息增量，而非重复既有信号）。
   - 指标 B：≥30% 因子与既有信号族相关性 <0.5（有真实增量）→ 过。
4. **成本评估**：单轮全量计算耗时与缓存增量估算，须满足报告生成时间预算。
   - 指标 C：全量计算（含缓存冷启动）≤ 现有报告耗时增量 20% → 过。

**判定**：A/B/C 全过 → 转正立项实施（另起实现计划）；任一不过 → 归档未采纳，
评测脚本与数据落 `docs/tmp/`（git 忽略），仅结论入库。

## 3. 若转正，语义命名预案

| 语义名 | 层 | 说明 |
|---|---|---|
| `factor_catalog` | 契约 | 因子目录（slug/来源族/类别/所需字段列表/出处）唯一事实来源 |
| `factor_catalog_loader` | fetcher | 目录装载与版本校验 |
| `factor_evaluator` | analysis | 因子计算编排（复用 chain 链路 + 缓存） |
| `signal_ledger` | — | 只读对账：目录因子信号并入账本时走既有登记原语，不旁路 |

## 4. 纪律

- **分层不重叠**：目录因子是 signal_ledger 的**输入候选**，不替代既有信号注册
  机制；并入须走账本原语。
- **先决门槛唯一**：本文件本身就是门槛载体；评测未完成前不写任何生产代码。
- **评测产物隔离**：含真实持仓穿透数据，冻结产物只落 `docs/tmp/`，入库仅脱敏
  样例（与 plan-55 Jev 评测红线一致）。
