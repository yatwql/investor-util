# 因子动物园目录评测（factor_zoo_catalog）设计 —— plan-78

> **状态**：评测方案（先评测后立项；未达阈值归档为「已评估未采纳」）。
> **参照**：Vibe-Trading `agent/src/factors/zoo`（462 个预置 alpha 的目录与元数据：
> qlib158 / alpha101 / gtja191 / academic / fundamental 五个来源族）。
> **研究背景**：见 `vibe-trading-borrow-candidates-research.md` §2.1。

## 1. 动机与边界

`core/signal_ledger`（确定性信号账本）与风格因子分析的**信号源全靠手写注册**，
新增一个信号要新写算子+测试，边际成本高。Vibe-Trading 的 Alpha Zoo 真正可借鉴的
不是 462 个算子实现（其数据口径面向股票池、与本项目基金持仓穿透后的股票池部分
重合但引擎不同），而是**目录形态**：每个因子带元数据（来源族/类别/所需字段/文献
或出处），按需取用、可评测可淘汰。

**明确不搬**：算子代码不移植（数据口径/复权/停牌处理不同，移植即埋雷）；只评测
「目录 + 元数据 + 少量代表性因子的可计算性」。

## 2. 评测设计（go-no-go）

评测分四个迭代串行推进，每个迭代产出可核查中间物；全部产物落 `docs/tmp/`（git 忽略）。

| 迭代 | 范围 | 前置依赖 | 产出物 |
|---|---|---|---|
| 1 选样与冻结 | 从五个来源族各抽 5 个代表性因子（共 25 个），优先字段需求简单的（动量/波动/换手率/量价背离类），回避需要分钟线/Level2/财务附注的 | 无（起点） | 25 因子清单 + 所需字段表，冻结入库（可复算） |
| 2 字段可计算性（指标 A） | 用穿透持仓股票池逐一验证所需字段在行情/财务链路是否全可得（走 `fetcher/chain.py`，禁裸调）；**指标 A：字段可得率 ≥80%（25 个中 ≥20 个可完整计算）** | 迭代 1 | 字段可得率数字 + 不可得因子的原因分类 |
| 3 增益评估（指标 B） | 可计算因子中抽样计算近 1 年信号，与 `signal_ledger` 既有信号族做相关性结构评估；**指标 B：≥30% 因子与既有信号族相关性 <0.5** | 迭代 2 过线（A 不过则直接判定不采纳） | 相关性矩阵 + 增益因子清单 |
| 4 成本评估（指标 C） | 单轮全量计算耗时与缓存增量估算；**指标 C：全量计算（含缓存冷启动）≤ 现有报告耗时增量 20%** | 迭代 3 过线 | 耗时实测 + 缓存增量估算 |

**判定**：A/B/C 全过 → 转正立项实施（另起实现计划）；任一不过 → 归档未采纳，
评测脚本与数据落 `docs/tmp/`（git 忽略），仅结论入库。

## 3. 若转正，语义命名预案

| 语义名 | 层 | 说明 |
|---|---|---|
| `factor_catalog` | 契约 | 因子目录（slug/来源族/类别/所需字段列表/出处）唯一事实来源 |
| `factor_catalog_loader` | fetcher | 目录装载与版本校验 |
| `factor_evaluator` | analysis | 因子计算编排（复用 chain 链路 + 缓存） |
| `signal_ledger` | — | 只读对账：目录因子信号并入账本时走既有登记原语，不旁路 |

## 4. 纪律

- **分层不重叠**：目录因子是 signal_ledger 的**输入候选**，不替代既有信号注册
  机制；并入须走账本原语。
- **先决门槛唯一**：本文件本身就是门槛载体；评测未完成前不写任何生产代码。
- **评测产物隔离**：含真实持仓穿透数据，冻结产物只落 `docs/tmp/`，入库仅脱敏
  样例（与 plan-55 Jev 评测红线一致）。

## 5. 架构定位与依赖方向（评测期）

| 构件 | 落点层 | 依赖方向与约束 |
|---|---|---|
| 评测脚本 | `scripts/`（非生产代码，不进 `src/python/`） | 复用 `fetcher/chain.py` 取字段（多源降级/HTTP 工厂，禁裸调 provider）；不新建取数通道 |
| 字段可得性验证 | 既有行情/财务链路 | 经 `cache/` 既有 TTL 缓存复用数据（缓存统一管理），评测重复跑不重复打源 |
| 穿透持仓股票池 | 既有穿透模块输出 | 只读复用，不重算穿透（分层不重叠） |
| 评测产物 | `docs/tmp/`（git 忽略） | 不落 `data/cache/`、不写用户配置；结论回填 plan.md 与本文档 |
| （若转正）`factor_evaluator` | analysis 纯计算 | 计算经 chain 备数；信号并入 `signal_ledger` 走既有登记原语；开关经 `config/features.py`（开关注册表唯一） |

依赖方向：评测脚本 → `fetcher` 网关 → `chain`；脚本不 import `report`/`llm`，
不向生产模块注入任何代码——评测期与生产期物理隔离，未过门槛时生产侧零改动。

## 6. 架构约束对照（逐条自查）

依据 `technical.md` §8「架构设计约束」逐条判定（评测期直接生效；转正项标注传导）：✓ = 适用且遵从；— = 不适用（附理由）。

| 约束 | 判定 | 遵从方式 / 不适用理由 |
|---|---|---|

| HTTP 客户端统一 | ✓ | 一切字段取数经工厂客户端（兼 cassette 回放注入点） |
| Provider Chain 必经 | ✓ | 字段验证走 `fetch_with_fallback`，禁裸调 provider |
| 日志统一 | ✓ | 评测脚本输出走 `logging.getLogger("invest")`（或 argparse 输出面），不裸 print |
| 测试纪律（marker / edge 文件隔离 / 数据隔离） | ✓ | 评测脚本配套用例带 marker；edge 入 `*_edge.py`；穿透持仓数据测试只读、产物落 `docs/tmp/` |

| **不适用汇总** | — | 原子写入（评测不直接写状态文件；写则经 `atomic_write`）、会话级复用（评测单进程顺序取数）、报告序号注册表/渲染/契约/图示/挂载（评测期不进报告管线）、LLM 模块注册/新闻召回/LLM 路由/凭据分离/指纹单源（无 LLM 参与）、着色不改/配置路径绝对化（不涉着色与路径配置键）、凭据源纪律（不经手凭据）、重试统一/节流统一（无新增重试/节流点） |

## 7. 共享能力复用清单（防双实现）

| 能力 | 既有实现（符号） | 评测/未来实施复用方式 | 若重复实现的技术债 |

## 8. 技术债防线

1. **评测代码不固化**：评测脚本只住 `scripts/`，不 import 进 `src/python/` 生产链——未过门槛时生产侧零改动，防止评测半成品沉淀为无人维护的死代码。
2. **产物不入库**：冻结评测数据只落 `docs/tmp/`（git 忽略），仓库只留脱敏样例与结论——防真实持仓穿透数据入库。
3. **单源纪律（转正传导）**：若转正，因子目录是**唯一**事实来源（目录数据文件 + loader），禁在各处散落 dict 副本；信号并入只走 `signal_ledger` 原语。
4. **评测可复现**：选样清单、字段快照、指标 A/B/C 计算脚本与输入版本一并冻结（含取数日与缓存快照标识），半年后可复算同一结论。
5. **语义命名**：转正语义名（`factor_catalog` 等）入命名表；任务代号不进实现层（双脚本强制）。
6. **测试卫生**：评测脚本配套用例过 `check-test-redundancy` 五类；edge 入 `*_edge.py`。
7. **归档防回潮**：未过门槛则结论入 plan.md 归档为「已评估未采纳」+ 不采纳理由，后续周期不重复同一批研究（防重复劳动型技术债）。
8. **文档同步即门禁**：判定结论回填本文档与 plan.md 当回合完成，`check-doc-drift --ci` 绿。

## 9. 测试策略（按评测迭代）

通用纪律：用例标注 pytest marker（测试 marker）、edge 入 `*_edge.py`（edge 文件隔离）、穿透持仓与配置路径只读隔离（测试数据隔离）、行情/财务全 mock（网络守卫 socket 层拦截；评测正式跑数允许真网但用独立命令与缓存快照）、`check-test-redundancy --ci` 五类零违规。

| 迭代 | 测试类型 | 关键用例 | 隔离与 mock |
|---|---|---|---|
| 1 选样与冻结 | 单测 | 五族×5 抽样规则确定性（同种子同清单）、清单字段完整 | 纯清单逻辑，无 I/O |
| 2 字段可计算性（A） | 单测 + edge | 指标 A 计算自检（小 fixture 集手算：20/25 过线、19/25 不过线边界）；字段链路失败 → 因子标记不可得不崩溃 | 字段结果 fixture 注入；取数 mock；链路失败 edge 入 `*_edge.py` |
| 3 增益评估（B） | 单测 | 指标 B 计算自检（相关性 <0.5 计数、阈值边界）；空信号族降级 | 相关性输入 fixture；与既有信号族结果 mock |
| 4 成本评估（C） | 单测 + 实测记录 | 指标 C 计算自检（耗时增量 ≤20% 边界）；冷/热缓存两态 | 耗时基准取 testplan 对照口径；正式实测结果落 `docs/tmp/` |

## 10. 门槛判定与计分规则（量化）

| 指标 | 判定式 | 阈值 | 边界规则 |
|---|---|---|---|
| A 字段可得率 | 可完整计算因子数 ÷ 25 | ≥80%（即 ≥20/25） | 恰等算过；A 不过 → 提前终态，不进迭代 3/4 |
| B 信号增量 | 相关性 <0.5 的因子数 ÷ 可计算因子数 | ≥30% | 恰等算过；分母 <10 → 样本不足，判不通过 |
| C 耗时预算 | 冷启动全量耗时增量 ÷ 基线报告耗时 | ≤20% | 恰等算过；基准口径 = testplan 耗时对照表 |

- **判定形态**：A/B/C 三项全过 → 转正立项（另起实现计划）；任一不过 → 归档「已评估未采纳」（含三项实测数值与不采纳理由）。
- **可复算**：判定输入（25 因子清单、字段快照、取数日期）与计算脚本冻结于 `docs/tmp/`；复算输出与入库结论逐字段一致（数值、分子分母、阈值、判定）才算判定完成。
- **迭代验收**：每迭代退出时产出上表对应数值；迭代 1 产出清单完整性（五族×5 = 25 条，族内可追溯到出处）；全部判定记录随 `check-doc-drift --ci` 0 finding 收口。

## 11. 外部数据依赖与稳定性考察

**结论先行**：评测本身即稳定性考察——核心风险不是「数据源宕机」而是 **字段口径随时间与源演进的可得性漂移**；取数全部经既有链路，无新增数据源与凭据。

| 数据项 | 来源（链路） | 稳定性风险 | 考察/监测指标 | 降级与防护 |
|---|---|---|---|---|
| 因子所需行情字段（OHLC/成交量/换手等） | `fetch_with_fallback` 多源链（既有） | 单源故障、字段改名、复权口径变更 | 指标 A 字段可得率（≥80% 为门槛）；chain 命中归属与失败原因分类（既有诊断） | 不可得 → 因子记不可得并分类原因；禁硬凑字段 |
| 财务/基本面字段（若样本涉） | 既有财报链路 | 财报披露节奏、字段缺失 | 同 A 分母统计 | 同上 |
| 穿透持仓股票池 | 既有穿透模块输出 | 持仓变动导致样本漂移 | 评测冻结快照（取数日 + 输入版本） | 快照冻结保证可复算；不随实时持仓漂移 |

**判定动作**：指标 A 的分子分母与不可得原因分类表一并入库（不只记百分比）——若多数不可得集中在单一源故障，判定书应区分「口径不可得」与「源暂不可用」，后者不直接否决（可复评）；转正后同一监测作为运行期告警（因子计算失败率）。
