# 交易日志复盘（trade_journal_review）设计 —— plan-76

> **状态**：设计 + 待评测（先决门槛未过不实施）。
> **参照**：Vibe-Trading `agent/src/skills/trade-journal`（journal schema 与归因分析）+ `agent/src/shadow_account`（extract→render 闭环形态）。
> **研究背景**：见 `vibe-trading-borrow-candidates-research.md` §2.1。

## 1. 动机与价值

当前输入只有**持仓快照**（每 worksheet 一个账户、固定 4 列），系统知道「你现在持有什
么」，不知道「你做过什么、为什么做」——买卖历史从未被结构化复盘。交易日志复盘把
成交记录变成可度量对象：胜率/盈亏比/持有期/买卖点质量/与信号账本对账，是 LLM 智
囊团复盘从「宏观局势评述」下沉到「你的具体操作」的关键输入，也是 plan-70 决策反思
闭环的真实成交侧数据源。

## 2. 先决门槛（go-no-go，未过则归档未采纳）

1. **数据可得性**：用户须愿意维护交易日志文件（半手工）。以 1 个真实账户 ≥3 个月、
   ≥20 笔成交的样本验证解析管线，字段缺失率 >20% 即判定不可行。
2. **口径可判定**：持有期/盈亏口径（ Fees 是否计入成本、分红如何处理）有唯一可
   解释定义，且与报告其他章（持仓穿透成本列）不矛盾。
3. **价值验证**：样本跑出的复盘指标（胜率/盈亏比）经用户确认「说得对、有启发」
   （人工比对标，仿 plan-71 转正判据 ②）。

## 3. 语义命名（先定名再设计）

| 语义名 | 层 | 说明 |
|---|---|---|
| `trade_journal` | 契约 | 日志解析后的标准成交记录结构（dataclass/dict 契约） |
| `journal_loader` | fetcher | Excel/CSV 日志 → `trade_journal` 契约（校验/容错/口径归一） |
| `journal_metrics` | analysis | 纯计算：胜率/盈亏比/持有期/回撤贡献/集中度变化 |
| `journal_review` | report | Excel/HTML 复盘章装配（含 LLM 归因块） |
| `journal_llm_review` | llm | LLM 归因 prompt 组（买卖点质量/与既有信号对账） |

## 4. 输入格式约定

新输入文件 `data/holdings/` 同级新目录暂不考虑——日志非持仓，放 `data/trade_journal/`
（git 忽略规则与 holdings 相同）。xlsx，每 worksheet 一个账户，固定列（列名不可配置，
与持仓格式纪律一致）：

| 列 | 必填 | 说明 |
|---|---|---|
| 日期 | ✓ | 成交日（YYYY-MM-DD） |
| 名称 / 代码 | ✓ | 与持仓格式同一代码口径 |
| 方向 | ✓ | 申购/赎回（基金口径，对应买入/卖出） |
| 份额 / 单价 | ✓ | 单价 = 成交净值 |
| 费用 | ✗ | 申购费/赎回费，缺省按 0 |
| 理由 | ✗ | 用户自由文本，LLM 归因输入；缺省空 |

不破坏既有持仓 4 列约定；日志文件缺席时整个特性静默关闭（与 whatif 无输入时同构）。

## 5. 迭代设计

- **迭代 1 — 解析与契约**：`journal_loader`（列校验/日期与代码口径归一/费用缺省）+
  契约单测。门禁：P0 十项。
- **迭代 2 — 指标纯计算**：`journal_metrics`（胜率/盈亏比/平均持有期/最大单笔亏损/
  与持仓快照对账差异——日志推得持仓 vs 用户申报持仓，差额列出）。纯函数、离线、
  可单测。
- **迭代 3 — 报告双端**：`journal_review` Excel 区块 + HTML 章（含「日志↔持仓对账
  差异表」）；开关 `trade_journal_review` 注册（默认关，实验组）。
- **迭代 4 — LLM 归因**：`journal_llm_review` prompt 组（买卖点质量 + 与
  `signal_ledger` 历史信号对账：当时信号说什么、实际怎么做），进统一附录（指纹
  携带，仿 plan-73 约束块单源纪律）+ 降级矩阵（无 LLM 时章隐藏）。
- **迭代 5 — 文档登记**：requirements / technical / testplan / manuals 同步 + P0 门禁。

## 6. 红线与约束

- **不重叠**：decision_ledger（LLM 决策登记）与本特性是「意图 vs 成交」两侧，只读
  对账、不互写；signal_ledger 只读。
- **降级**：日志字段非法 → 行级跳过 + 计数告警，不中断报告；LLM 缺席 → 无量化
  指标照常出，LLM 块隐藏。
- **隐私**：日志含真实成交，报告产物留在本地 `reports/`，不外传（LLM 调用仅发送
  必要摘要字段，与现网纪律一致）。
- **测试纪律**：全部 mock/临时文件；网络层既有守卫生效；新增 marker 注册 conftest。

## 7. 验收标准

1. 样本日志（fixture 构造 3 账户混合：正常/缺费用/非法行）指标与手算一致；
2. 日志↔持仓对账差异表正确列出缺笔/多笔；
3. LLM 归因块降级时逐字节回退；
4. P0 门禁十项全绿；文档五份同步。
