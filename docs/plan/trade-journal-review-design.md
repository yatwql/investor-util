# 交易日志复盘（trade_journal_review）设计 —— plan-76

> **状态**：设计 + 待评测（先决门槛未过不实施）。
> **参照**：Vibe-Trading `agent/src/skills/trade-journal`（journal schema 与归因分析）+ `agent/src/shadow_account`（extract→render 闭环形态）。
> **研究背景**：见 `vibe-trading-borrow-candidates-research.md` §2.1。

## 1. 动机与价值

当前输入只有**持仓快照**（每 worksheet 一个账户、固定 4 列），系统知道「你现在持有什
么」，不知道「你做过什么、为什么做」——买卖历史从未被结构化复盘。交易日志复盘把
成交记录变成可度量对象：胜率/盈亏比/持有期/买卖点质量/与信号账本对账，是 LLM 智
囊团复盘从「宏观局势评述」下沉到「你的具体操作」的关键输入，也是 plan-70 决策反思
闭环的真实成交侧数据源。

## 2. 先决门槛（go-no-go，未过则归档未采纳）

1. **数据可得性**：用户须愿意维护交易日志文件（半手工）。以 1 个真实账户 ≥3 个月、
   ≥20 笔成交的样本验证解析管线，字段缺失率 >20% 即判定不可行。
2. **口径可判定**：持有期/盈亏口径（ Fees 是否计入成本、分红如何处理）有唯一可
   解释定义，且与报告其他章（持仓穿透成本列）不矛盾。
3. **价值验证**：样本跑出的复盘指标（胜率/盈亏比）经用户确认「说得对、有启发」
   （人工比对标，仿 plan-71 转正判据 ②）。

## 3. 语义命名（先定名再设计）

| 语义名 | 层 | 说明 |
|---|---|---|
| `trade_journal` | 契约 | 日志解析后的标准成交记录结构（dataclass/dict 契约） |
| `journal_loader` | fetcher | Excel/CSV 日志 → `trade_journal` 契约（校验/容错/口径归一） |
| `journal_metrics` | analysis | 纯计算：胜率/盈亏比/持有期/回撤贡献/集中度变化 |
| `journal_review` | report | Excel/HTML 复盘章装配（含 LLM 归因块） |
| `journal_llm_review` | llm | LLM 归因 prompt 组（买卖点质量/与既有信号对账） |

## 4. 输入格式约定

新输入文件 `data/holdings/` 同级新目录暂不考虑——日志非持仓，放 `data/trade_journal/`
（git 忽略规则与 holdings 相同）。xlsx，每 worksheet 一个账户，固定列（列名不可配置，
与持仓格式纪律一致）：

| 列 | 必填 | 说明 |
|---|---|---|
| 日期 | ✓ | 成交日（YYYY-MM-DD） |
| 名称 / 代码 | ✓ | 与持仓格式同一代码口径 |
| 方向 | ✓ | 申购/赎回（基金口径，对应买入/卖出） |
| 份额 / 单价 | ✓ | 单价 = 成交净值 |
| 费用 | ✗ | 申购费/赎回费，缺省按 0 |
| 理由 | ✗ | 用户自由文本，LLM 归因输入；缺省空 |

不破坏既有持仓 4 列约定；日志文件缺席时整个特性静默关闭（与 whatif 无输入时同构）。

## 6. 红线与约束

- **不重叠**：decision_ledger（LLM 决策登记）与本特性是「意图 vs 成交」两侧，只读
  对账、不互写；signal_ledger 只读。
- **降级**：日志字段非法 → 行级跳过 + 计数告警，不中断报告；LLM 缺席 → 无量化
  指标照常出，LLM 块隐藏。
- **隐私**：日志含真实成交，报告产物留在本地 `reports/`，不外传（LLM 调用仅发送
  必要摘要字段，与现网纪律一致）。
- **测试纪律**：全部 mock/临时文件；网络层既有守卫生效；新增 marker 注册 conftest。

## 8. 架构定位与依赖方向

| 构件 | 落点层 | 依赖方向与约束 |
|---|---|---|
| `journal_loader` | 本地文件解析（与 `core/reader.py` 同族） | **零网络**：不注册进 provider 链路、不经熔断；xslx 解析异常行级容错；落盘类产物经 `core/atomic_write.py` 原语（原子写入） |
| `journal_metrics` | analysis 纯计算 | 零 I/O；持有期一律交易日计数（交易日计数，经 `core/trading_calendar.py`）；盈亏/回撤复用 `metrics*` 原语不新造 |
| `journal_review` | report 双端 | 章节序号经 `core/registry.py`（报告序号注册表）；pipeline_data 键先入附录 H（pipeline_data 契约）；图表带 `.chart-caption`（图下说明）；**默认关的实验章经 `report/_experimental_seams.py` 挂载点接入**（实验挂载点集中） |
| `journal_llm_review` | llm | 指纹经 `module_fingerprint.py` 单源构造（LLM 指纹单源）；调用走 Provider Chain（LLM 路由统一）；若独立成模块须在 `_llm_dispatch._MODULE_FNS` 与 `core/registry.py` 双注册（LLM 模块注册） |
| 开关 `trade_journal_review` | `config/features.py` | 唯一登记点（开关注册表唯一），实验组默认关 + experiment_stats 观测 |
| 日志文件目录 `data/trade_journal/` | 本地状态数据 | 与 `data/holdings/` 同等只读纪律：测试隔离（测试数据隔离）、不入 git |

依赖方向：`report` → `analysis.journal_metrics`（纯函数）← `journal_loader` 备数；
`llm` 只消费 pipeline_data 摘要字段；`analysis` 不 import `report`/`llm`；
decision_ledger / signal_ledger 均只读对账，不互写。

## 11. 技术债防线

1. **日志格式契约版本化**：列结构变更 = 契约版本 +1，读侧「版本不符」按行跳过并计数告警，不重写用户历史文件、不静默误读。
2. **口径单源**：持有期/盈亏/费用口径在**一处**定义（文档 + 代码同一份），与持仓穿透成本列不矛盾（先决门槛 2 的持续约束）；对账 diff 复用 `whatif.py` 合并原语，不写第二套。
3. **单文件红线**：`journal_loader`/`journal_metrics`/`journal_review` 受 800 行红线守护，逼近即拆。
4. **LLM 块不污染缓存**：归因入参与指纹同源（LLM 指纹单源）；降级态提示词与缓存键双不变（同 plan-73 纪律），避免「开关看似生效实则全量重调」。
5. **静默容错可见**：行级跳过必带计数告警（不吞错）；容错率超阈值在报告中显式呈现，不把坏输入伪装成空数据。
6. **开关可撤销**：experiment_stats 观测不足 → 开关/章/需求条目一并摘除，不留僵尸分支（转正才进注册表）。
7. **测试卫生与计数同步**：过 `check-test-redundancy` 五类；删并后同步 `test-coverage.md`/`folders.md` 计数；`data/trade_journal/` 真实日志测试只读（测试数据隔离）。
8. **文档同步即门禁**：每迭代同回合同步五份文档，`check-doc-drift --ci` 绿才算完；迭代可独立合并（P0 全绿）。

## 13. 外部数据依赖与稳定性考察

**结论先行**：**无新增外部数据源**——日志是用户本地文件、指标是纯计算、交易日历在本地；外部依赖仅剩既有的 LLM 调用链（多链降级与熔断已由既有体系治理）。

| 数据项 | 来源 | 稳定性风险 | 考察/监测指标 | 降级与防护 |
|---|---|---|---|---|
| 交易日志文件 | 用户半手工维护（`data/trade_journal/`） | **维护节奏中断、字段缺失、格式漂移**（本特性最大稳定性风险） | 先决门槛 1：样本 ≥20 笔、字段缺失率 ≤20%；运行期解析层行级跳过计数与缺失率持续回显 | 缺失率超阈 → 报告显式标注样本不足，指标置灰而非硬算；格式变更走契约版本 +1 |
| 持仓快照（对账基准） | 既有持仓读入 | 用户持仓文件变动 | 对账差异表本身即呈现 | 差异表只读展示，不回写 |
| LLM 归因 | 既有 Provider Chain（多链降级/熔断） | 端点故障/配额 | 既有 429 诊断与 pacing 回显 | 无 LLM → 归因块隐藏，量化照常（降级矩阵） |
| 交易日历 | `core/trading_calendar.py`（本地） | — | — | 持有期一律经此计数 |

**判定动作**：运行期字段缺失率连续 2 次报告 >20% → 在报告中提示「日志质量退化，建议补录」；真实日志文件永远只读（测试与运行均不回写）。

## 14. 风险、回滚与文档同步义务

| 风险 | 影响 | 缓解 | 触发后的动作 |
|---|---|---|---|
| 用户停止维护日志 | 样本不足、指标失真 | 缺失率持续回显；样本不足显式标注 | 提示补录；不拿失真样本出结论 |
| 字段缺失率 >20%（先决门槛 1） | 特性不可行 | 解析层行级跳过计数 + 缺失率量化 | 归档未采纳 |
| 指标口径与持仓穿透成本列矛盾 | 两处结论互斥（门槛 2） | 口径单源定义 + 对账差异表暴露 | 发现矛盾 → 先修口径再继续 |
| 日志隐私外泄 | 用户成交数据暴露 | 产物本地 `reports/`；LLM 仅发必要摘要 | 审计发送字段清单入迭代 4 验收 |
| LLM 归因不可用 | 归因块缺失 | 降级矩阵（量化照常） | 章隐藏不阻塞，既有链路治理 |
