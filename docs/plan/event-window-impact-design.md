# 事件窗量化对照（event_window_impact）设计 —— plan-79

> **状态**：设计 + 待评测（先决门槛未过不实施）。
> **参照**：gs-quant `timeseries/event_study.py`（`frame_timeseries_around_events` 事件×序列对齐切窗、`event_impact_analysis` 窗口影响度量的纯函数拆分）。
> **研究背景**：见 `gs-quant-borrow-candidates-research.md` §2.1。

## 1. 动机与价值

新闻关联分析（`news_correlation` / Jev 判定通道）回答「**文本上**这条新闻与持仓是否相关」，从不回答「**数据上**事件发生后持仓真的动了吗」。两者互证才闭环：LLM 说「利好」而事件窗收益为负，恰是复盘最该暴露的分歧点，也是 `fact_checker` 的事实锚。gs-quant 的事件研究把「事件×时间序列」对齐、切窗、影响度量拆成可单测纯函数，这套口径可直接移植到本仓库的持仓+行情数据上。

## 2. 先决门槛（go-no-go，未过则归档未采纳）

1. **事件日期结构化可得**：既有新闻链路的日期字段（关联新闻表）抽检 20 条，结构化可用率 ≥80%；不足则先补新闻元数据，不进入本特性。
2. **窗口口径可判定**：事件日 T（新闻日期→最近交易日映射）、窗口默认 ±5 交易日、基准（持仓品种所属宽基指数）对齐规则唯一且文档化；停牌/缺失按 LOCF+标注，绝不硬算。
3. **增益验证**：抽 10 个既有报告中的关联新闻事件，量化结论与文本判定「方向一致或分歧可解释」≥7 例（人工比对，仿 plan-71 判据 ②）。

## 3. 语义命名（先定名再设计）

| 语义名 | 层 | 说明 |
|---|---|---|
| `event_window_impact` | analysis | 纯计算：事件日期 + 品种序列 + 基准序列 → 窗口对齐、超额收益、方向一致标记 |
| `event_impact_panel` | report | Excel/HTML 事件窗对照表（事件 × 窗口收益 × 文本判定列） |
| `event_impact_review` | llm | 事件窗分歧点注入新闻关联 LLM 块（单源块纪律，同 plan-73） |
| 开关 `event_window_impact` | config | 默认关（实验组，experiment_stats 观测） |

## 4. 迭代设计

四个迭代串行推进，每个迭代单独可合并（P0 门禁绿）；前置依赖未满足不得开工。

| 迭代 | 范围 | 前置依赖 | 产出物 |
|---|---|---|---|
| 1 契约与纯计算 | `event_window_impact`：事件日→交易日对齐、T±N 切窗、LOCF 缺失处理、超额=品种收益−基准收益、方向一致标记 = sign(窗口收益) vs 文本极性；全纯函数、零 I/O | 先决门槛 2（窗口口径文档化） | 对齐/度量纯函数 + fixture 手算对照 |
| 2 事件表编排 | 新闻链路既有日期字段 → `event_item`（日期/品种/关联新闻 id/文本极性）组装；行情窗口取数走 `fetcher/chain.py`（多源降级）；数据不足 → `available=false` 章隐藏 | 迭代 1（契约定型）；先决门槛 1（日期字段可用率） | 事件表组装 + 取数降级链路 |
| 3 报告双端 + LLM 注入 | `event_impact_panel`（Excel 区块 + HTML 章，含「文本判定 vs 量化方向」一致/分歧列）；分歧例进 `event_impact_review` 注入新闻关联 LLM 块（指纹携带，降级时只出表不出段落） | 迭代 2（事件表就绪） | 双端面板 + LLM 注入块 + 降级形态 |
| 4 验收与文档 | 先决门槛三项判定 + 五份文档同步 + P0 门禁 | 迭代 1~3 全绿 | 门槛判定记录 + 文档同步 |

## 5. 红线与约束

- **分层不重叠**：文本相关性判定归 Jev 通道（plan-55），本模块只做数据侧窗口度量，**不做文本判定**；`crisis_annotation` 图表注记不复用不互写。
- **降级**：窗口内行情缺失 >30% 或基准不可得 → 该事件不出行（计入告警计数），不阻塞报告。
- **开关纪律**：默认关；开/关两态输出差异有回归用例（关态逐字节不变）。
- **测试纪律**：fixture 构造事件表（正常/停牌/缺基准/极性冲突），全部 mock 行情；网络守卫既有机制生效。

## 6. 验收标准（按迭代量化）

每个迭代全项满足才算通过；未过不得进入下一迭代。

| 迭代 | 量化验收标准 |
|---|---|
| 1 契约与纯计算 | 窗口切分与手算一致（容差 0，含 T 落非交易日、停牌 LOCF、缺基准、极性冲突，每类 ≥2 例，合计 ≥10 例）；纯函数零 I/O 断言；新增单测 ≥10 项全绿 |
| 2 事件表编排 | 先决门槛 1 判定：日期字段抽 20 条结构化可用率 ≥80%；行情缺失 >30% → 该事件不出行且告警计数 = 缺失事件数；`available=false` 传导用例全绿 |
| 3 报告双端 + LLM 注入 | fixture 分歧例进入注入块召回率 100%；分歧例正确进入 LLM 块且关态逐字节回退（哈希比对）；双端一致断言全绿；先决门槛 3 判定：10 例人工比对「方向一致或分歧可解释」≥7 |
| 4 验收与文档 | 先决门槛三项判定记录入评测文档；P0 `test-runner.py --mode dev-verify` 0 失败；五份文档同步后 `check-doc-drift --ci` 0 finding |

## 7. 架构定位与依赖方向

| 构件 | 落点层 | 依赖方向与约束 |
|---|---|---|
| `event_window_impact` | analysis 纯计算 | 零 I/O、零 LLM：事件表与窗口行情由编排层备入，函数不取数 |
| 事件表组装 | 既有新闻关联链路的消费侧 | 只读 `news_correlation` 落盘字段，不回写、不与 Jev 判定通道互写 |
| 行情窗口取数 | `fetcher/chain.py` 网关 | 经 Chain 多源降级与熔断（Provider 多源链路必经），禁 `providers.*` 直连；HTTP 经 `core/http_client.py` 工厂（HTTP 客户端统一，兼作 cassette 回放注入点） |
| 事件日→交易日映射、±N 窗口 | `core/trading_calendar.py` | 一律交易日计数（交易日计数），禁自建日历或自然日差 |
| `event_impact_panel` | report 双端 | 章节序号/可见性经 `core/registry.py` 注册表（报告序号注册表）；pipeline_data 键先入附录 H schema（pipeline_data 契约）；图表带 `.chart-caption`（图下说明） |
| `event_impact_review` | llm 注入块 | 指纹经 `llm/module_fingerprint.py` 单源构造（LLM 指纹单源）；调用走 Provider Chain（LLM 路由统一） |
| 开关 `event_window_impact` | `config/features.py` | 唯一登记点（开关注册表唯一），默认关 + experiment_stats 观测 |

依赖方向：`report` → `analysis.event_window_impact`（纯函数）← 数据由 `fetcher` 备入；
`analysis` 不 import `report`/`llm`；LLM 注入只消费 pipeline_data 中的分歧例，不反向写回分析层。

## 8. 架构约束对照（逐条自查）

依据 `technical.md` §8「架构设计约束」逐条判定：✓ = 适用且本设计遵从；— = 不适用（附理由）。

| 约束 | 判定 | 遵从方式 / 不适用理由 |
|---|---|---|
| 原子写入 | ✓ | 窗口序列/面板中间产物若落盘经 `core/atomic_write.py`，不直接覆写 |
| 会话级 API 复用 | ✓ | 同一事件窗口行情同会话只取一次，多模块共用 |
| HTTP 客户端统一 | ✓ | 窗口行情 HTTP 经工厂客户端（兼 cassette 回放注入点） |
| Provider Chain 必经 | ✓ | 行情经 `fetch_with_fallback` 多源降级；analysis 纯函数零 I/O |
| 报告序号不可硬编码 | ✓ | 事件窗面板序号/可见性经 `core/registry.py` 注册表 |
| 日志统一 | ✓ | 组装/降级告警走 `logging.getLogger("invest")` |
| 测试纪律（marker / edge 文件隔离 / 数据隔离） | ✓ | 用例带 marker；停牌/缺基准等 edge 入 `*_edge.py`；fixture 不碰真实配置与持仓 |
| 渲染期数据不落全局 | ✓ | 面板数据经 render context 传递 |
| pipeline_data 契约 | ✓ | 事件表/面板数据键先入附录 H schema 再实现 |
| 图下说明 | ✓ | 事件窗对照图带 `.chart-caption`，随渲染分支同现 |
| LLM 指纹单源 | ✓ | 分歧例注入块的指纹由 `module_fingerprint.py` 构造 |
| 实验挂载点集中 | ✓ | 章接入经 `_experimental_seams.py`，实验异常不中断主链路 |
| 开关注册表唯一 | ✓ | `event_window_impact` 只在 `config/features.py` 登记 |
| 交易日计数 | ✓ | 事件日→交易日映射、±5 窗口、基准对齐全交易日计 |
| **不适用汇总** | — | 代码类型判定（代码路由判定在 chain 既有，本模块不新增判定）、缓存统一管理（不直写缓存文件）、LLM 模块注册/路由/凭据分离（注入既有新闻关联 LLM 块，不新增模块与调用面）、新闻召回不改（不改新闻召回）、着色不改/配置路径绝对化（不涉着色与路径配置）、凭据源纪律（不经手凭据）、重试统一/节流统一（退避/节流由 chain 与 pacing 既有原语承担） |

## 9. 共享能力复用清单（防双实现）

| 能力 | 既有实现（符号） | 本设计复用方式 | 若重复实现的技术债 |
|---|---|---|---|
| 对齐/切窗/LOCF 口径 | `analysis/whatif_backtest.py`（并集+LOCF 对齐） | 事件窗对齐复用同一 LOCF/并集原语 | 第二套对齐 → 同一持仓两处窗口结果不一致 |
| 收益/超额/方向判定 | `analysis/metrics*` 原语 | 超额=品种收益−基准收益由原语拼装 | 自写收益公式 → 口径漂移 |
| 交易日历与窗口 | `core/trading_calendar.py` | 事件日→交易日、±5 窗口 | 自建日历 → 长假假告警（违反交易日计数约束） |
| 行情获取 | `fetch_with_fallback()` | 窗口序列经 chain 备入 | 直连 provider → 熔断/fallback 失效 |
| 新闻日期/极性字段 | `news_correlation` 既有落盘字段 | 只读组装事件表 | 第二套新闻元数据存储 → 双源漂移 |
| 指数行情入口 | `fetcher/index.py`（双链路例外入口） | 基准序列经既有指数入口取 | 自建指数取数 → 旁路既有双链路 |
| 章接入 | `_experimental_seams.py` + `core/registry.py` | 实验期挂载、转正后注册 | 内联守护/硬编码序号（违反实验挂载点集中/报告序号注册表约束） |

## 10. 技术债防线

1. **单文件红线**：`event_window_impact`/`event_impact_panel` 受 800 行红线守护，逼近即拆。
2. **语义命名**：三个语义名入「功能语义命名表」；任务代号不进实现层（双脚本强制）。
3. **口径单源**：对齐/LOCF/归一/超额计算只有一份实现（复用 `whatif_backtest`/`metrics*`）；窗口参数（±N、映射规则）只在一处配置化定义，面板与 LLM 注入读同一份。
4. **事件表不双写**：事件表由既有新闻落盘字段组装，不新建第二份新闻元数据存储；字段升级则 schema 版本化（旧条目按不可用跳过）。
5. **开关转正可撤销**：experiment_stats 观测不足或门槛复评不过 → 开关与章一并摘除，不留默认关僵尸分支；转正才进 `core/registry.py` 章节注册。
6. **测试卫生 + 计数同步**：过 `check-test-redundancy` 五类；删并后同步 `test-coverage.md`/`folders.md` 计数。
7. **文档同步即门禁**：迭代落地同回合同步五份文档，`check-doc-drift --ci` 绿才算完。
8. **迭代可独立合并**：每迭代 P0 门禁全绿再进下一迭代，不堆叠未验证改动。

## 12. 外部数据依赖与稳定性考察

**结论先行**：两项外部依赖——**窗口行情（含基准指数）** 与 **上游新闻聚合源的日期字段质量**（字段本身落本地，但上游源结构会变）；均经既有链路，无新增数据源与凭据。

| 数据项 | 来源（链路） | 稳定性风险 | 考察/监测指标 | 降级与防护 |
|---|---|---|---|---|
| 事件窗行情 | `fetch_with_fallback` 多源链（既有） | 单源故障、停牌、长窗口缺口 | 窗口行情缺失率（>30% → 该事件不出行）；chain 命中归属登记（既有诊断） | LOCF + 标注；缺则告警计数，不硬算 |
| 基准指数序列 | `fetcher/index.py` 双链路例外入口 | 指数源变更 | 同上 | 缺则该事件降级不出行 |
| 新闻日期字段 | `news_correlation` 既有落盘（上游聚合源） | 上游改版导致日期格式漂移、字段缺失 | **先决门槛 1：抽 20 条可用率 ≥80%（首轮判定）**；运行期以事件表组装时的字段跳过计数持续监测 | 可用率 <80% → 不进入本特性（先补元数据）；运行期跳过计数异常升高 → 告警提示源变更 |
| 交易日历 | `core/trading_calendar.py`（本地） | 长假/休市 | — | 事件日→交易日映射唯一经此，禁自建 |

**判定动作**：先决门槛 1 在迭代 2 入口复测一次（不只首轮）；运行期任一监测指标越阈，降级路径优先（章隐藏/事件不出行），绝不为凑数硬算；稳定性结论随迭代 4 判定记录归档。

## 13. 风险、回滚与文档同步义务

| 风险 | 影响 | 缓解 | 触发后的动作 |
|---|---|---|---|
| 日期可用率 <80%（先决门槛 1） | 特性整体不可行 | 迭代 2 入口复测前置 | 归档未采纳，先补新闻元数据 |
| 文本判定与量化方向大面积分歧 | 误报淹没真分歧点 | 门槛 3（10 例 ≥7 一致或可解释）先行验证 | 一致率不达 → 复评窗口口径或归档 |
| 行情缺口/停牌处理不当 | 窗口收益失真 | LOCF+标注、缺口 >30% 不出行 | 只降级不硬算；告警计数呈现 |
| LLM 注入块污染既有缓存 | 全量重调、费用翻倍 | 指纹单源（LLM 指纹单源）+ 降级态键不变 | 指纹回归用例拦截，不在运行期发现 |

**回滚策略**：① 迭代级——每迭代独立提交、独立验收，未过不合入，出问题单次 revert。② 功能级——`event_window_impact` 开关关闭即回现状（关态逐字节不变已由验收锁定）。③ 数据级——事件表为组装态不落新持久源，回滚无残留数据。

**文档同步义务（每迭代同回同）**：`requirements.md`、`technical.md`（语义命名表 + 约束落点）、`testplan.md`（载体）、`changelog.md`、`folders.md`/`test-coverage.md`（计数）；完成判据 = `check-doc-drift --ci` 0 finding。
