# What-if 回放成本建模与基准对比设计 —— plan-77

> **状态**：设计 + 待评测（先决门槛未过不实施）。
> **参照**：Vibe-Trading `agent/backtest/factor_costs.py`（成本因子）+ `benchmark.py`（基准对比面板）+ `constraints.py`；成本分层（Constant/Scaled/Aggregate）与 PnL 分解语义参照 gs-quant `backtests/backtest_objects.py`（`TransactionModel`/`PnlAttribute`，见 gs-quant 借鉴批研究文档）。
> **研究背景**：见 `vibe-trading-borrow-candidates-research.md` §2.1。

## 1. 动机与问题

`analysis/whatif_backtest.py` 已支持指定生效日的窗口回测（收益/年化/波动/夏普/最大
回撤，基准持仓 vs 目标持仓 as-if 归一化对比），但有两个系统性偏差：

1. **无交易成本**：基金调仓真实发生申购费/赎回费（且与持有期强相关——赎回费常按
   持有期阶梯减免）。现状回测把调仓收益系统性高估，持有期越短高估越狠，恰是
   what-if 最该警示的频繁调仓场景。
2. **无基准对比**：只有「调 vs 不调」两侧对比，没有「两侧都跑赢/跑输业绩基准多
   少」的第三方参照，用户无法判断差异是否显著。

Vibe-Trading 的 factor_costs（成本计入回放）与 benchmark（自动选基准 + 同图对比）
正好补齐这两块，且其 zero-dependency 设计与我们离线纪律兼容。

## 2. 先决门槛（go-no-go）

1. **费率数据可得性**：目标基金申赎费率必须可取得（天天基金申购状态 provider
   已有同源页面；或用户配置表兜底）。抽样 20 只既有持仓基金，费率字段取得率
   <80% → 降级为「用户配置表单源」或归档。
2. **口径可判定**：赎回费阶梯按「份额持有期」逐笔判定（先进先出），口径唯一且
   文档化；无法逐笔判定时明确标注近似（按平均持有期）。
3. **增益验证**：成本计入后，对既有 fixture 场景回测结论发生「方向性翻转」的
   案例 ≥1 个且经人工复核合理（证明不是无感装饰）。

## 3. 语义命名

| 语义名 | 层 | 说明 |
|---|---|---|
| `redemption_fee_schedule` | 契约 | 赎回费阶梯（持有期下界 → 费率）+ 申购费率 |
| `trade_cost_model` | analysis | 纯计算：给定买卖明细+费率表 → 成本金额/成本后收益序列 |
| `benchmark_index_resolver` | analysis | 目标持仓 → 基准指数映射（宽基默认，可配置覆盖） |
| `whatif_cost_panel` | report | 成本对比面板（成本前/后收益差 + 基准三线图数据） |
| 开关 `whatif_trade_cost` | config | 默认关；成本不计入时行为逐字节不变 |

## 4. 迭代设计

四个迭代串行推进，每个迭代单独可合并（P0 门禁绿）；前置依赖未满足不得开工。

| 迭代 | 范围 | 前置依赖 | 产出物 |
|---|---|---|---|
| 1 费率表与成本模型 | `trade_cost_model` 纯函数（申购费计入买入日、赎回费按 FIFO 份额持有期对档）+ fixture 单测（手算对照） | 先决门槛 2（口径文档化） | 成本模型 + `redemption_fee_schedule` 契约 |
| 2 费率数据接入 | 扩展天天基金申购状态链路取申赎费率（走 `fetcher/chain.py`，三级降级；配置表 `data/config/` 键兜底），TTL 与既有缓存体系一致 | 迭代 1（契约定型）；先决门槛 1（抽样取得率 ≥80%） | 费率链路 + 缓存 + 配置兜底 |
| 3 基准映射与对比面板 | `benchmark_index_resolver`（宽基默认规则 + 配置覆盖）+ 指数行情经既有行情链路；`whatif_cost_panel` 在 HTML/Excel 的 what-if 章追加「成本后对比 + 基准三线」（无基准数据则只出成本后对比） | 迭代 2（费率就绪） | 基准映射 + 双端面板 + 降级形态 |
| 4 回归网与文档 | 零改动断言（开关关时输出逐字节不变）、变更场景断言（成本翻转结论案例）、五份文档同步 + P0 门禁 | 迭代 1~3 全绿 | 回归用例 + 文档同步 + 门槛判定记录 |

## 5. 红线与约束

- **不重叠**：只扩展 `whatif_backtest.py` 消费侧，不改其纯计算契约；限购受限判定
  （plan-74 的 `restricted_index`/`evaluate_purchase_feasibility`）只读复用。
- **默认零影响**：开关 `whatif_trade_cost` 关时，what-if 章输出与现状逐字节一致
  （回归用例锁定）。
- **降级**：费率取数失败 → 该品种按「费率未知」标注（不出成本后数字，只出成本前），
  不阻塞主回测。
- **交易日纪律**：持有期一律以交易日计（禁按自然日差判定）。

## 6. 验收标准（按迭代量化）

每个迭代全项满足才算通过；未过不得进入下一迭代。

| 迭代 | 量化验收标准 |
|---|---|
| 1 成本模型 | FIFO 档位手算一致（容差 0，≥8 例：持有期临界两侧/恰好整档/零费率/超长持有）；申购费计入买入日断言；新增单测 ≥10 项全绿 |
| 2 费率接入 | 先决门槛 1 判定：抽 20 只费率取得率 ≥80%；费率未知品种「不出成本后数字」标注率 100%；缓存语义版本不符按未命中丢弃用例全绿 |
| 3 基准映射与面板 | 宽基映射断言 ≥6 条（含配置覆盖优先）；无基准降级只出成本后对比；双端渲染一致断言全绿 |
| 4 回归网与文档 | 开关关态输出哈希与基线逐字节一致（零改动断言）；成本翻转案例入回归网 ≥1 例；先决门槛 2/3 判定记录（口径文档化 + 翻转人工复核）；P0 `test-runner.py --mode dev-verify` 0 失败；`check-doc-drift --ci` 0 finding |

## 7. 架构定位与依赖方向

| 构件 | 落点层 | 依赖方向与约束 |
|---|---|---|
| `trade_cost_model` | analysis 纯计算 | 只扩展 `whatif_backtest.py` 的消费侧，不改其纯计算契约；成本分层语义参照 gs-quant `TransactionModel`（只借语义） |
| `redemption_fee_schedule` | 契约 + 费率取数 | 取数经 `fetcher/chain.py` 扩展既有天天基金链路（多源降级/HTTP 工厂，三级降级 + 熔断）；缓存经 `cache/` TTL（缓存统一管理），载荷带语义版本防旧条目误读 |
| 费率兜底表 | `data/config/` 配置键 | 经 `get_config()` 绝对路径化（配置路径绝对化）；不新建第二套配置入口 |
| `benchmark_index_resolver` | analysis 纯映射 | 宽基/代码判定复用 `core/code_utils.py`（代码类型判定），禁自建前缀表；指数行情经既有行情链路（Provider 多源链路必经） |
| `whatif_cost_panel` | report 双端（what-if 章内条件块） | 序号/显示名经注册表（报告序号注册表）；pipeline_data 键先入附录 H（pipeline_data 契约）；若最终登记为实验组功能则经 `_experimental_seams` 挂载点（实验挂载点集中） |

## 9. 共享能力复用清单（防双实现）

| 能力 | 既有实现（符号） | 本设计复用方式 | 若重复实现的技术债 |
|---|---|---|---|
| 窗口回测骨架 | `analysis/whatif_backtest.py` | 成本模型作消费侧插入，不改其纯计算契约 | 改引擎内核 → 影响既有 what-if 回归面 |
| 申赎费率源 | `fetcher/fund_purchase.py`（天天基金申购状态链路） | 扩展该链路取费率，同一熔断/降级治理 | 另开费率取数 → 第二套限速/熔断口径 |
| 限购受限判定 | plan-74 `evaluate_purchase_feasibility` / `restricted_index` | 只读复用，不复制判定矩阵 | 复制判定 → 两处阈值漂移 |
| 指数行情入口 | `fetcher/index.py`（双链路 fallback 例外入口） | 基准三线的指数行情经既有入口 | 自建指数取数 → 旁路双链路 |
| 代码/宽基判定 | `core/code_utils.py` | 宽基映射复用前缀/类型判定 | 自建前缀表（违反代码类型判定约束） |
| 费率缓存 | `cache/` TTL 接口 + 语义版本载荷 | 费率按基金粒度缓存，语义变更按未命中丢弃 | 直写缓存文件 → TTL 失效/旧费率误读 |
| FIFO 逐笔持有期 | `core/trading_calendar.py` 交易日计数 | 档位判定以交易日持有期为键 | 自然日差 → 长假前后档位错判（违反交易日计数约束） |

## 10. 技术债防线

1. **费率载荷语义版本**：费率缓存载荷带版本字段，费率口径/来源变更时读侧按未命中丢弃——防 7 天旧条目让修复失效（QDII 联接前车之鉴）。
2. **FIFO 口径单源**：逐笔持有期与档位判定只有一份实现，what-if 回测与面板只读同一函数；禁两处各写一遍档位表。
3. **基准映射单源**：宽基映射规则一处定义（配置覆盖优先），Excel/HTML/LLM 引用同源；不双写 config。
4. **降级不留伪精度**：费率未知品种显式标注，不出「成本后」数字；不以 0 费率冒充已计成本。
5. **翻转案例入回归网**：成本计入后的方向性翻转案例固化为回归用例，防后续改动静默回退到「无感装饰」状态。
6. **单文件红线与语义命名**：新增模块受 800 行红线守护；语义名入命名表，任务代号不进实现层（双脚本强制）。
7. **测试卫生与计数同步**：过 `check-test-redundancy` 五类；edge 入 `*_edge.py`；删并后同步两份计数文档。
8. **文档同步即门禁**：每迭代同回合同步五份文档，`check-doc-drift --ci` 绿；迭代可独立合并（P0 全绿）。

## 11. 测试策略（按迭代）

通用纪律（每迭代生效）：用例标注 pytest marker（测试 marker）、edge 入 `*_edge.py`（edge 文件隔离）、配置与持仓路径隔离（测试数据隔离）、费率/指数行情 mock 强制（或 cassette 回放，经工厂注入）、跨模块 patch 打在调用点所在模块、`check-test-redundancy --ci` 五类零违规。

| 迭代 | 测试类型 | 关键用例 | 隔离与 mock |
|---|---|---|---|
| 1 成本模型 | 单测 + edge | FIFO 逐笔档位手算（含持有期恰好临界、阶梯减免、零费率）；申购费计入买入日 | 纯函数 fixture（零 I/O）；边界 edge 入 `*_edge.py` |
| 2 费率接入 | 单测 + 降级 | 取得率统计、费率未知标注、三级降级链路、缓存载荷语义版本丢弃旧条目 | HTTP 全 mock/cassette 回放；配置兜底用临时 config（测试数据隔离） |
| 3 基准与面板 | 场景测试 | 宽基映射（含配置覆盖）、无基准降级只出成本后对比、双端渲染一致 | 指数行情 mock；输出目录临时化 |
| 4 回归网与文档 | 场景 + 门禁 | 开关关态逐字节不变（零改动断言）；成本翻转案例固化回归；`check-doc-drift` 绿 | 翻转案例用固定 fixture，不依赖实时数据 |

## 12. 外部数据依赖与稳定性考察

**结论先行**：两项外部依赖——**申赎费率**（天天基金页面链路，本特性最大稳定性风险：页面结构可随改版变化）与**基准指数行情**（既有双链路）；无新增凭据。

| 数据项 | 来源（链路） | 稳定性风险 | 考察/监测指标 | 降级与防护 |
|---|---|---|---|---|
| 申赎费率 | 扩展天天基金申购状态链路（`fetch_with_fallback`） | **页面改版导致解析失败**、字段缺失、限频 | 先决门槛 1：抽 20 只取得率 ≥80%（迭代 2 入口复测）；运行期费率解析失败计数（chain 失败诊断既有） | 解析失败 → 费率未知标注（不出成本后数字）；配置表单源兜底；cassette 回放防解析器漂移（解析器改后离线回放即知） |
| 费率载荷缓存 | `cache/` TTL（既有） | 口径/来源变更后旧条目误读 | 载荷语义版本字段 | 版本不符按未命中丢弃重取 |
| 基准指数行情 | `fetcher/index.py` 双链路例外入口 | 指数源变更 | 取数失败率（既有诊断） | 缺则降级只出成本后对比 |
| 交易日历（持有期档位） | `core/trading_calendar.py`（本地） | — | — | 档位判定一律交易日计 |

**判定动作**：取得率 <80% → 按门槛降级为「用户配置表单源」并显式标注数据来源；运行期解析失败率突增（较基线翻倍）→ 视为源改版，先修解析器（回放用例过）再恢复取数，期间走兜底配置。

## 13. 风险、回滚与文档同步义务

| 风险 | 影响 | 缓解 | 触发后的动作 |
|---|---|---|---|
| 天天基金页面改版致解析失败 | 费率不可得 | cassette 回放防漂移 + 失败计数监测 | 修解析器（回放用例过）前走配置兑底；取得率 <80% 降级单源 |
| FIFO 口径误判（持有期档位） | 成本算错、结论误导 | 交易日计（交易日计数）+ 手算 ≥8 例含临界 | 口径以文档为唯一依据，争议回文档不改代码 |
| 成本翻转案例被误读 | 用户据错误结论行动 | 翻转人工复核（先决门槛 3） | 未复核的翻转不入回归网、不进报告示例 |
| 基准指数数据不可得 | 对比面板缺失 | 降级只出成本后对比 | 不阻塞主特性 |

**回滚策略**：① 迭代级——每迭代独立提交、独立验收，未过不合入，出问题单次 revert。② 功能级——`whatif_trade_cost` 开关关闭即回现状（关态逐字节不变已由验收锁定，零改动断言长期驻留回归网）。③ 数据级——费率缓存语义版本保证回滚后旧条目被正确丢弃，不误读。

**文档同步义务（每迭代同回同）**：`requirements.md`、`technical.md`（语义命名表 + 约束落点 + FIFO 口径文档化）、`testplan.md`（载体）、`changelog.md`、`folders.md`/`test-coverage.md`（计数）；完成判据 = `check-doc-drift --ci` 0 finding。
